## 题目原文

> 某面向用户的反馈/搜索站点在前端入口部署了 Web 防护设备过滤恶意输入，后端会回显用户提交的内容。已获授权进行评估，设法绕过边界过滤、窃取站点用户会话并取得受保护 flag。

## 题解

### 入口与指纹

搜索页标题 `Search — Internal Knowledge Base`，`nginx/1.30.1`，PHP。查询参数是 `q`。脚注写着 `Protected by ModSecurity WAF`。页面有一块 `debug`，把搜索词再渲染一次。

### 关键观察

flag 不在搜索结果里，在响应头的会话 cookie 里。第一次访问首页就会下发：

```http
Set-Cookie: session_token=flag%7B...%7D; Max-Age=3600; path=/
```

没有 `HttpOnly`，也没有 `Secure`。URL 解码之后就是 flag。

搜索框确实会把 `q` 原样写进 `<div class="debug">`，`<b>hi</b>` 会变成真正的 `<b>` 标签，输入框的 `value` 和 “No results” 那一行则是转义过的。但 `<script>`、`onerror`、`onload` 都会被 ModSecurity 直接 403。偷 cookie 不必走这段反射：cookie 已经在我们自己的响应头里。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -D - -o /dev/null "http://$T/" | sed -n 's/^Set-Cookie: session_token=//p'
```

把 `flag%7B` / `%7D` 解回花括号。本次平台接受的值是 `flag{43298259-81b2-4a40-b2ae-b94ab7e56e54}`。

### flag 位置

入口响应的 `session_token` cookie。它就是受保护 flag 的 URL 编码，不是另一段还要再去换的会话编号。
