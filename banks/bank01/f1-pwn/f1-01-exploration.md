# f1-01 · 探索记录

对应题解：[`f1-01.md`](./f1-01.md)

## 目标与起点

横幅写的是 Token Store v1.0。先把 `HELP` 里的命令各走一遍，确认短令牌能存、能查、能列，再拉长 `STORE` 的参数，看列表输出从哪一个长度开始带上槽外面的字节。

## 第一阶段：64 字节让 LIST 读过槽尾

`STORE short` 回 `[OK] Token #0 stored`。`LIST` 打出 `[0] short` 和 `[LAST] short`。`CHECK short` 回 `Token found at index 0`。短令牌的行为是闭合的。

接着用同一条连接之外的新连接，分别存 32 字节和 64 字节的 `A`。32 字节的 `LIST` 只含这些 `A`。64 字节的 `[LAST]` 行在 `A` 后面直接接上 `flag{...}`。

## 走不通 / 走过的弯路（留档）

| 方向 | 结果 | 判据 |
| --- | --- | --- |
| `STORE short` 后 `LIST` / `COUNT` / `CHECK` | 正常存储 | 列表只有 `short`，计数是 1，`CHECK` 命中下标 0 |
| `STORE` 32 个 `A` | 没有带出槽外数据 | `[LAST]` 只有 32 个 `A`，响应里没有 `flag{` |
| `STORE` 64 个 `A` | 读出相邻 flag | `[LAST]` 是 64 个 `A` 紧贴 `flag{...}`，中间没有 0 |

更长的长度没有继续试。64 字节已经让打印越过槽尾，flag 也已经被平台接受。

## 这次真正的收获

槽的可见长度是 63 字节加一个结尾 0。写满 64 字节后这个 0 不存在，`LIST` 会一直读到后面的 flag。不需要改写返回地址。
