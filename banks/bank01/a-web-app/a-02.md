## 题目原文

> 公司内部部署了一套文档协作平台，员工可以上传、分享和导入文档。系统支持自定义用户偏好设置，管理员可以查看系统文档。最近安全团队发现系统可能存在一些安全隐患，但尚未定位到具体问题。Flag 存储在系统的机密文档中。

## 题解

### 入口与指纹

`Werkzeug/3.1.6` + `Python/3.9.25`。登录页直接给出三组测试账号：

```
管理员：rootadmin / docpass
普通用户：editor1 / edit123!
普通用户：editor2 / edit456!
```

登录后导航有：`/dashboard`、`/upload`、`/import`、`/preferences`；管理员额外有 `/admin`。

### 关键观察

**1. 用管理员账号登录后，`/admin` 里有一个 `/admin/flag` 链接。**

管理面板显示三份「系统文档」和一条「🔒 机密文档」：

```
🔒 机密文档
此文档包含系统机密信息，需要通过特殊方式访问
💡 提示：系统导入功能支持 XML 格式...
🏁 获取 Flag
```

`🏁 获取 Flag` 指向 `/admin/flag`。

**2. `/admin/flag` 只要管理员会话就返回 flag。**

```bash
curl -s -b cj "http://$T/admin/flag"
# {"flag":"flag{622ea75a-be2a-4c1a-a06a-1c9ca48a283c}",
#  "message":"Congratulations! You found the flag!"}
```

没有二次校验、没有文档 id 参数、没有「特殊方式」的验证。

### 利用链

**Step 1：用登录页给的管理员账号登录。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -X POST -d 'username=rootadmin&password=docpass' "http://$T/login"
# 302 → /dashboard
```

**Step 2：访问 `/admin`，找到「获取 Flag」。**

```bash
curl -s -b cj "http://$T/admin" | grep -oE 'href="/admin/flag"'
```

**Step 3：取 flag。**

```bash
curl -s -b cj "http://$T/admin/flag"
# {"flag":"flag{622ea75a-...}","message":"Congratulations! You found the flag!"}
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/admin/flag` 接口，管理员会话直接返回 |

### 复盘

- **登录页给的账号先用，包括管理员。** 本题的 `rootadmin/docpass` 直接把整条链跳过了。
- **`/admin` 之类的高权限路由要认真翻。** 「获取 Flag」按钮就是一个现成接口，不需要去猜。
- **「需要通过特殊方式访问」是叙事，不是约束。** 提示里提到的 XML 导入确实有问题（`XMLParser(resolve_entities=...)` 在 Python 3.9 是非法参数，导入直接报错），但真正的 flag 在 `/admin/flag`，比绕路便宜得多。
- **偏好设置是存储型字段（原样渲染），本题不是主路。** `theme={{7*7}}` 会原样显示，不构成 SSTI。
