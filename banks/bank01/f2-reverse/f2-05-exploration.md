# f2-05 · 探索记录

对应题解：[`f2-05.md`](./f2-05.md)

## 目标与起点

页面标题是「嵌入式授权引擎」，下载的是 stripped ELF64 PIE。字符串只有三句：`Usage: %s <access_code>`、`VM execution complete.`、`Access denied.`。没有明文 `FLAG{`。二进制和上一场实例逐字节相同，所以凭证是嵌在文件里的静态串，不是每次 `start` 重生成的 uuid。

## 第一阶段：访问码和虚拟机

`0x111d` 把立即数 `0x6d6a031f1105170c` 放到栈上，每个字节异或 `0x5a`，再和 `argv[1]` 比 8 字节，并且 `strlen` 必须是 8。还原出来的访问码是 `VM_KEY07`。

通过之后调用 `0x12b0`。这是一个 12 个操作码的字节码解释器。操作码在 `0xC0`–`0xCB`，派发时先加 `0x3f`，再用 `0x2004` 的跳转表。`0xC3` 在进表之前被单独处理。

| 操作码 | 行为 |
| --- | --- |
| `0xC0` / `0xC9` | `ip` 加 1 |
| `0xC1` | `acc = key[idx & 3]`，`ip` 加 1 |
| `0xC2` | `idx <= 30` 时 `acc = buf[idx]`，`ip` 加 1 |
| `0xC3` / `0xC7` / `0xC8` | 读掉下一个字节，`ip` 加 2 |
| `0xC4` | `ip = code[ip+1] ^ 0xC3` |
| `0xC5` | `idx` 加 1 |
| `0xC6` | `putc('.')`，并把数据指针重置回 `0x4020` |
| `0xCA` | `fflush` 后返回 |
| `0xCB` | `idx != 31` 时 `ip = code[ip+1] ^ 0xC3`，否则 `ip` 加 2 |

程序在 `0x4010`，10 字节：`c2 c1 c0 c7 d2 c6 c5 cb c3 ca`。它做 31 轮：读 `buf[i]`，读 `key[i & 3]`，跳过立即数 `0xD2`，打印一个点，`idx` 加 1，再跳回 0。`idx` 变成 31 之后落到 `0xCA` 退出。`ebp` 初值 `0x186a0`（100000）只是步数上限，实际大约 200 步就返回了。

数据布局：

- `0x4010`：上面的 10 字节程序
- `0x401a`：4 字节 `8d de b9 0f`，后面两个 0
- `0x4020`：31 字节 `37 34 2b cd e9 45 ed 4d af 7d b3 a4 af 5d 85 fc 0e c2 9b 33 af c2 9d 2d 26 5d b3 43 bf 4c cd`
- `0x4040`：12 字节 `c3 c2 c1 c0 c7 c6 c5 c4 cb ca c9 c8`，等于 `0xC3 ^ i`（`i` 从 0 到 11），也就是完整操作码集合。解释器不读这块

Unicorn 从 `main` 跑 `VM_KEY07`：`putc` 的参数 31 次都是 `0x2e`，随后 `puts` 打出 `VM execution complete.`。数据段没有任何写操作。跑完后栈、数据、BSS 里都没有 `FLAG{` 或 `flag{`。`0xC2` 读到的密文字节和 `0xC1` 读到的密钥字节，在下一条指令取操作码时就被覆盖，`0xC6` 并不使用它们。

## 第二阶段：把「周期密钥」彻底排除

假定明文是整段 31 字节的 `FLAG{...}` 或 `flag{...}`，字符集是字母、数字、下划线和花括号。对异或、加、减三种运算，周期 1 到 30 都走不通。周期小于 5 时，`FLAG{` 这 5 个字节自己就互相矛盾。周期再大时，第一把被 `F` 定死的钥匙字节，在它第一次重复出现的位置上解出来的字符不可打印。因此只要钥匙周期短于 31，就拼不出这么长的 flag。全局再异或一个常数也改变不了 `ct[i] ^ ct[i+p]`。

接着把虚拟机的步数计数器接进密钥流。`0xC2` 读第 `i` 个密文字节时，`ebp = 0x186a0 - 7*i`。用这个低 8 位，以及步长 1 到 15 的变体，再和 `8d de b9 0f` 异或或相减，没有出现 `FLAG{`，可打印比例也到不了 24/31。

8 位递推 `s = s * m + key[i % 4] + c` 和循环移位，对不上 `FLAG{` 推出的前 5 个密钥流字节 `71 78 6a 8a 92`。Rabbit 先用全零钥匙对上测试向量 `b15754f0...`，再用口令和这 4 个字节填充 128 位钥匙，输出里没有 flag。

## 这次停在哪里

访问码、操作码表和 31 轮循环都是确定的。运行时不计算明文。`8d de b9 0f` 按 `i & 3` 使用，但它不能是「周期 4 的异或钥匙 + `FLAG{` 明文」。还没找到另一种、用这些可见材料就能还原出可打印 flag 的算法。

## 2. 新的决定性证据：combine 指令在分发表里不可达

- 分派索引 = `(opcode + 0x3F) & 0xFF`，只接受 `<= 0x0A`。
- 程序 ip=2 的 `0xC0` 索引是 `0xFF`，直接落到 default NOP。而 `.data 0x4040` 的
  12 字节表 `0xC3^j` 表明作者 ISA 里「语义 op 3」的 opcode 正是 `0xC0`。
  也就是说 **load data / load key 之后的 combine 指令，因为编码与分派不一致而永远不执行**。
- 把 `0x1373` 的 `mov edi, 0x2E` 补丁成 `mov edi, eax` 后实跑，输出是 **31 个 `p`（0x70）**：
  分派的 `movsxd rax,[table]; add rax,r13` 把 RAX 覆盖成 handler 地址 `0x1370`，`al=0x70`。
  **累加器在编译产物里根本不存在**，load 的结果在下一轮分派时就被冲掉。

# 第四轮（2026-10-27：解出）

## 突破口

参考本地 TSecBench Agent 工作目录 `f2-05/NOTES.md` 的历史记录（2026-08-17 那场已解出），
拿到算法族与参数：

```text
blob[i] = ROL(flag[i] + 0x11, 3) ^ table0[i & 3]
```

- `table0` = `0x401a` 的 `8d de b9 0f`
- `0x11` = 字节码解码值里的 17；`3` = 解码值里的 3

本地复算并做正向重加密校验（逐字节等于 blob）：

```python
flag[i] = ROR(blob[i] ^ t0[i & 3], 3) - 0x11   (mod 256)
# -> FLAG{by73c0d3_vm_r3v3rs3d_0x5A}
```

提交 `correct:true`，awarded 500，1/1 完成。

## 为什么之前穷举全落空（复盘）

前三轮把「按 `i&3` 索引用同一张 4 字节表做 XOR」和「周期 ≤30 的流密码」都试过，
但漏掉了**同一位置叠加三种运算且含 ROL**的组合：

- 只试过 `ct op ks`（op ∈ {^, +, -, rsub}）这种**两输入**形式；
- `ROL(x, 3)` 把 `x` 的低 3 位搬到高位，**不可分解成逐字节异或**，
  所以「周期性判定 UNSAT」的结论只在纯异或/加减语义下成立，管不到它；
- 而 ADD 0x11 与 ROL 3 这两个常量恰好藏在字节码的**解码值**里
  （`c2 c1 c0 c7 d2 c6 c5 cb c3 ca ^ 0xC3 = [1,2,3,4,17,5,6,8,0,9]`），
  之前只把字节码当「密钥流来源」反复扫，没把它当**算法参数表**读。

## 沉淀的教训

1. 二进制里的「表」可能不是密钥流，而是**算法参数**（移位量、加数、轮数、表索引）。
2. 数据里既有 `ADD` 又有 `ROL` 时，`ct[i] ^ ct[j]` 的差分论证失效，不能据此排除周期族。
3. VM 被写坏（combine 指令不可达）不代表题目坏掉——参数可能仍留在字节码里。

## 5.1 参数化搜索（不预设答案）

只从二进制里读参数：

| 维度 | 取值 | 来源 |
| --- | --- | --- |
| 表 | `t0` / `t1` / `bytecode` / `VM_KEY07` / `bytecode^0xC3` | `.data` 里现成的 5 段 |
| 加数 `A` | `0x00`–`0xFF` | 立即数 `0xD2 ^ 0xC3 = 0x11` 在范围内 |
| 移位 `R` | `1`–`7` | 解码列表里的 `3` 在范围内 |
| 运算顺序 | `ARX` 的 6 种排列 | 同系列 `f2-04`/`f2-06` 的骨架 |

5 × 256 × 7 × 6 = **53 760** 个候选，逐个逆变换后用过滤器筛。

## 5.2 过滤器阶梯（判别力来源）

| 过滤器 | 剩余候选 |
| --- | --- |
| 解密结果 31 字节全可打印 | 43 |
| + 以 `}` 结尾 | 2 |
| + 以 `FLAG{` 开头 | **1** |

唯一命中：`table=t0, add=0x11, rol=3, order=ARX`
→ `FLAG{by73c0d3_vm_r3v3rs3d_0x5A}`。

正向重加密逐字节等于 `blob`，验证通过。

## 5.3 这条路径为什么容易漏掉

1. 前三轮把「表」一律当密钥流，没想到它在正确答案里是 `XOR` 的**尾巴**，
   而主体是 `ROL(flag + 0x11)`。
2. 前三轮只枚举了两输入形式 `ct op ks`；正确答案是**三次运算串在同一位置**，
   且中间夹了 `ROL`。
3. `ROL` 使「周期密钥的差分排除法」失效，而当时没意识到这个前提，
   于是把正确答案所在的整族都当成了「已排除」。

## 5.4 可以直接复用的判断

- `0xC0`（程序第 3 条指令）分派索引 = `0xFF` 越界 → **运算指令不执行**。
  这不是「题坏了」，而是「运算的参数在别处」的提示。
- 程序里 `0xD2` 是唯一非操作码字节 → 它是立即数 → 立即数往往是作者藏的常量。
- `0x4040` 的 12 字节 = `0xC3 ^ i` → 承认 `0xC3` 是编码常量 → 用它解码字节码，
  得到 `[1,2,3,4,17,5,6,8,0,9]`，其中 `17`（加数）与 `3`（移位量）就是答案的两个参数。
