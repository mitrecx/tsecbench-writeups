# f2-01 · 探索记录

对应题解：[`f2-01.md`](./f2-01.md)

## 目标与起点

下载到的 ELF 没有把 flag 放在字符串里。`main` 在校验返回 1 时只打印 `License accepted.`。凭证是校验函数自己算出来的 38 字节，所以先把 `0x1200` 用 Unicorn 跑起来，看栈上有什么。

## 第一阶段：很多密钥都“通过”，但凭证不是 flag

`######`、`AAAAAAAAAA`、`000020202` 的返回值都是 1。`license`、种子串 `st4t3_tr4c3_engine_seed_v1`、全 0 的长串返回 0。

`000020202` 的缓冲后半段是可读的 `st4t3_tr4c3_1s_th3_k3y5tr34m}`，前面仍是二进制。把 `FLAG{st4t3_tr4c3_1s_th3_k3y5tr34m}`、小写 `flag{...}` 和没有前缀的那半句交给平台，都是 `correct: false`。

## 走不通 / 走过的弯路（留档）

| 方向 | 结果 | 判据 |
| --- | --- | --- |
| 种子串当许可证 | 校验失败 | 返回值 0，没有写出缓冲 |
| `######` | 通过但不是 flag | 返回值 1，38 字节里没有 `FLAG{` 或 `flag{` |
| 直接提交可读的后半句 | 平台拒绝 | `FLAG{st4t3_tr4c3_1s_th3_k3y5tr34m}`、`flag{...}`、不带花括号的尾巴都是 `correct: false` |
| 按 `FLAG{` 逐字节反推，并在中途遇到 `}` 就停 | 明文中途坏掉 | 得到 `FLAG{f5m_U{4tdm}>` 后面又是二进制 |
| 反推时要求整段都是 `FLAG{` + 字母数字下划线 + `}`，短输入用种子补齐 | 得到完整 flag | 许可证 `!# !##!"!`，缓冲是 `FLAG{f5m_st4t3_tr4c3_1s_th3_k3y5tr34m}`，Unicorn 复算一致，平台接受 |

## 这次真正的收获

返回值 1 只说明状态机走到了接受态，不说明凭证就是要交的 flag。每个位置只有 4 种输出，所以可以从 `FLAG{` 把许可证反推出来。种子只负责把不足 38 字节的输入补满。
