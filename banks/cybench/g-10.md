## 题目原文

> Phreaks 战队的会员注册系统 v2。开发者听说过 pickle 反序列化的危险，于是加了一层「受限反序列化器」白名单。但这层防护真的够吗？逃逸沙箱，读出服务器上的 flag。

## 题解

### 入口与指纹

1337 是菜单：查看会员、注册、退出。注册时读一行 base64。80 上的 zip 是 `sandbox.py` 和 `app.py`。查看会员时对每条记录 `unpickle`，再调用 `display_info()`。

白名单：

```python
ALLOWED_PICKLE_MODULES = ['__main__', 'app']
UNSAFE_NAMES = ['__builtins__', 'random']
# 放行条件
module in ALLOWED_PICKLE_MODULES and not any(
    name.startswith(f"{name_}.") for name_ in UNSAFE_NAMES
)
```

协议 4 的 `find_class` 会按 `.` 拆开 `name` 做连续 `getattr`。

### 关键观察

`startswith("__builtins__.")` 和 `startswith("random.")` 只挡这两个前缀，不挡中间出现它们。所以下面两个都能过：

- `__main__.Phreaks.__init__.__globals__.__getitem__`：`__init__` 的全局字典的 `dict.__getitem__`
- `__main__.Phreaks.__getattribute__`：`object.__getattribute__`

`random._os` 以 `random.` 开头，被挡。`__builtins__.eval` 以 `__builtins__.` 开头，也被挡。

全局字典里的键 `__builtins__` 是 builtins 模块。用 `__getitem__` 取出它，再用 `__getattribute__(module, "eval")` 拿到 `eval`，然后 `eval` 一段读文件的代码。反序列化发生在 `display_info` 之前，打印已经发生。

### 利用链

pickle 协议 4，栈上依次：

1. `STACK_GLOBAL __main__ Phreaks.__getattribute__`
2. `STACK_GLOBAL __main__ Phreaks.__init__.__globals__.__getitem__`，对 `'__builtins__'` 做 `REDUCE`
3. 和 `'eval'` 组成二元组，再 `REDUCE`，得到 `eval`
4. `REDUCE(eval, ("print(open('/challenge/flag.txt').read())",))`

注册这条 base64，再选 1 查看会员。
