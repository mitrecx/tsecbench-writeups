## 题目原文

> LockTalk 是一个加密通讯服务，敏感接口由前置代理与 JWT 鉴权双重保护。签发访客凭证的接口据说已经被网关封禁，而读取 flag 的接口只对管理员开放。想办法突破这两道防线。

## 题解

### 入口与指纹

两个地址。1337 是 uWSGI 上的 Flask，前面还有 HAProxy。80 是 nginx 目录，给出 `web_locktalk.zip`，里面是这份应用的源码。网关规则：

```text
http-request deny if { path_beg,url_dec -i /api/v1/get_ticket }
```

`/api/v1/flag` 只允许 `role == administrator`。签发接口发出的是 `role: guest` 的 PS256 JWT，密钥是进程内临时生成的 2048 位 RSA JWK。依赖钉死在 `python_jwt==3.3.3`。

### 关键观察

1. `path_beg` 不匹配多出来的斜杠。`GET //api/v1/get_ticket` 返回 200 和访客票，`GET /api/v1/get_ticket` 是 403。
2. 3.3.3 的 `verify_jwt` 先用 `split('.')` 看第一段里的 `alg`，签名校验却交给 `JWS.deserialize`，它会先尝试把整段当 JSON。可以做成恰好两个 `.` 的 JSON/compact 混合串：反序列化时验的是原始 payload 的签名，`split` 读到的 claims 却是改过的。

### 利用链

拿到访客票 `header.payload.signature` 后，把 payload 里的 `role` 改成 `administrator`，时间戳不动，拼成：

```text
{"  <header>.<forged_payload>.":"","protected":"<header>", "payload":"<original_payload>","signature":"<signature>"}
```

`Authorization` 带上这个字符串请求 `GET /api/v1/flag`。

### flag 位置

响应 `message`。本次是 `flag{f7de4312-0bd8-4fca-ae6d-8f1088fb89cb}`。zip 里的 `FLAG = "HTB{f4k3_fl4g_f0r_t35t1ng}"` 只是占位，实例上的值每次 `start` 都会变。
