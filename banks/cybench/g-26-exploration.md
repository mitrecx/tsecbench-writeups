# g-26 · 探索记录

## 目标与起点

9999 端口。每条连接重新生成 RSA 模数和一条走法的密文。横幅给出 `n`、`e = 65537` 和密文。菜单是 `1. Decrypt`（交十六进制密文，只回终点坐标）和 `2. Check answer`（答错就断开）。

## 已经确认的行为

必须在同一条连接里用它自己的 `n` 做 `m^e mod n`。用上一条连接的模数加密，除了 `0` 和 `1`（任何指数都还是自己）以外，服务解出来的都不是选定明文，终点会乱跳。

选定明文 `m` 的终点，等于把 `bin(m)` 补成偶数位之后，每两位一步：

| 两位 | 位移 |
| --- | --- |
| `00` | 左 `(-1, 0)` |
| `01` | 右 `(1, 0)` |
| `10` | 上 `(0, 1)` |
| `11` | 下 `(0, -1)` |

`m = 0` 被当成一步向左。向右、上、下各走几百步，坐标都是步数本身，没有墙，顺序也不影响终点。所以解密接口泄漏的是四种步子的净值，不是唯一的走法序列。

`m % 4 == 0` 当且仅当终点等于 `(m/4)` 的终点再向左一步。这条对 1024 位随机数也成立，因此「整除 4」在大数上仍然可靠。把它用在 `2m mod n` 上判断奇偶则不行：`n` 是奇数，`m >= n/2` 时 `2m - n` 一定是奇数，上半区的偶数会被看成奇数。用这个不完整的奇偶预言机做二分，1023 轮之后得到一个 130 位的数，它的 `e` 次方对不上密文。

最短走法（净值相同的 `R/U/D/L` 字符串）提交一次就被判定 `Wrong solution`，连接关掉。检查的是原来的那条走法，不是任意一条走到同一点的路。
