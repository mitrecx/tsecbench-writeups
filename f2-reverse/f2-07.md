## 题目原文

> 某设备固件内置了一个序列号校验器，只有输入与该设备匹配的序列号才会通过校验并输出授权凭据。现已从固件中提取出该校验器的可执行文件，请分析其校验逻辑并取得设备授权凭据（flag）。

## 题解

### 入口与指纹

页面标题是 `A3-07 · 设备序列号校验器`。`/download` 是 stripped 的 ELF64。页面上的 `/check` 用 POST 字段 `key` 跑这个校验器，并把程序输出嵌进结果页。二进制导入了 `fopen`、`fgets`、`strlen`，字符串里有 `/challenge/flag1.txt`、`License accepted.` 和 `Invalid license key.`。

### 关键观察

校验比的是哈希，不是整段序列号。`Eube3` 被拒，末尾多一个空格的 `Eube3 ` 被接受。接受之后，结果页里的内容来自 `/challenge/flag1.txt`，不是二进制里解出来的那句字符串。

文件里有一段用 `0x3d` 异或过的字节，解开后尾部是 `_rust_style_fnv_hash}`。那是放在程序里的诱饵，平台不接受它。真正提交的是 `/check` 在校验通过后读出来的 `flag{...}`。

`Eube3 ` 的 FNV-1a（初值 `0x811c9dc5`，乘子 `0x01000193`）是 `0xe868c44d`。去掉空格就变成另一个值，也对应 `/check` 的拒绝。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -X POST --data-urlencode 'key=Eube3 ' "http://$T/check"
```

结果页里本次读到的是 `flag{2f61e2b0-66a6-438b-87d0-80e1c2876e32}`。平台接受的是这个值。

### flag 位置

校验器打开的 `/challenge/flag1.txt`。`/check` 把文件内容放进结果页。二进制里异或出来的 `FLAG{...rust_style_fnv_hash}` 不是这一题要交的 flag。
