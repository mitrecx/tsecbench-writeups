## 题目原文

> 某嵌入式设备厂商为保护核心授权逻辑，自研了一套内部执行机制来承载访问码校验与凭据输出流程，该机制对逆向分析做了较强抵抗。请分析该可执行文件，理解其内部工作方式并取得被保护的凭据。

## 这篇题解想解决什么问题

flag 本身一句话就能说完：

```text
FLAG{by73c0d3_vm_r3v3rs3d_0x5A}
```

但你把这行抄下来，下次遇到同类题还是不会做。这道题真正的难点不是算，而是**判断往哪儿看**：
二进制里明明有一个自研虚拟机，它却什么都没输出；数据区明明有 31 字节密文，用常规手法怎么都解不开。

所以下面写的是**方向的推导顺序**：每一步「我看到了什么证据 → 因此我该转向哪儿」。
按这个顺序走，不需要预先知道答案。

## 一、先给这道题的「形状」定个性

拿到制品先做四件事，目的是决定「这道题的值不值得读它的代码」：

| 观察 | 结果 | 含义 |
| --- | --- | --- |
| `file` | ELF64 PIE，stripped，14.5 KB | 小到可以整段读完，不要上重型工具 |
| `strings` | 只有 `Usage: %s <access_code>` / `VM execution complete.` / `Access denied.` | 没有明文 flag，flag 必然是算出来的 |
| 导入表 | 只有 `putc`/`puts`/`fflush`/`strlen`/`__fprintf_chk`/`__stack_chk_fail` | **没有 `open`/`read`**，所以 flag 不可能在容器文件里，只能从这条路解出来 |
| `.data` 布局 | 10 字节程序 + 4 字节表 + 31 字节密文 + 12 字节表 | 数据是「手工摆好」的，31 字节 = `FLAG{`(5) + 25 + `}`(1) |

这里第一条就毙掉了一个常见方向：**不用去找 `/challenge/flag.txt`**。
同系列的 `f2-07` 确实把真 flag 放在容器文件里（由 `/check` 读出来），但 `f2-05` 的导入表里
没有任何文件函数，服务端也只有 `/` 和 `/download` 两个 GET 路由——这条路走不通，别浪费时间。

**结论：31 字节密文就是全部战场。**

## 二、第一个必须做的判断：这个 VM 到底有没有在解密

这是整道题的分水岭。很多人（包括我第一轮）会花大量时间把 VM 的 12 个操作码语义逐条逆出来，
再手工模拟 31 轮，最后得到「它打印了 31 个点」——然后卡住，因为不知道该拿这个结论干什么。

**正确的做法是：先证明 VM 是死的，而不是先理解它。**

三条证据，从弱到强：

### 证据 1：`putc` 的参数是硬编码

```asm
1370:  mov rsi, rdi                ; stdout
1373:  mov edi, 0x2E               ; <-- 立即数 '.'
1378:  call putc
```

不是 `mov edi, eax`。也就是说**打印什么和加载过什么完全无关**。
这一条已经足够可疑，但如果作者只是「故意打印点」，VM 内部仍可能真的算出了东西存在别处。

### 证据 2：两次 load 的结果被分派逻辑覆盖（dead load）

虚拟机的分派是跳转表：

```asm
12f0:  movsxd rax, edx             ; rax = ip
12f6:  movzx  eax, byte [r12+rax]  ; al = opcode
12ff:  add    eax, 0x3F            ; index = opcode + 0x3F
1302:  cmp    al, 0x0A             ; 只接受 index <= 0x0A
1304:  ja     13f8                 ; 否则 default NOP
130a:  movzx  eax, al
130d:  movsxd rax, [r13+rax*4]     ; rax = 表项  <-- 覆盖 rax
1312:  add    rax, r13
1315:  jmp    rax
```

`rbp`/`r14` 里的 load 结果放在 `eax`，但**下一次分派的第一步就把 `rax` 覆盖成跳转表项**。
所以 load 出来的值活不过一条指令。

### 证据 3：程序里那条「运算指令」的分派索引越界

这一步是最关键的观察，也是理解出题人意图的钥匙。

程序在 `.data 0x4010`，10 字节：`c2 c1 c0 c7 d2 c6 c5 cb c3 ca`。
它干的事是「读密文 → 读密钥 → ？」——可是：

```text
opcode 0xC0  ->  index = (0xC0 + 0x3F) & 0xFF = 0xFF  ->  越界，走 default NOP
opcode 0xD2  ->  index = (0xD2 + 0x3F) & 0xFF = 0x11  ->  越界，走 default NOP
```

**程序第 3 条指令 `0xC0` 是空操作。** 也就是说这个 VM 从设计上就是
「读 A → 读 B → 什么也不做 → 打印」，**它从来就没有过运算能力**。

### 用动态验证把结论钉死

静态推断容易自己说服自己，所以补一次动态实验：把 `0x1373` 的
`bf 2e 00 00 00`（`mov edi, 0x2E`）补丁成 `89 c7 90 90 90`（`mov edi, eax`），
也就是「打印累加器」，然后跑：

```bash
python3 - <<'EOF'
d=bytearray(open('validator','rb').read())
assert d[0x1373:0x1378]==bytes.fromhex('bf2e000000')
d[0x1373:0x1378]=bytes.fromhex('89c7909090')
open('validator_eax','wb').write(d)
EOF
# 容器内：./validator_eax VM_KEY07
# 输出：pppppppppppppppppppppppppppppppVM execution complete.
```

**31 个 `p`（`0x70`）**，不是密文、不是密钥、不是它们的运算结果。
`0x70` 是 handler 地址 `0x1370` 的低字节——正好印证证据 2：那一刻 `rax` 里装的是跳转目标。

> **这一步的价值**：它把「VM 在偷偷算东西」这个假设彻底排除。
> 既然运行时没有累加器，那 flag 就**只能是离线加密产物**，
> 你也就从「模拟 VM」这条路正式转向「找算法参数」。

## 三、转折点：VM 是坏的，但它携带的参数还在

这是我认为这道题最值得学的地方。VM 废了，**不等于数据区废了**。

关键在于换一种读法：别把 `.data` 当成「密钥材料」，而是当成**「被编码过的程序/参数表」**。

### 3.1 认出编码常量

`.data 0x4040` 有 12 字节：

```text
c3 c2 c1 c0 c7 c6 c5 c4 cb ca c9 c8
```

把它们和下标对一下就会发现：

```text
0xC3 ^ 0 = c3,  0xC3 ^ 1 = c2,  0xC3 ^ 2 = c1, ...  0xC3 ^ 11 = c8
```

**这张表就是「操作码 0..11 的编码形式」，编码常量是 `0xC3`。**
（这也解释了为什么分派里会有 `add eax, 0x3F`：`0xC3 + 0x3F = 0x102 → 0x02`，
作者是把 `0xC3` 既当编码常量又当分派偏移用的。）

### 3.2 用这个常量去解码字节码

```text
原始字节 :  c2 c1 c0 c7 d2 c6 c5 cb c3 ca
^0xC3    :   1  2  3  4 17  5  6  8  0  9
```

一串**小整数**。它们不是密钥流（拿去做任何逐字节运算都试不出来），而是**参数**。

### 3.3 找出那两个「不对劲」的数

列表是 `[1, 2, 3, 4, 17, 5, 6, 8, 0, 9]`。绝大多数值落在 0–9，只有 **17** 突兀。

再看它在程序里的身份：原字节是 `0xD2`，而 `0xD2` **是整条程序里唯一不是合法操作码的字节**
（合法操作码只有 `0xC1`–`0xCB`）。它不是指令，是**立即数**。

> **可迁移的经验**：VM 程序里的立即数，往往是作者故意藏在程序里的常量。
> 你这个 VM 语义逆不出来，不代表那个立即数没有意义。
> 这里 `0xD2 ^ 0xC3 = 0x11 = 17`。

于是手里有了两个候选常量：

- `17 = 0x11` → 一个字节的**加数**
- `3` → 一个 1..7 范围内的**循环移位量**（`ROL`）

## 四、识别同系列指纹：`ROL / ADD / XOR` 轮

这一步是「方向」里最省时间的一步：**先看同系列别的题用什么骨架。**

`f2` 这一组是同一个出题人、同一套生成器产出的，已经解过的几道题的骨架高度一致：

| 题 | 骨架 |
| --- | --- |
| `f2-04` | 33 字节命令做 **6 轮 `rol` + `add` + `xor`**（表在 `0x2321`/`0x2327`/`0x232d`） |
| `f2-06` | 4 轮密钥扩展 → `xor` + S 盒 + **`rotr`** |
| `f2-08` | FNV 派生 4 个 dword → **TEA/XTEA** 分组 |

也就是说：**「移位 + 加法 + 异或 + 一张按 `i` 索引的小表」是这个出题人的口头禅。**
而 `f2-05` 手上正好凑齐了这三样东西：

- 表：`0x401a` 的 4 字节 `8d de b9 0f`，按 `i & 3` 索引（`0xC1` 指令就是 `key[idx & 3]`）
- 加数：`0x11`（来自立即数）
- 移位：`3`（来自解码列表）

**为什么这个方向值得优先试**：它不是「再猜一种密码算法」，而是「在这套二进制里
已经出现的三种运算」——你不用引入任何外部原语。

## 五、可复现的搜索：不猜算法，直接枚举这一族

有了「三种运算 + 一张表」的骨架，剩下的就交给机器。**不要去猜组合，把它参数化。**

参数空间（互斥且有限）：

| 维度 | 取值 | 规模 |
| --- | --- | --- |
| 表 | `t0`(4B) / `t1`(12B) / `bytecode`(10B) / `VM_KEY07`(8B) / `bytecode^0xC3` | 5 |
| 加数 `A` | `0x00`–`0xFF` | 256 |
| 移位 `R` | `1`–`7` | 7 |
| 三种运算的顺序 | `ARX` 的 6 种排列 | 6 |

合计 **53 760** 个候选，秒级跑完。

```python
import itertools
d = open('validator', 'rb').read()
blob = d[0x3020:0x303f]           # 31 字节密文
t0   = d[0x301a:0x301e]           # 8d de b9 0f
bc   = d[0x3010:0x301a]           # 10 字节程序
t1   = d[0x3040:0x304c]           # c3 c2 c1 ... = 0xC3^i
acc  = b'VM_KEY07'

def ror(b, r):
    r &= 7
    return ((b >> r) | (b << (8 - r))) & 0xff if r else b

TABLES = {'t0': t0, 't1': t1, 'bc': bc, 'acc': acc,
          'bcc3': bytes(x ^ 0xC3 for x in bc)}

hits = []
for tname, T in TABLES.items():
    for A in range(256):
        for R in range(1, 8):
            for order in itertools.permutations('ARX'):   # A=add, R=rol, X=xor
                out = []
                for i in range(31):
                    x = blob[i]
                    for op in reversed(order):            # 逆运算：反序、每步求逆
                        if   op == 'A': x = (x - A) & 0xff
                        elif op == 'R': x = ror(x, R)
                        else:           x ^= T[i % len(T)]
                    out.append(x)
                pt = bytes(out)
                if pt[:5] == b'FLAG{' and pt.endswith(b'}') \
                   and all(32 <= c < 127 for c in pt):
                    hits.append((tname, A, R, ''.join(order), pt))

for h in hits:
    print(h)
```

输出**唯一一条**：

```text
t0  0x11  3  ARX  b'FLAG{by73c0d3_vm_r3v3rs3d_0x5A}'
```

即：

```text
blob[i] = ROL(flag[i] + 0x11, 3) ^ t0[i & 3]
```

### 为什么这个过滤器是可靠的

三个约束叠加，判别力非常强：

| 过滤器 | 剩余候选 |
| --- | --- |
| 解密结果 31 字节全可打印 | 43 |
| 再加「以 `}` 结尾」 | 2 |
| 再加「以 `FLAG{` 开头」 | **1** |

31 字节 = 5 + 25 + 1 的长度自洽，加上同系列 flag 都是 `FLAG{小写 leet 短语}`，
这两个先验一起用，把 5 万个候选压到 1 个。

> **注意**：这里能这么干脆地枚举，是因为**参数是从二进制里读出来的**。
> 如果只是「随便找几种常见密码」，参数空间会膨胀到不可枚举——那才是真正的无底洞。
> 所以第四步（认骨架）不是可选项，它是把搜索从「无限」压到「5 万」的原因。

## 六、为什么几条「直觉方向」会全部失效（负面清单）

这一节是我希望你能提前看到的——以下方向我都试过，且**注定失败**，原因值得记住。

### 6.1 「凑一个周期密钥做 XOR」——数学上被排除

最容易上手的思路是：`flag[i] = blob[i] ^ k[i % p]`，然后由 `FLAG{` 推出前几个密钥字节。

对纯异或（以及加减）流密码可以严格证明：**只要周期 `p < 31` 就无解**。
理由是 `pt[i] ^ pt[j] = blob[i] ^ blob[j] ^ k[i] ^ k[j]`，
当 `i ≡ j (mod p)` 时后两项抵消。取 `i=0, j=4`：`F ^ {` = `0x3d`，
而 `blob[0] ^ blob[4] = 0x37 ^ 0xe9 = 0xde`，差一个固定量，怎么调 `k` 都消不掉。
我当时把 `p = 1..30` × `{xor, add, sub}` 全部求交集，结果 **UNSAT**。

**但这个证明有个前提：运算是「逐字节线性」的。**
本题是 `ROL(x + A, 3) ^ k`——`ROL` 把低 3 位搬到高位，**整体不是字节间的异或仿射变换**，
`pt[i] ^ pt[j]` 不再等于 `blob[i] ^ blob[j] ^ 常数`。所以上面那个「已排除」的结论
**完全不适用**。我第一轮就是被自己的证明确实说服了，直接跳过了正确答案所在的族。

> **教训**：写死结论时一定要写清前提。`§6.1` 只排除「纯 xor/add/sub 的周期密钥」。

### 6.2 把那张 4 字节表当密钥流

`8d de b9 0f` 长得就像密钥，于是很容易掉进「`blob ^ key[i&3]`，再套各种派生」的坑。
实测 31 字节里只有 14 个可打印，开头是 `ba ea 92 c2`，不是 `FLAG`。

**它确实是密钥，但不是「直接异或」的密钥**——它是 `ROL(...) ^ table[i&3]` 里的那一段。
同样一张表，做异或的尾巴和做整个密钥流，效果完全不同。

### 6.3 把字节码当密钥流来源反复扫

我扫过 `bytecode`、`bytecode` 反序、`bytecode ^ 0xC3` 做「密钥流」的几十种组合，
全部落空。原因是**读法错了**：它不是用来当 keystream 的，它是**参数表**。

> **教训**：一段「看起来像数据」的字节，至少有三种身份——
> 密钥流 / 密钥 / 参数（移位量、加数、轮数、表下标）。
> 三种都试过才算排除，别只试第一种就说「这不是密钥」。

### 6.4 优先怀疑「题目坏了」

VM 打印 31 个点、`0xC0` 是空操作、二进制里没有解密路径——这些加在一起非常像「部署坏了」。
我当时甚至写下了「这道题不可解」的结论。

真相是：**出题人把 VM 写坏了，但算法和参数都还在数据区里。**
`0xC0` 越界不是 bug 的证据，而是**提示**——它告诉你「运算那条指令你在这里看不到，
那就去别处找它的参数」。

## 七、验证

不要只靠「看起来像 flag」就提交。三个独立校验：

**1. 正向重加密逐字节一致**

```python
def rol(b, r):
    r &= 7
    return ((b << r) | (b >> (8 - r))) & 0xff if r else b

flag = bytes((ror(blob[i] ^ t0[i & 3], 3) - 0x11) & 0xff for i in range(31))
assert flag == b'FLAG{by73c0d3_vm_r3v3rs3d_0x5A}'
assert bytes(rol((flag[i] + 0x11) & 0xff, 3) ^ t0[i & 3] for i in range(31)) == blob
```

**2. 结构自洽**：31 字节 = `FLAG{` + 25 + `}`，全可打印。

**3. 语义自洽**：明文读作 `bytecode vm reversed 0x5A`，
而 `0x5A` 正是 `main` 里访问码校验用的异或常量（`VM_KEY07` 的每字节 `^0x5A`）。
出题人把线索点在了 flag 里。

## 八、flag 位置与访问码

- **访问码**：`VM_KEY07`。`0x111d` 把 `0x6d6a031f1105170c` 放栈上，逐字节 `^0x5A`，
  再和 `argv[1]` 比 8 字节，并要求 `strlen == 8`。
- **flag**：虚址 `0x4020` 的 31 字节密文 `37 34 2b cd e9 45 ed 4d af 7d b3 a4 af 5d 85 fc
  0e c2 9b 33 af c2 9d 2d 26 5d b3 43 bf 4c cd`，按
  `flag[i] = ROR(blob[i] ^ t0[i & 3], 3) - 0x11` 还原。
  程序运行时不会打印它（VM 是死代码）。

## 九、把方向压缩成一张检查表

下次拿到「自研 VM / 执行引擎 + 一段密文」的题，按这个顺序走：

1. **先看导入表**：有没有 `open`/`read`？
   没有 → flag 一定是从密文算出来的，别去找服务器文件。
2. **先证伪 VM，再理解 VM**：
   打印参数是不是硬编码？load 结果有没有活到被使用？
   补丁成「打印累加器」跑一次，看输出是什么——一次实验胜过半小时静态推理。
3. **分派索引算一遍**：程序里每条 opcode 的 `index` 是否落在表内？
   越界的那一条，往往就是「作者删掉/写坏的那一步」，而它的**操作数是参数**。
4. **找编码常量**：数据区里有没有「依次递增再异或同一常量」的表？
   有 → 这个常量就是解码字节码的钥匙，去解字节码。
5. **解出来的小整数当参数读，不当密钥流读**：
   1..7 的像移位量，0x10..0xFF 的像加数，重复的像轮数。
6. **借同系列骨架**：同一出题人的其他题用什么？（本题 = `ROL + ADD + XOR` + 按 `i&3` 索引的表）
7. **参数化枚举 + 强过滤器**：
   表 × 加数 × 移位 × 运算顺序，通常 10⁴–10⁶ 量级；
   过滤器用「长度自洽 + 全可打印 + `FLAG{...}`」。
8. **正向验证**：解出来的明文必须能**逐字节重新加密回原密文**。
