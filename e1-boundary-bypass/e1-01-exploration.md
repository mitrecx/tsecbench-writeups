# e1-01 · 探索记录

对应题解：[`e1-01.md`](./e1-01.md)

## 目标与起点

题目要求穿过边界防护，拿到只有管理员能看到的 flag。打开入口就是一张登录表，脚注写明 ModSecurity。没有其他路径，先看登录请求被拦在哪一层。

## 第一阶段：区分「规则拦截」和「口令错误」

用同一口令 `x` 换用户名。判据只有三个：HTTP 403 且正文是 nginx Forbidden，说明请求没到 PHP；HTTP 200 且页面写 `Invalid username or password`，说明到了后端但认证失败；HTTP 302 到 `dashboard.php`，说明会话已经是管理员。

`admin` / `x` 是第二种。`admin' or '1'='1` 是第一种。所以后端很可能把用户名拼进 SQL，但布尔注入的写法在边界上就被丢掉了。

## 走不通 / 走过的弯路（留档）

| 方向 | 结果 | 判据 |
| --- | --- | --- |
| `admin` / `admin` | 认证失败 | 200，页面原文是 Invalid username or password |
| `admin' or '1'='1` | 被边界拦截 | 403，正文是 nginx Forbidden，没有 PHP 会话页 |
| `admin' OR 1=1-- -` | 被边界拦截 | 同样 403 |
| `admin'--` | 被边界拦截 | 403。它没有变成「口令错误」，所以不是 SQL 语法失败 |
| `admin'#` | 认证失败 | 200。`#` 没有截断后面的口令比较 |
| `admin'-- -` | 进入仪表盘 | 302 `dashboard.php`，页面上出现 flag |
| `admin'/**/-- -` | 进入仪表盘 | 同样 302。块注释也能把比较切掉 |

## 这次真正的收获

这台 ModSecurity 认 `or` 和贴在末尾的 `--`，不认「注释符后面还有一个 token」的写法。后端是 MySQL 风格的注释，`--` 后面必须有空白，所以 `admin'-- -` 同时是合法 SQL 和规则缺口。flag 不在登录响应里，在随后的仪表盘页面里。
